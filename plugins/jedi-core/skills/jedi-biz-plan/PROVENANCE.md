## 조용히 틀렸던 것

에러 없이 통과하는데 결과가 틀린 유형이다. 게이트를 만들 근거가 된 것들이다.

**표지 날짜 치환이 한 번도 성공한 적이 없는데 로그는 계속 「바뀌었다」로 찍혔다.** `print`가 성공 여부와 무관한 자리에 있었다. 원인은 run이 `'2'` / `'026. '` / `'0'` / `'.'` 넷으로 쪼개져 `'0.'`을 찾는 조건이 애초에 맞지 않은 것이었다.
→ 검증 5단계의 「읽어서 확인」이 여기서 나왔다.

**`cell.text`가 중첩 표를 제외한다.** 문항 글자수가 811자로 나왔으나 실제는 1,265자였다. 「각 문항 1,000자 이상」 게이트가 **미달로 오판**하고 있었다.
→ 검증 1의 「중첩 표 포함」이 여기서 나왔다.

**중첩 표의 `tblHeader`가 조용히 무시된다.** python-docx로 `trPr`에 `append`하면 스키마 자식 순서(cantSplit → trHeight → tblHeader)를 어겨 로그는 「적용됨」인데 렌더링에는 없다.

**문체 재작성이 볼드를 통째로 지운다.** v17에서 51문단의 볼드가 0이 됐다.
→ 검증 4가 여기서 나왔다.

**표지 빈칸이 두 건 연속 공란으로 나갔다.** 멘토기관·닉네임 자리다.
→ 검증 6이 여기서 나왔다.

**회의록에 「본문 12pt」로 적힌 것이 양식 원문에서는 15pt였다.** V20 작업 초반에 회의록
숫자를 그대로 따라갈 뻔했고, 양식을 다시 열어 보고서야 갈렸다. 폰트가 3pt 다르면 페이지
수가 통째로 달라진다.
→ 0단계의 「판정 근거는 언제나 양식 원문」과 1단계 소스 우선순위표가 여기서 나왔다.

## 캡처·도식 실측

- 캡처 원본 42px(device_scale 3, 14px 폰트)이 문서에서 6pt로 보이려면 이미지 폭 ≤ 2,975px. 좌우 2단으로 합치면 폭이 두 배가 되어 **2.8pt로 판독 불가**가 됐다(실제 사고)
- 도식을 임의 좌표계(0~100)로 그리면 박스 높이 대비 폰트가 넘쳐 **글자가 박스를 뚫는다**(실제 사고). 인치 좌표계로 고정하면 fontsize가 문서에서 보이는 pt와 같아진다
- 한 줄에 태그·숫자·설명을 몰아넣었다가 글자가 겹쳤다. 코드는 정상 종료했다 — **눈으로 봐야 보인다**

## 줄갭 사내 정본과의 관계

이 스킬은 `tier: shared`라 다른 회사에도 배포된다. 따라서 **본체와 references는 어떤 회사의 노션에도 의존하지 않는다.** 회사마다 다른 값은 frontmatter `preset_slots`로만 들어온다.

줄갭 사내에는 같은 주제의 살아있는 정본이 별도로 있고, 사례·이력이 계속 쌓인다.

- 🧠 지원사업 합격용 사업계획서 최종 가이드라인 (완성판) — `2ddefa2f2c3b80d4a78ff8250c874bf9`
- 🔧 실무 함정 — 문체 수치·도식·이미지·분량 (실측 누적) — `3baefa2f2c3b810d8809cc4ea2b1e050`

**층이 다르다.** 노션은 줄갭의 축적(사례·건별 이력)이고, 이 스킬은 배포되는 규격 스냅샷이다. 정본이 두 벌이 된 것이 아니다.

⚠️ 위 링크는 **줄갭 워크스페이스 구성원만 열 수 있다.** 다른 회사에서 이 스킬을 쓸 때는 무시하면 되고, 스킬 동작은 링크 없이 완결된다.

⚠️ 노션 쪽에 실측이 추가되면 이 스킬에도 반영해야 한다. **자동으로 따라오지 않는다.**

## 검증 안 된 것 (약속하지 않는다)

- **`scripts/` 없이 만든 이유** — 양식이 기관마다 달라 범용 스크립트가 성립하지 않는다. 문항 개수·표 구조·파일 형식이 전부 다르므로 절차와 검증 항목만 고정하고 구현은 건별로 한다
- **hwp 직접 편집** — 이 스킬은 규격만 다룬다. 파일 조작 처방은 한글 양식 채우기 스킬 쪽에 있다
- **docx 외 형식의 페이지 실측** — Word COM 기준으로만 확인했다. LibreOffice·한글 경로는 미검증
- **표본이 3건이다** — 세 문서(선정본 2 + 자체 1)에서 나온 규격이다. 기관 성격이 크게 다른 공모(R&D·해외진출 등)에서는 어긋날 수 있다
