# 사업계획서

> 🔓 **이 문서는 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하거나
> "그만하고 그냥 해줘"라고 하면 그 순간 이 절차는 무효다.

지원사업(예비창업패키지·초기창업패키지·지자체 공모 등) 제출용 사업계획서를 쓴다.
**양식의 빈칸을 채우는 일이 아니라 문항마다 몇 백 자짜리 글을 쓰는 일**이다.

## 왜 있나

한 건을 쓰는 데 문서 버전이 20~40개까지 늘어난다. 그러는 동안 얻은 것 — 문체를 어떻게
재야 하는지, 페이지가 왜 안 줄어드는지, 표지 빈칸을 왜 매번 빠뜨리는지 — 가 **그 건이
끝나면 사라졌다.** 다음 사람이 같은 자리에서 같은 시간을 쓴다.

이 스킬은 그 규격을 문서 두 벌로 고정하고, 검증을 도구로 옮긴 것이다.

## 경계 — 무엇이 이 스킬의 일이 아닌가

| 하는 일 | 안 하는 일 | 어디로 |
|---|---|---|
| 문항에 들어갈 **글**을 쓴다 | 신청서·동의서의 **칸**을 채운다 | 한글 양식 채우기 스킬 (`jedi-hwp-form`) |
| 문체를 **판정 기준**에 맞춘다 | 문체 점수 계산 자체 | 백엔드 도구 `validate_ai_voice` |
| 제출본 파일을 만든다 | **제출(메일 발송)** | 🔴 사람이 한다 |

🔴 **제출은 이 스킬이 하지 않는다.** 보낸 메일은 되돌릴 수 없고, 마감 시각과 수신처 판단은
사람 몫이다. 파일이 완성되면 경로를 알리고 멈춘다.

## 준비물

| 무엇 | 언제 | 없으면 |
|---|---|---|
| **양식 원문** (`.hwp`/`.hwpx`/`.docx`) | 항상 | 🔴 시작하지 않는다 (§0) |
| 공고문 또는 작성요령 | 항상 | 양식 안의 안내문으로 대체 |
| `python-docx` · `pymupdf` | docx 작업·검증 | `pip install python-docx pymupdf` |
| `pywin32` (Windows) | 페이지 실측·hwp 변환 | 페이지 수를 추정으로 답하지 말고 **미실측이라고 밝힌다** |

# 실행 순서

## 0. 양식 원문을 연다

🔴 **추측으로 시작하지 않는다.** 폰트·글자수·페이지 상한·파일명 규정은 전부 원문에 있다.

- `.hwp` → 한컴 COM으로 `.hwpx` 변환 후 `Contents/section0.xml` 파싱 (일반 hwp 파서는 표 셀을 잃는다)
- `.docx` → `python-docx`. 🔴 **표 셀을 빼지 말 것** — 정부 양식은 본문이 전부 표 안에 있다
- 안내문·주석·회색 예시글까지 읽는다. 「항목 및 서식 임의 수정 불가」가 있으면 서식 레버가 봉인된다

읽은 것을 표로 정리해 사용자에게 보여주고 시작한다.

| 확인할 것 | 예 |
|---|---|
| 본문 폰트·크기 | 맑은고딕 15pt |
| 페이지 상한 | 15p 이내 |
| 문항별 글자수 하한 | 각 1,000자 이상 |
| 서식 수정 허용 범위 | 줄간격만 조정 가능 |
| 제출 파일명 규정 | `[사업명]_[신청자명].hwp` |

⚠️ **회의록·안내 메일의 숫자를 믿지 않는다.** 회의록에 「12pt」로 적힌 것이 원문에서는
15pt였던 사례가 있다. **판정 근거는 언제나 양식 원문이다.**

## 1. 규격을 읽는다

- `references/writing-rules.md` — 무엇을 쓸까 (PSST·톤·표·이미지·문체 수치·금지어)
- `references/layout-traps.md` — 어떻게 만들까 (분량·이미지 삽입·도식·docx 함정)
- `preset_slots.회사정본링크`가 채워져 있으면 그것도 함께 읽는다

### 소스가 서로 다른 말을 할 때

세 곳이 같은 항목에 다른 값을 말하는 일이 잦다. **위가 이긴다.**

| 순위 | 소스 | 예 |
|---|---|---|
| 1 | **양식 원문·공고문** | 폰트 15pt, 15p 이내, 파일명 규정 |
| 2 | `회사정본링크` (사내 가이드) | 그 회사가 쌓아 온 관행 |
| 3 | `references/` (이 스킬의 규격) | 22~30p 권장, 표 6종 |
| 4 | 회의록·안내 메일·기억 | 🔴 **단독 근거로 쓰지 않는다** |

어긋난 것을 발견하면 **조용히 한쪽을 택하지 말고 사용자에게 알린다.** 규격 문서가 상한
22~30p를 권해도 양식이 15p면 15p가 답이고, 그때는 문항별 글자수 하한을 먼저 맞춘다.

## 2. 기존 자산을 찾는다

`preset_slots.지원사업_보관폴더`에서 **같은 팀이 낸 다른 사업계획서**를 찾는다.

여기서 나오는 것들이다.

- 표지 빈칸의 답 (멘토기관명·팀 닉네임·법인 정보)
- 이미 쓴 팀 역량표·협력사 목록 — 다시 만들 필요가 없다
- 그 기관이 좋아하는 표 구성

⚠️ **선정된 문서가 있으면 그것을 먼저 본다.** 규격 문서보다 실물이 정확한 지점이
있다(목업 경계가 그랬다 — `writing-rules.md` §6).

🔴 **보관폴더 값이 비어 있으면 그 사실을 알리고 경로를 묻는다.** 조용히 건너뛰고 3단계로
넘어가지 않는다 — 표지 빈칸의 답이 여기에만 있어서, 못 찾은 채 진행하면 **검증 6에서
공란으로 걸리거나 그대로 제출된다**(두 건 연속 공란으로 나간 전례가 있다).
사용자가 "없다"고 답하면 그때는 표지 빈칸을 **질문 목록으로 만들어** 3단계와 함께 채운다.

## 3. 쓴다

문항마다 PSST로 구조를 잡고 초안을 만든다. 지시문은 `writing-rules.md` §13을 그대로 쓴다.

- 그림 자리는 **마커만** 둔다 (`[이미지 1: 관리자 화면 — 증명 대상: 실제 운영 중]`)
- 표를 넣으면 **같은 내용의 문장을 지운다** — 추가가 아니라 치환이다
- 소제목 형식을 문항 단위로 통일한다

## 4. 검증한다

🔴 **여기가 이 스킬의 값이다.** 눈으로 읽어서는 일곱 가지 중 다섯 가지가 안 보인다.

| # | 무엇 | 어떻게 | 왜 |
|---|---|---|---|
| 1 | 문항별 글자수 | 🔴 **중첩 표 포함**으로 센다 | `cell.text`는 중첩 표를 빼서 절반도 안 잡힌다 (811 vs 실제 1,265) |
| 2 | 페이지 수 | Word COM `Repaginate()` + `ComputeStatistics(2)` | 글자수 추정은 크게 빗나간다 (추정 8p ↔ 실제 14p) |
| 3 | 문체 | `validate_ai_voice` · `profile: business_plan` | 기호·종결률이 판별축이다 |
| 4 | 볼드 개수 | 재작성 전후로 센다 | 문체를 고치면 `**마크업**`이 통째로 사라진다 (51문단 중 0) |
| 5 | 레이아웃 | 전 페이지 PNG → 컨택트 시트 | 빈 페이지·잘린 표·글자 넘김은 **눈으로만 보인다** |
| 6 | 표지 빈칸 | 멘토기관·닉네임·날짜 | **두 건 연속 공란으로 나갔다** |
| 7 | 제출본 파일명 | 규정 그대로 | `_v20`·`_최종` 접미사 금지 |

`validate_ai_voice` 호출 시 🔴 **`tenant_id`를 직접 넣지 않는다** — 자동 주입된다. 자칭
`tenant_id`가 내 토큰의 회사와 다르면 그 자리에서 끊긴다.

### 1번·4번은 세는 방법이 정해져 있다

「센다」로만 두면 다음 사람이 다른 방식으로 세고 다른 답을 얻는다. 둘 다 **run 단위 재귀 순회**다.

```python
def cell_text(cell):
    """중첩 표를 포함해 셀의 모든 글자를 모은다 — cell.text는 중첩분을 뺀다."""
    parts = [p.text for p in cell.paragraphs]
    for t in cell.tables:                      # 🔴 이 줄이 빠지면 절반만 세진다
        for row in t.rows:
            for c in row.cells:
                parts.append(cell_text(c))
    return '\n'.join(parts)

def bold_runs(cell):
    """볼드는 문단이 아니라 run 기준으로 센다 — 한 문단에 여러 개일 수 있다."""
    n = sum(1 for p in cell.paragraphs for r in p.runs if r.bold)
    for t in cell.tables:
        for row in t.rows:
            for c in row.cells:
                n += bold_runs(c)
    return n
```

- **글자수**는 공백을 포함해 센다. 양식이 「공백 제외」를 명시했으면 그 기준을 따른다
- **볼드**는 문서 전체 합계를 재작성 **전후로** 비교한다. 절대값이 아니라 **감소 여부**가 신호다
- 문항 경계는 양식의 셀 구조를 따른다. 문항이 몇 번째 셀인지 0단계에서 확인해 둔다

### 검증이 끝나는 조건

- 문항별 글자수가 전부 하한 이상
- 페이지 수가 상한 이하 (**실측값**. 미실측이면 "확인 못 했다"고 밝힌다)
- `validate_ai_voice` 위반 0 또는 사용자가 남기기로 판단한 것만 잔존
- 컨택트 시트에서 빈 페이지·잘린 표 0

## 5. 제출본을 만든다

1. 규정 파일명으로 저장한다
2. 표지 빈칸 세 곳을 채운다
3. 🔴 **값을 넣은 뒤 다시 읽어서 확인한다**

```python
# 나쁨 — 성공 여부와 무관한 자리에서 보고한다
replace(para, old, new); print('교체 완료')

# 좋음 — 바꾼 뒤 읽어서 값으로 판정한다
replace_all_runs(para, old, new)
after = ''.join(r.text for r in para.runs)
assert new in after, f'치환 실패: {after!r}'
print(f'표지 날짜 = {after}')
```

표지 날짜 치환이 **한 번도 성공한 적이 없는데 로그에는 계속 「바뀌었다」로 찍힌** 일이
있었다. 한글·docx의 텍스트는 한 문장이 여러 run으로 쪼개져 있어 문자열 매칭이 자주 빗나간다.

4. 완성 파일 경로를 사용자에게 알리고 **멈춘다.** 메일은 사람이 보낸다.

## 자주 걸리는 것

| 증상 | 실제 원인 |
|---|---|
| 페이지가 안 줄어든다 | 그림·간격을 만지고 있다. **문장을 덜어내야 준다** (`layout-traps.md` §1) |
| 그림과 캡션이 페이지 경계에서 갈라진다 | 1×1 표로 감싸고 `cantSplit`을 건다 (§2) |
| 캡처 글자가 안 읽힌다 | 도식부터 줄이고 캡처는 마지막에. 판독 불가 캡처는 **빼는 편이 낫다** (§3) |
| 문체 재작성 후 문서가 밋밋하다 | 볼드가 전멸했다. 개수를 센다 (검증 4) |
| 「1,000자 이상」인데 미달로 나온다 | 중첩 표를 빼고 셌다 (검증 1) |

## 안 하는 것

- **제출(메일 발송)** — 되돌릴 수 없다. 파일까지 만들고 멈춘다
- **양식 서식 임의 변경** — 「수정 불가」가 명시된 양식에서 `trHeight` 제거·폰트 변경은 규정 위반 소지가 있다
- **페이지 수 추정 답변** — 실측 못 했으면 "확인 못 했다"고 밝힌다. 추정은 크게 빗나간다
- **검사 스크립트 새로 만들기** — 문체 판정은 `validate_ai_voice` 하나로 모았다
