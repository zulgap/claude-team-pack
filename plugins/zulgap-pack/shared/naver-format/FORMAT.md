# 네이버 블로그 포맷 — 정본

> 이 파일이 **규칙의 유일한 집**이다. 카드를 «만드는» 스킬과 «올리는» 스킬이 같은 것을 본다.
> 실측: 2026-08-16 · 대상 블로그 발행글 4편 전수 + 네이버 에디터 붙여넣기 실험
> 코드: 같은 폴더 `naver-format.js` — 값이 어긋나면 `_test-naver-format.js` 가 깨진다

## 왜 포맷이 문제인가

네이버 글은 **여백과 인용구로 숨을 쉰다.** 홈페이지용 마크다운을 그대로 옮기면 문단이 빽빽하게 붙고
소제목이 그냥 굵은 글씨라, 같은 블로그의 다른 글과 **확연히 달라 보인다.**

등록 버튼은 사람이 누른다(네이버가 발행 API를 닫았다). 그러니 **누르기 직전 상태가 완성이어야** 자동화에 값이 있다.
고칠 게 남아 있으면 절감이 0으로 수렴한다.

## 규칙

| 무엇 | 이렇게 | 쓰면 안 되는 것 |
|---|---|---|
| **소제목** | `<blockquote>` → 네이버 **인용구**(`se-quotation`)<br>원고에서는 `## 소제목` **또는** `**줄 전체 볼드**` 둘 다 인식한다 | 🔴 **`<h2>`** — 별도 컴포넌트가 안 되고 앞 문단에 **텍스트로 흡수**된다 |
| **인용구 안** | **굵게** (`<blockquote><b>…</b></blockquote>`) | 그냥 두기 — 소제목이 본문과 같은 굵기라 눈에 안 띈다 |
| **문단 여백** | 문단↔문단 **3칸** · 문단↔이미지 **2칸** (`<p><br></p>` 개수) | 어디든 한 칸 — 손으로 친 글보다 빽빽해진다 |
| **이미지 폭** | **옆트임** (`se-object-arrangement-extend`) | 🔴 올린 직후 기본값 **문서 너비** 그대로 두기 — 그림이 좁게 나간다 |
| **구분선** | `<hr>` → `horizontalLine` 컴포넌트 | `---` 를 버리기 |
| **표 머리 행** | `<td style="border:1px solid #d5d5d5;background-color:rgb(0,78,130)"><span style="color:#ffffff;">…</span></td>` | 🔴 `header-row="true"` 속성 — **네이버가 무시한다**<br>🔴 `td` 에 `color` — **안 먹는다**(검은 글씨로 나온다) |
| **표 셀 선** | 모든 셀에 `border:1px solid #d5d5d5` | 선을 빼기 — 사장님이 넣기로 하셨다(아래 «달라진 것») |
| **표 셀 안** | 마크다운을 풀어서 넣는다 (`**THC**` → `<b>THC</b>`) | 별표를 그대로 두기 — **글자로 발행된다** |
| **큰 강조** | `<span style="font-size:19px">` | |
| **밑줄** | **쓰지 않는다** | `<u>` — 기존 글 4편 모두 0개 |

## 여백 — 몇 칸인가 (2026-08-20 개정)

담당자가 손으로 칠 때 **엔터를 몇 번 누르는지**가 규칙이다.

| 사이 | 칸 수 | 코드 |
|---|---:|---|
| 문단 ↔ 문단 (소제목·표·구분선 포함) | **3칸** | `GAP_PARAGRAPH` |
| 문단 ↔ 이미지 | **2칸** | `GAP_IMAGE` |

🔴 **이미지 옆이 «더 좁다».** 이미지는 그 자체로 쉼이라, 위아래까지 벌리면 글이 토막나 보인다.

⚠️ **위 「빈 문단 비율 56~61%」 실측치는 이 규칙과 맞지 않는다.** 한 칸이면 약 50%, 세 칸이면 약 75%다.
2026-08-20 담당자 확인으로 **3칸/2칸이 실무 규칙**임을 정본으로 삼았고, 옛 비율은 세는 방식이
달랐던 것으로 본다(그때 원본을 다시 세지 않았다). **비율이 아니라 칸 수가 판정축이다.**

🔑 칸 수를 «쌓기»로 만들지 말 것 — 문단 뒤 1칸 + 원고 빈 줄 1칸 = 2칸이 되어 원고마다 들쭉날쭉해진다.
`normalizeGaps()` 가 조각을 다 만든 뒤 **한 번에 다시 센다.**

## 글꼴 — 마루부리 (2026-08-20 신설)

에디터 기본값은 **나눔고딕**이라, 그냥 두면 손으로 친 글과 서체가 갈린다.
코드는 `nanummaruburi` — 글꼴 버튼의 `data-value` 이자 본문에 박히는 `se-ff-<코드>` 클래스다.

**어디에 거는가** (2026-08-20 실측)

| 자리 | 어떻게 |
|---|---|
| 본문 문단 | 붙여넣기 «전»에 골라 두면 그대로 들어간다 |
| **표 셀** | 미리 고른 것이 안 닿는다 — 채운 뒤 **전체 선택**으로 한 번 더 건다 |
| **제목칸** | 본문과 **다른 편집 영역**이라 전체 선택이 안 닿는다 — 따로 눌러 따로 건다 |
| **인용구** | 🔴 **바꿀 수 없다** — 아래 참조 |

🔴 **인용구 안에서는 네이버가 글꼴 버튼을 «감춘다».** 커서를 인용구에 두면 버튼이 화면에서
사라져 **클릭조차 못 한다**(실측: 20개 전부 실패). 인용구는 제 서체(**나눔명조**)가 고정이다.
바꿀 방법이 없으므로 **검사에서도 뺀다** — 세면 「고칠 수 없는 문제」가 매번 뜬다.

⚠️ 「골랐다」와 「들어갔다」는 다르다. 글꼴 버튼의 `aria-current` 는 *다음에 칠 글자*의 상태라
**선택한 글자에 입히려면 이미 그 글꼴로 보여도 실제로 눌러야 한다.** 판정은 화면 클래스로 한다.

## 인용구 안은 굵게 (2026-08-20 신설)

담당자가 손으로 칠 때 인용구 문장을 **굵게** 친다. 인용구는 이 블로그에서 «소제목 자리»라,
굵기가 없으면 본문과 구별이 안 된다.

🔴 **`subheading()` 과 `quote()` 둘 다**에 건다 — 네이버에서 두 함수가 **같은 컴포넌트**
(`se-quotation`)로 나가므로, 한쪽만 굵게 하면 화면에서 같아 보이는 인용구끼리 굵기가 갈린다.
본문 인용(의료 안내·기관 인용)만 빼고 싶어지면 `bold()` 한 자리를 나누면 된다.

⚠️ **이미 굵게인 문장에 겹쳐 걸지 않는다** — `**A**` 를 `<b><b>A</b></b>` 로 만들면
네이버가 별표째 남기거나 태그를 뭉갠다. 줄 전체가 이미 `<b>` 면 그대로 둔다.

## 이미지 폭 — 옆트임 (2026-08-20 신설)

본문 그림은 전부 **옆트임**으로 넣는다. 올린 직후 기본값은 「문서 너비」라 그냥 두면 좁게 나간다.

**실측** (2026-08-20 · 1080px 원본 7장 · 네이버 에디터 화면 폭)

| 설정 | 화면 폭 | 선택된 토글 |
|---|---:|---|
| 작게 | 375px | `se-object-arrangement-normal-toolbar-button` |
| 문서 너비 *(올린 직후 기본값)* | 500px | `se-object-arrangement-fit-toolbar-button` |
| **옆트임** | **700px** | `se-object-arrangement-extend-toolbar-button` |

🔴 **컴포넌트 클래스로 판정하지 말 것** — 세 설정 모두 `se-l-default` 로 **똑같다.**
바뀌지 않는 것을 보고 「안 먹었다」고 오판하기 딱 좋다(2026-08-20에 그렇게 헤맸다).
판정축은 ① 그 이미지를 **선택한 상태**에서 읽는 토글, ② 화면에서 잰 **폭** 둘이다.

🔴 **토글은 이미지를 «선택하지 않았을 때»도 값이 보인다** — 그건 *다음에 넣을 그림*의 기본값이지
이 그림의 상태가 아니다. 선택한 뒤에 읽지 않으면 **조용한 오답**이 된다.

## 강조 — 굵게는 쓰고 형광펜은 안 쓴다

**실측** (2026-08-16 · 발행글 「원산지증명서」 편 2,698자)

| | 기존 발행글 | 뜻 |
|---|---:|---|
| 볼드 `<b>` | **37개** (약 **73자당 1개**) | 문장 안에서 자주 굵게 한다 |
| 형광펜(배경색) | **0개** | 이 블로그는 안 쓴다 |
| 큰 글씨 19px | 9개 | 소제목 자리에 쓰인다 |
| 밑줄 | 0개 | 안 쓴다 |

**어디를 굵게 하나** — 실측 글에서 굵게 처리된 것들의 성격

| 종류 | 예 |
|---|---|
| 핵심 판단 | **직접 유입이 크다고 브랜드가 알려진 게 아닙니다** |
| 숫자·판정 | 머문 시간이 **106초**로 검색(**67초**)보다 |
| 경고 | **직접 유입을 줄이려다 오히려 늘리는 자리**입니다 |
| 나열의 항목 이름 | **리다이렉트** / **단축 주소** |
| 답의 결론 | **안 맞는 게 정상입니다** |
| 용어 | **탐색 보고서** / **서치 콘솔** |

🔴 **줄 전체를 감싸지 말 것** — 소제목(인용구)이 되어 버린다. 문장 «일부»만 감싼다.
⚠️ **형광펜을 넣지 말 것** — 기존 글에 0개다. 넣으면 이 블로그에서 혼자 튄다.

### 기존 글과 «일부러 다르게» 한 것

| 무엇 | 기존 발행글 | 우리 | 왜 |
|---|---|---|---|
| 표 셀 선 | **없음**(`0px`, 색으로만 구분) | `1px solid #d5d5d5` | 2026-08-16 사장님이 실물을 검수하고 «선을 넣자»고 정하셨다 |

되돌리려면 `naver-format.js` 의 `TABLE_BORDER` 하나만 보면 된다.
🔑 **네이버가 이 인라인 `border` 를 받는다는 것은 실측했다**(적용 후 계산값 `0.8px solid rgb(213,213,213)`).
`header-row="true"` 처럼 무시되는 속성이 아니다.

**표** (CIF 편) — 머리 행 셀 배경 `rgb(0, 78, 130)`, 셀 테두리 `0px`(색으로 구분),
글자색은 **`span` 의 `style="color:#ffffff;"`** 로 들어가 있다.

**에디터 실험** — 붙여넣기 HTML 이 무엇으로 변환되는지 직접 확인:

```
<blockquote>  → se-quotation   ✅        <hr>          → horizontalLine ✅
빈 문단        → 유지           ✅        font-size     → 유지           ✅
<u>           → 유지           ✅        <h2>          → ❌ 컴포넌트 안 됨
<table header-row="true">  → 머리 색 ❌ (무시됨)
<td style="background-color:…">  → ✅ 적용
```

## 카드를 «쓰는» 쪽에게

원고를 이 포맷에 맞춰 쓰면 발행이 그대로 옮긴다. 반대로 홈페이지 문법으로 쓰면 발행이 번역해야 하고,
번역 규칙이 늘수록 깨진다.

- 소제목은 `## 소제목` 으로 쓴다 → 발행이 인용구로 바꾼다
  🔑 **`**줄 전체 볼드**` 도 소제목으로 인식**한다 — 기존 카드들이 그렇게 쓰고 있어서 함께 받는다.
  판정축은 **줄 전체**다: `**A**입니다.` 처럼 문장 «일부»면 그냥 굵게로 남는다
- 🔴 **문장 «안»의 핵심 구절을 `**...**` 로 굵게 한다** — 아래 「강조」 절 참조.
  **이건 «작성»의 판단이다.** 발행은 `**` 를 `<b>` 로 바꿀 뿐 «어디를 굵게 할지» 정하지 않는다
  (정하면 원고를 고치는 셈이다). 카드에 강조가 없으면 **발행이 그 사실을 세어 알려 준다** — 막지는 않는다
- 문단은 그냥 줄바꿈으로 나눈다 → 발행이 여백을 넣는다
- 표는 `<table header-row="true">` 그대로 쓴다 → 발행이 머리 색을 입힌다
- 이미지는 **넣을 자리에** `![설명](주소)` 로 둔다 → 발행이 그 순서대로 올린다
  🔑 **어디에 넣을지는 「작성」의 판단이다.** 발행은 순서대로 옮길 뿐 판단하지 않는다
- 밑줄은 쓰지 않는다

## 안 건드릴 것

- 🔴 **`<h2>` 로 소제목을 만들지 말 것** — 네이버에서 사라진다(텍스트로 흡수)
- 🔴 **표 글자색을 `td` 에 주지 말 것** — 검은 글씨로 나온다. `span` 에 준다
- 🔴 **`header-row="true"` 만 믿지 말 것** — 네이버가 무시한다. 인라인 style 이 유일한 길
- 🔴 **여백을 「보기 싫다」고 빼지 말 것** — 기존 글의 절반 이상이 빈 문단이다. 그게 이 블로그의 모양이다
- 🔴 **이미지 폭을 «컴포넌트 클래스»로 판정하지 말 것** — 세 설정이 전부 `se-l-default` 다
- 🔴 **굵게를 「우리가 넣으니 괜찮다」고 두지 말 것** — 조각 경계에서 «에디터가» 씌운다.
  붙이기 직전마다 커서 자리의 굵게를 끄고, 끝나면 굵게 «글자 수»를 세어 번졌는지 본다
  (2026-08-20 실사고: 문단 하나가 굵게로 끝난 뒤 나머지 글 전체가 굵어졌는데 검증은 초록이었다)
- ⚠️ 이 문서의 값을 고치면 `naver-format.js` 도 함께 고친다 — **동기화 테스트가 잡는다**
