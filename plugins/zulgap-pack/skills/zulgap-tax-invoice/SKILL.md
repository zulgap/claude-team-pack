# 줄갭 세금계산서 준비 (경리)

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하면
> **즉시 이 절차를 그만두고 도구를 직접 호출한다.**
> 단, 아래 「발행하지 않는다」만은 예외다 — 그건 지름길이 아니라 **경계**다.

## 🔴 이 스킬은 발행하지 않는다 — 발행 **요청**까지만 한다

준비를 마치고 증빙방에 **확인 카드를 띄우는 것**까지가 이 스킬의 일이다. **국세청에 도달하는 행위(발행·전송·취소·수정발행)는 이 스킬에 경로가 없고, 만들어서도 안 된다.**

이유는 하나다 — **되돌릴 수 없기 때문이다.** 국세청에 전송된 계산서는 팝빌이 아니라 **국세청 제도상** 취소가 없고, 수정세금계산서(마이너스) 상계만 가능하며 거래처에도 그 이력이 보인다. 그래서 마지막 한 걸음은 **사람이 텔레그램에서 버튼을 누르는 것**으로 남겨뒀다.

사람이 서는 자리는 **둘**이다.

| 자리 | 카드 | 누르면 |
|---|---|---|
| ① 발행 전 | `[✅ 발행합니다]` / `[❌ 취소]` | 팝빌에 등록·발행 (아직 국세청 아님) |
| ② 국세청 전송 전 | `[국세청 전송]` → `[네, 전송합니다]` | **되돌릴 수 없음** |

> ⚠️ 사용자가 *"그냥 발행까지 해줘"* 라고 해도 이 경계는 유지한다. 대신 **카드를 띄우고** 버튼만 누르면 된다고 안내한다. 발행 도구(`issue_tax_invoice`)는 이 자리에서 보이지도 않고, 사람이 버튼을 누른 경우가 아니면 서버가 거부한다(`_assertHumanCallback`).

## 개요

- 실행: 신나래 (사장님도 동일)
- 시점: 매월 **5일 발행 권고** → **10일 법정 마감** (전월분 매출 계산서, 영업일 기준)
- 줄갭 사업자: **주식회사 줄갭 / 361-88-02764**

> 🔴 **5일과 10일은 성격이 다르다.** 5일은 "슬슬 끊으시죠"는 권고이고, **10일은 세법상 마감**이라 넘기면 가산세가 붙는다. 알림도 두 번 따로 온다.

### 순서 — 거래처가 먼저다

```
1단계 거래처 확인 ─┬─ 등록돼 있다 ──────────→ 2단계
                   └─ 없다 → 정보 한 번에 요청 → 등록 → 2단계
2단계 발행 내용 확정 (금액·세액·작성일자·품목)
3단계 검수(도구) ─┬─ 통과 → 표로 보여주기 → 4단계
                  └─ 미비 → 빠진 항목만 재요청 → 재검수
4단계 발행 요청 → 증빙방에 확인 카드 → 🔴 여기서 멈춘다
                                        [✅ 발행합니다]는 사람이 누른다
                                                  ↓ 사장님이 누른 뒤
5단계 최종 검증 ─ 상태·금액·품목 대조 → 경로별 다음 안내
```

🔴 **금액부터 묻지 않는다.** 거래처가 없으면 등록이 선행되어야 하는데, 금액을 먼저 받아두면 등록하는 동안 사람이 두 번 일하게 된다.

---

## 1단계 — 거래처 확인 (여기서 시작한다)

먼저 **누구에게 끊는지**만 묻는다. 금액·품목은 아직 묻지 않는다.

> 어느 거래처에 끊을까요? (상호 또는 사업자번호)

받으면 바로 조회한다.

```
mcp__jedi__find_trade_partner({ name: "엔노블" })
mcp__jedi__find_trade_partner({ biz_no: "123-45-67890" })   // 사업자번호를 알면 이쪽이 정확
```

### (가) 등록돼 있으면

돌아온 값에서 **두 가지를 본다.**

| 볼 것 | 뜻 | 조치 |
|---|---|---|
| `ready_to_issue` | 발행 필수 항목이 다 있나 | `false`면 `missing`에 적힌 것을 채운다 |
| `email` | 계산서 받을 주소 | **비어 있으면 아래 ⚠️ 참조** |

> ⚠️ **이메일이 비어도 `ready_to_issue`는 true가 된다.** 시스템은 사업자번호·상호·대표자명 3개만 보기 때문이다. 그런데 **이메일이 없으면 발행은 되지만 거래처가 계산서를 못 받는다.** 비어 있으면 반드시 물어볼 것:
>
> *"계산서 받을 이메일이 등록돼 있지 않습니다. 지금 알려주시면 함께 저장하겠습니다. (없이 진행하면 거래처가 계산서를 못 받습니다)"*

둘 다 괜찮으면 **2단계**로.

### (나) 없으면 — 필요한 것을 한 번에 요청한다

🔴 **찔끔찔끔 묻지 않는다.** 아래 안내문을 **통째로** 준다. 한 항목씩 물으면 사람이 여러 번 왕복한다.

> 처음 거래하는 곳이네요. **사업자등록증 사진 한 장**이면 제가 읽어서 정리하겠습니다.
>
> **꼭 필요한 것** (없으면 발행이 안 됩니다)
> · 사업자등록번호
> · 상호
> · **대표자명**
>
> **같이 주시면 좋은 것**
> · 계산서 받을 이메일 — 없으면 발행돼도 거래처가 못 받습니다
>
> **사업자등록증에 있으면 함께 담습니다**
> · 사업장 주소 · 업태 · 종목
>
> 사진이 어려우시면 위 항목을 텍스트로 주셔도 됩니다.

사진을 받았으면 값을 읽어 **표로 정리해 보여주고 사람이 확인한 뒤** 저장한다(`source: "ocr"`). 텍스트로 받았으면 `source: "manual"`.

```
mcp__jedi__save_trade_partner({
  biz_no: "123-45-67890",
  name: "주식회사 엔노블",
  ceo_name: "홍길동",          // 🔴 없으면 발행이 튕긴다
  email: "...",                // 계산서 수신용
  address: "...",              // 사업자등록증에 있으면
  business_type: "...",        // 업태
  business_item: "...",        // 종목
  source: "ocr"                // manual | ocr | parsed
})
```

### (다) 정보가 부족하면 — 빠진 것만 다시 요청

저장 후 `ready_to_issue`가 여전히 `false`면 `missing`에 적힌 것만 딱 집어 요청한다.

> 사업자등록증에서 **대표자명**을 못 읽었습니다. 대표자명만 알려주시면 등록을 마치겠습니다.

- 🔴 **판정 키는 사업자번호다.** 상호는 바뀌고 동명이인 법인도 있다.
- 같은 사업자번호가 이미 있으면 **덮어쓰지 않고 빈 값만 채운다** — 기존 정보가 날아갈 걱정은 없다.

## 2단계 — 발행 내용 확정

거래처가 확정된 **뒤에** 나머지를 묻는다.

| 항목 | 예 | 없으면 |
|---|---|---|
| 공급가액 | 5,000,000 | 물어본다 |
| 세액 | 500,000 | 보통 공급가액의 10% — **계산해 제시하되 사람이 확정** |
| 작성일자 | 2026-07-31 | 보통 **전월 말일**. 물어본다 |
| 품목 | "마케팅 대행 7월분" | 물어본다 |

🔴 **금액을 추측하지 말 것.** 계약서·견적서가 있으면 그 숫자를 쓰고, 없으면 사람에게 묻는다.

## 3단계 — 검수 → 정리해서 보여주기

### 먼저 검수한다 (표를 보여주기 전에)

🔴 **눈으로 확인하지 말고 도구에 물어본다.** 발행이 쓰는 검증과 **같은 코드**라, 여기서 통과하면 발행에서도 통과한다.

```
mcp__jedi__check_tax_invoice_ready({
  buyer_biz_no: "123-45-67890", buyer_name: "주식회사 엔노블", buyer_ceo: "홍길동",
  issue_date: "2026-07-31", supply_amount: 5000000, tax_amount: 500000,
  items: [{ name: "마케팅 대행 7월분", supply: 5000000, tax: 500000 }]
})
```

| 반환 | 뜻 | 다음 |
|---|---|---|
| `ready: true` | 발행 가능 | `parsed` 값으로 아래 표를 만든다 |
| `ready: false` | 빠진 게 있다 | `missing`에 적힌 **그 항목만** 다시 요청 → 채운 뒤 재검수 |

- `parsed`에는 **시스템이 해석한 값**이 들어 있다(하이픈 뺀 사업자번호·합계·정규화된 날짜). **표에는 이 값을 쓴다** — 내가 계산한 값이 아니라.
- ⚠️ 이 검수는 **입력 항목만** 본다. 팝빌 자격·전송정책은 발행 시점에 확인된다.

### 그 다음 표로 보여준다

확정된 내용을 **표로 정리해 사람에게 보여준다.** 이게 이 스킬의 마지막 산출물이다.

```
📋 발행 준비 완료 — 확인해 주세요

  거래처    주식회사 엔노블 (123-45-67890)
  대표자    홍길동
  이메일    account@ennoble.co.kr
  작성일자  2026-07-31
  품목      마케팅 대행 7월분
  공급가액  5,000,000원
  세액        500,000원
  합계      5,500,000원

이대로 진행할까요? 확인해 주시면 증빙방에 발행 카드를 올리겠습니다.
(발행 버튼은 사장님이 누르십니다)
```

🔴 **숫자를 다시 계산해서 바꾸지 말 것.** 사람이 확정한 값을 그대로 옮긴다.
🔴 **사람이 "네"라고 한 뒤에 4단계로 간다.** 표를 보여주자마자 카드를 올리지 않는다 — 카드가 올라가면 사장님 방에 알림이 울린다.

---

## 4단계 — 발행 요청 (증빙방에 카드 올리기)

사람이 표를 보고 "네"라고 한 뒤에만 부른다. **3단계 검수에 넣은 인자를 그대로 다시 쓴다.**

```
mcp__jedi__request_tax_invoice_issue({
  buyer_biz_no: "123-45-67890", buyer_name: "주식회사 엔노블", buyer_ceo: "홍길동",
  buyer_email: "account@ennoble.co.kr",
  issue_date: "2026-07-31", supply_amount: 5000000, tax_amount: 500000,
  items: [{ name: "마케팅 대행 7월분", qty: 1, unit_cost: 5000000, supply: 5000000, tax: 500000 }]
})
```

이 도구가 하는 일은 **요청을 기록하고 증빙방에 카드를 띄우는 것뿐**이다. 팝빌에 아무것도 등록하지 않는다.

| 카드 버튼 | 누르면 |
|---|---|
| **[✅ 발행합니다]** | 팝빌에 등록·발행 → 발행완료 카드가 이어서 뜬다 |
| **[❌ 취소]** | 요청이 닫힌다. 국세청·팝빌 어디에도 흔적이 없다 |

호출 뒤 사람에게는 이렇게만 전한다.

> 증빙방에 발행 카드를 올렸습니다. **[✅ 발행합니다]** 를 눌러 주세요.

- 🔴 **버튼을 대신 눌러줄 방법은 없다.** 서버가 사람 클릭이 아닌 발행을 거부한다(`_assertHumanCallback`).
- 🔴 **카드를 두 번 올리지 말 것.** 응답이 늦어도 다시 부르지 않는다 — 카드가 두 장이면 사장님이 어느 것을 누를지 헷갈린다.
  (혹시 두 번 눌려도 발행은 한 번만 된다. 두 번째 클릭에는 *"이미 처리된 요청입니다"* 가 뜬다.)
- ⚠️ **카드 버튼은 24시간 뒤 만료된다.** 하루 넘게 방치된 카드를 누르면 *"만료된 카드입니다"* 로 거절되니, 그때는 4단계를 다시 부른다(새 카드가 올라간다). 지난달 카드의 버튼이 살아 있으면 오발행 표면이 되기 때문에 일부러 이렇게 뒀다.
- ⚠️ **사장님(master 토큰)이 이 스킬을 쓸 때는** `write_tenant_id: "a0000000-0000-0000-0000-000000000002"` 를 함께 넣는다. 없으면 도구가 거부한다. 신나래처럼 줄갭 계정으로 부르면 넣지 않는다.
- ⚠️ 이 도구는 검수를 **한 번 더** 한다(거래처·금액에 더해 팝빌 자격·전송정책까지). 3단계를 통과했어도 여기서 막힐 수 있고, 그러면 이유가 그대로 온다.

### 발행 후에 틀린 걸 발견했다면

증빙방 발행 카드에 **[✏️ 내용이 틀렸어요]** 버튼이 있다. 누르면 순서를 안내해 준다.

1. 카드에서 **[🗑 발행취소]** — 아직 국세청에 안 갔으면 취소된다
2. **이 창(클로드코드)으로 돌아와** "방금 계산서 내용이 틀렸어요" 라고 말한다
3. 여기서 이어서 고친 뒤 다시 준비한다

🔴 **텔레그램에서 고칠 내용을 적지 말 것** — 그 대화는 이 세션과 이어지지 않아 처음부터 다시 해야 한다. 수정은 **항상 이 창에서** 한다.

## 5단계 — 최종 검증 (버튼을 누른 뒤 **반드시** 한다)

🔴 **카드를 올리고 끝내지 않는다.** 사장님이 버튼을 누르면 **이 창으로 돌아와** 실제로 그렇게 됐는지 확인하는 것까지가 이 스킬의 일이다. 텔레그램 알림 문구는 "무엇을 하려 했는가"이지 "무엇이 됐는가"가 아니다.

사장님이 *"눌렀다"* 고 하면 문서번호로 조회한다.

```
mcp__jedi__get_tax_invoice({ mgt_key: "ZG-202608-002" })
```

### 볼 것 — 상태 코드가 경로를 말해준다

| `state_code` | `state_label` | 뜻 | `cancellable` |
|---|---|---|---|
| **300** | 발행완료 (전송 전) | 팝빌엔 등록됐고 **국세청엔 아직 안 갔다** | ✅ true |
| **303** | 전송중 | **국세청으로 갔다 — 되돌릴 수 없다** | ❌ false |
| 600 | 발행취소 | 취소됨 | ❌ |

🔴 **`cancellable`이 상태와 짝이 맞는지 함께 본다.** `state_code=303`인데 `cancellable=true`면 어딘가 어긋난 것이니 사장님께 보고한다. 상태 하나만 보고 «됐다»고 말하지 말 것.

### 대조 3종 (전부 확인하고 표로 보고)

1. **금액** — `supply_amount` / `tax_amount` / `total_amount`가 3단계에서 확정한 값과 같은가
2. **품목** — `items` 개수와 각 `name`·`supply`가 같은가 (숫자 하나가 밀려도 수정세금계산서를 써야 한다)
3. **국세청 승인번호** — `nts_confirm_num`이 채워져 있는가

### 경로별 다음 안내

| 사장님이 누른 것 | 확인될 상태 | 사람에게 할 말 |
|---|---|---|
| **[국세청 전송]** 까지 | `303 전송중` | "국세청 전송까지 끝났습니다. 취소는 불가하고 정정은 수정세금계산서로만 됩니다." |
| **[✅ 발행합니다]** 만 | `300 발행완료 (전송 전)` | "**다음 영업일 오후 3시**에 팝빌이 자동 전송합니다. 그전까지는 [발행취소]로 되돌릴 수 있습니다." |

🔴 **다음 영업일을 요일로 계산해서 알려줄 것** — 수요일 발행이면 목요일 15시, **금요일 발행이면 월요일 15시**다. "다음 영업일"이라고만 말하면 사람이 다시 계산해야 한다.

### 여러 건이면 목록으로

```
mcp__jedi__list_tax_invoices({ from: "2026-08-01", to: "2026-08-31" })
```

- 문서번호는 `ZG-YYYYMM-NNN` 형식이다.
- **전송 여부를 다른 필드로 추측하지 말 것** — `state_code`가 유일한 판정축이다.
- 조회는 국세청에 아무 영향이 없다. 마음껏 봐도 된다.

### 🔴 노션은 **자동으로 안 바뀐다** — 사람이 채워야 한다 (2026-08-05 실측)

발행이 끝나도 **노션 「월별 인보이스 DB」는 발행 전 상태 그대로다.** 역기록 배선이 아직 없다(실측: 발행·국세청 전송까지 끝난 건인데 `세금 계산서 발행 여부`가 `__NO__`, 상태도 `2. 마감자료 보고`).

**그대로 두면 다음 달에 이 표를 보고 *"8월분 아직 안 끊었네"* 로 읽는다.** 발행 확인 뒤 사람에게 이렇게 안내한다.

> 노션 인보이스는 자동으로 안 바뀝니다. 「월별 인보이스 DB」에서 이 건을 이렇게 고쳐 주세요.
> · 상태 → **3. 세금계산서 발행**
> · 세금 계산서 발행 여부 → **✅**
> · 비고 → `ZG-202608-002 / 승인 <국세청승인번호> / <전송완료 or 전송대기>`

- ⚠️ **승인번호를 담을 필드가 아직 없다** — 그래서 비고에 문자열로 적는다(임시). 필드 3개 신설 + 자동 역기록 크론은 설계 완료·구현 대기(`~/.claude/specs/2026-08-05-invoice-nts-watch-and-notion-writeback.md`).
- 🔴 **전송 전(300)인 건을 「발행 완료」로 적지 말 것** — 익일 자동 전송을 기다리는 중이면 비고에 **전송대기**라고 남긴다. 노션이 실제보다 앞서 나가면 다음 달 대사에서 어긋난다.
- ⚠️ 인보이스 DB는 **거래처마다 별도**다(엔노블·검단가온이 각각 다른 DB). 한 곳만 고치면 반쪽이다.

> 📌 **실측 (2026-08-05 첫 운영 발행 2건)**: 같은 날 올린 카드 2장에서 사장님이 한쪽은 [국세청 전송]까지, 다른 쪽은 [✅ 발행합니다]만 눌렀고 **상태가 정확히 303 / 300으로 갈렸다**. 이 5단계가 그것을 확인해 준 절차다.

## 안 하는 것 (경계)

- ❌ **발행 · 국세청 전송 · 발행취소 · 수정발행** — 전부 **텔레그램 인라인버튼 전용**이다. 이 스킬에 경로가 없다. 4단계에서 부르는 것은 **요청**(카드 띄우기)이지 발행이 아니다.
- ❌ **금액 임의 결정** — 계약·견적에 근거하거나 사람에게 묻는다.
- ❌ **거래처 정보 추측 등록** — 사업자등록증 등 근거가 있어야 저장한다.
- ❌ **월마감** — 별개 절차다(`/월마감`). 계산서 발행과 월마감은 서로 무관하다.
- ❌ **입금 확인·미수금 관리** — 월마감 집계가 담당한다.

## 함정

- 🔴 **거래처를 건너뛰고 금액부터 묻지 말 것.** 없는 거래처면 사람이 두 번 일한다.
- 🔴 **필요한 정보를 한 번에 알려줄 것.** 한 항목씩 물으면 왕복이 늘어난다.
- 🔴 **대표자명 없이 준비를 끝냈다고 하지 말 것.** 발행 단계에서 튕겨 사람이 다시 와야 한다.
- 🔴 **이메일이 비었는데 `ready_to_issue=true`라고 넘어가지 말 것.** 시스템은 이메일을 안 보지만 거래처는 그걸로 받는다.
- 🔴 **거래처가 아직 거의 등록돼 있지 않다.** 실 거래처는 0건에 가까우니 첫 계산서 전에 등록이 선행된다고 미리 안내한다.
- 🔴 **줄갭 사업자번호는 `361-88-02764`(주식회사 줄갭, 법인)** 이다. PC에 있는 `217-16-25954`는 **줄갭AI 개인사업자로 다른 사업자**다 — 섞지 말 것.
- 🔴 **표를 보여주자마자 카드를 올리지 말 것.** 카드가 올라가면 사장님 방에 알림이 울린다. 사람이 "네"라고 한 뒤가 4단계다.
- 🔴 **5일과 10일을 같은 것으로 말하지 말 것.** 5일은 권고, **10일은 세법상 마감**(넘기면 가산세)이다.
- ⚠️ 세액은 보통 공급가액의 10%지만 **면세·영세율이면 다르다.** 확신이 없으면 사람에게 확인한다.
- ⚠️ 작성일자를 **당월로 잡으면 지연발행**이 될 수 있다. 전월분은 전월 말일이 기본이다.
- ⚠️ **줄갭 테넌트 전용**이다. 다른 회사 계정으로 부르면 도구가 거부한다.
- ⚠️ **사장님(master 토큰)으로 부를 때만** 테넌트를 함께 넣는다 — 조회·검수는 `read_tenant_id`, 발행 요청은 `write_tenant_id`, 값은 둘 다 `a0000000-0000-0000-0000-000000000002`. 신나래처럼 줄갭 계정으로 부르면 **넣지 않는다**(자동으로 붙는다).
