# 줄갭 세금계산서 준비 (경리)

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 범위 밖을 요청하면
> **즉시 이 절차를 그만두고 도구를 직접 호출한다.**
> 단, 아래 「발행하지 않는다」만은 예외다 — 그건 지름길이 아니라 **경계**다.

## 🔴 이 스킬은 발행하지 않는다

준비만 한다. **국세청에 도달하는 행위(발행·전송·취소·수정발행)는 이 스킬에 경로가 없고, 만들어서도 안 된다.**

이유는 하나다 — **되돌릴 수 없기 때문이다.** 국세청에 전송된 계산서는 팝빌이 아니라 **국세청 제도상** 취소가 없고, 수정세금계산서(마이너스) 상계만 가능하며 거래처에도 그 이력이 보인다. 그래서 마지막 한 걸음은 **사람이 텔레그램에서 버튼을 누르는 것**으로 남겨뒀다.

> ⚠️ 사용자가 *"그냥 발행까지 해줘"* 라고 해도 이 경계는 유지한다. 대신 **준비를 끝까지 마치고** 텔레그램에서 누를 것만 남겼다고 안내한다. 발행 도구는 이 자리에서 보이지도 않는다(설계상 봉인).

## 개요

- 실행: 신나래 (사장님도 동일)
- 시점: 매월 **10일** 마감 (전월분 매출 계산서)
- 줄갭 사업자: **주식회사 줄갭 / 361-88-02764**

### 순서 — 거래처가 먼저다

```
1단계 거래처 확인 ─┬─ 등록돼 있다 ──────────→ 2단계
                   └─ 없다 → 정보 한 번에 요청 → 등록 → 2단계
2단계 발행 내용 확정 (금액·세액·작성일자·품목)
3단계 검수(도구) ─┬─ 통과 → 표로 보여주기 → 🔴 여기서 멈춘다
                  │                          발행은 텔레그램 버튼
                  └─ 미비 → 빠진 항목만 재요청 → 재검수
```

🔴 **금액부터 묻지 않는다.** 거래처가 없으면 등록이 선행되어야 하는데, 금액을 먼저 받아두면 등록하는 동안 사람이 두 번 일하게 된다.

---

## 1단계 — 거래처 확인 (여기서 시작한다)

먼저 **누구에게 끊는지**만 묻는다. 금액·품목은 아직 묻지 않는다.

> 어느 거래처에 끊을까요? (상호 또는 사업자번호)

받으면 바로 조회한다.

```
mcp__jedi__find_trade_partner({ name: "엔노블" })
mcp__jedi__find_trade_partner({ biz_no: "123-45-67890" })   // 사업자번호를 알면 이쪽이 정확
```

### (가) 등록돼 있으면

돌아온 값에서 **두 가지를 본다.**

| 볼 것 | 뜻 | 조치 |
|---|---|---|
| `ready_to_issue` | 발행 필수 항목이 다 있나 | `false`면 `missing`에 적힌 것을 채운다 |
| `email` | 계산서 받을 주소 | **비어 있으면 아래 ⚠️ 참조** |

> ⚠️ **이메일이 비어도 `ready_to_issue`는 true가 된다.** 시스템은 사업자번호·상호·대표자명 3개만 보기 때문이다. 그런데 **이메일이 없으면 발행은 되지만 거래처가 계산서를 못 받는다.** 비어 있으면 반드시 물어볼 것:
>
> *"계산서 받을 이메일이 등록돼 있지 않습니다. 지금 알려주시면 함께 저장하겠습니다. (없이 진행하면 거래처가 계산서를 못 받습니다)"*

둘 다 괜찮으면 **2단계**로.

### (나) 없으면 — 필요한 것을 한 번에 요청한다

🔴 **찔끔찔끔 묻지 않는다.** 아래 안내문을 **통째로** 준다. 한 항목씩 물으면 사람이 여러 번 왕복한다.

> 처음 거래하는 곳이네요. **사업자등록증 사진 한 장**이면 제가 읽어서 정리하겠습니다.
>
> **꼭 필요한 것** (없으면 발행이 안 됩니다)
> · 사업자등록번호
> · 상호
> · **대표자명**
>
> **같이 주시면 좋은 것**
> · 계산서 받을 이메일 — 없으면 발행돼도 거래처가 못 받습니다
>
> **사업자등록증에 있으면 함께 담습니다**
> · 사업장 주소 · 업태 · 종목
>
> 사진이 어려우시면 위 항목을 텍스트로 주셔도 됩니다.

사진을 받았으면 값을 읽어 **표로 정리해 보여주고 사람이 확인한 뒤** 저장한다(`source: "ocr"`). 텍스트로 받았으면 `source: "manual"`.

```
mcp__jedi__save_trade_partner({
  biz_no: "123-45-67890",
  name: "주식회사 엔노블",
  ceo_name: "홍길동",          // 🔴 없으면 발행이 튕긴다
  email: "...",                // 계산서 수신용
  address: "...",              // 사업자등록증에 있으면
  business_type: "...",        // 업태
  business_item: "...",        // 종목
  source: "ocr"                // manual | ocr | parsed
})
```

### (다) 정보가 부족하면 — 빠진 것만 다시 요청

저장 후 `ready_to_issue`가 여전히 `false`면 `missing`에 적힌 것만 딱 집어 요청한다.

> 사업자등록증에서 **대표자명**을 못 읽었습니다. 대표자명만 알려주시면 등록을 마치겠습니다.

- 🔴 **판정 키는 사업자번호다.** 상호는 바뀌고 동명이인 법인도 있다.
- 같은 사업자번호가 이미 있으면 **덮어쓰지 않고 빈 값만 채운다** — 기존 정보가 날아갈 걱정은 없다.

---

## 2단계 — 발행 내용 확정

거래처가 확정된 **뒤에** 나머지를 묻는다.

| 항목 | 예 | 없으면 |
|---|---|---|
| 공급가액 | 5,000,000 | 물어본다 |
| 세액 | 500,000 | 보통 공급가액의 10% — **계산해 제시하되 사람이 확정** |
| 작성일자 | 2026-07-31 | 보통 **전월 말일**. 물어본다 |
| 품목 | "마케팅 대행 7월분" | 물어본다 |

🔴 **금액을 추측하지 말 것.** 계약서·견적서가 있으면 그 숫자를 쓰고, 없으면 사람에게 묻는다.

---

## 3단계 — 검수 → 정리해서 보여주기

### 먼저 검수한다 (표를 보여주기 전에)

🔴 **눈으로 확인하지 말고 도구에 물어본다.** 발행이 쓰는 검증과 **같은 코드**라, 여기서 통과하면 발행에서도 통과한다.

```
mcp__jedi__check_tax_invoice_ready({
  buyer_biz_no: "123-45-67890", buyer_name: "주식회사 엔노블", buyer_ceo: "홍길동",
  issue_date: "2026-07-31", supply_amount: 5000000, tax_amount: 500000,
  items: [{ name: "마케팅 대행 7월분", supply: 5000000, tax: 500000 }]
})
```

| 반환 | 뜻 | 다음 |
|---|---|---|
| `ready: true` | 발행 가능 | `parsed` 값으로 아래 표를 만든다 |
| `ready: false` | 빠진 게 있다 | `missing`에 적힌 **그 항목만** 다시 요청 → 채운 뒤 재검수 |

- `parsed`에는 **시스템이 해석한 값**이 들어 있다(하이픈 뺀 사업자번호·합계·정규화된 날짜). **표에는 이 값을 쓴다** — 내가 계산한 값이 아니라.
- ⚠️ 이 검수는 **입력 항목만** 본다. 팝빌 자격·전송정책은 발행 시점에 확인된다.

### 그 다음 표로 보여준다

확정된 내용을 **표로 정리해 사람에게 보여준다.** 이게 이 스킬의 마지막 산출물이다.

```
📋 발행 준비 완료 — 확인해 주세요

  거래처    주식회사 엔노블 (123-45-67890)
  대표자    홍길동
  이메일    account@ennoble.co.kr
  작성일자  2026-07-31
  품목      마케팅 대행 7월분
  공급가액  5,000,000원
  세액        500,000원
  합계      5,500,000원

이대로 발행하시려면 텔레그램 증빙방에서 발행 버튼을 눌러 주세요.
(국세청에 가는 일이라 마지막 확인은 사람이 합니다)
```

🔴 **숫자를 다시 계산해서 바꾸지 말 것.** 사람이 확정한 값을 그대로 옮긴다.
🔴 **여기서 멈춘다.** 발행을 시도하지 않는다.

### 발행 후에 틀린 걸 발견했다면

증빙방 발행 카드에 **[✏️ 내용이 틀렸어요]** 버튼이 있다. 누르면 순서를 안내해 준다.

1. 카드에서 **[🗑 발행취소]** — 아직 국세청에 안 갔으면 취소된다
2. **이 창(클로드코드)으로 돌아와** "방금 계산서 내용이 틀렸어요" 라고 말한다
3. 여기서 이어서 고친 뒤 다시 준비한다

🔴 **텔레그램에서 고칠 내용을 적지 말 것** — 그 대화는 이 세션과 이어지지 않아 처음부터 다시 해야 한다. 수정은 **항상 이 창에서** 한다.

## 4단계 — 발행 내역 확인 (필요할 때)

이미 발행된 건을 볼 때만 쓴다.

```
mcp__jedi__list_tax_invoices({ period: "2026-07" })     // 그 달 목록
mcp__jedi__get_tax_invoice({ mgt_key: "ZG-202607-001" }) // 한 건 상세
```

- 문서번호는 `ZG-YYYYMM-NNN` 형식이다.
- 상태(`stateCode`)로 어디까지 갔는지 알 수 있다 — **전송 여부를 다른 필드로 추측하지 말 것.**
- 조회는 국세청에 아무 영향이 없다. 마음껏 봐도 된다.

## 안 하는 것 (경계)

- ❌ **발행 · 국세청 전송 · 발행취소 · 수정발행** — 전부 **텔레그램 인라인버튼 전용**이다. 이 스킬에 경로가 없다.
- ❌ **금액 임의 결정** — 계약·견적에 근거하거나 사람에게 묻는다.
- ❌ **거래처 정보 추측 등록** — 사업자등록증 등 근거가 있어야 저장한다.
- ❌ **월마감** — 별개 절차다(`/월마감`). 계산서 발행과 월마감은 서로 무관하다.
- ❌ **입금 확인·미수금 관리** — 월마감 집계가 담당한다.

## 함정

- 🔴 **거래처를 건너뛰고 금액부터 묻지 말 것.** 없는 거래처면 사람이 두 번 일한다.
- 🔴 **필요한 정보를 한 번에 알려줄 것.** 한 항목씩 물으면 왕복이 늘어난다.
- 🔴 **대표자명 없이 준비를 끝냈다고 하지 말 것.** 발행 단계에서 튕겨 사람이 다시 와야 한다.
- 🔴 **이메일이 비었는데 `ready_to_issue=true`라고 넘어가지 말 것.** 시스템은 이메일을 안 보지만 거래처는 그걸로 받는다.
- 🔴 **거래처가 아직 거의 등록돼 있지 않다.** 실 거래처는 0건에 가까우니 첫 계산서 전에 등록이 선행된다고 미리 안내한다.
- 🔴 **줄갭 사업자번호는 `361-88-02764`(주식회사 줄갭, 법인)** 이다. PC에 있는 `217-16-25954`는 **줄갭AI 개인사업자로 다른 사업자**다 — 섞지 말 것.
- ⚠️ 세액은 보통 공급가액의 10%지만 **면세·영세율이면 다르다.** 확신이 없으면 사람에게 확인한다.
- ⚠️ 작성일자를 **당월로 잡으면 지연발행**이 될 수 있다. 전월분은 전월 말일이 기본이다.
- ⚠️ **줄갭 테넌트 전용**이다. 다른 회사 계정으로 부르면 도구가 거부한다.
