### ⚠️ 1차 판단 정정 — 「카테고리 번호가 없다」는 **틀렸다**

처음엔 `li` **자체의** `data-*` 만 보고 「번호가 없으니 이름 매칭이 유일하다」고 적었다.
번호는 **자식 `<input>`** 에 있었다(`data-testid="categoryBtn_111"`, `id="111_RPG_…"`).
e2e 가 실패하고 나서야 li 내부를 열어 보고 알았다.
→ 교훈: **컨테이너만 보고 「속성이 없다」고 단정하지 말 것.** outerHTML 을 실제로 찍어 본다.

### 🔴 드롭다운 토글 → 공개설정 오인 (실측 사고)

드롭다운은 누를 때마다 토글이고, **닫히면 `selectbox__SD2nT` 상자가 통째로 사라진다.**
조상을 타고 올라가 「`li` 를 가진 상자」를 찾는 방식은 이때 **공개설정 라디오 12건**
(`layer_content_set_publish__KDvaV`)을 카테고리 목록으로 잡는다.
그대로 클릭했으면 **글을 비공개로 만들었을 것**이다.
→ 조상 탐색을 버리고 `[data-testid^="categoryBtn_"]` 를 직접 쓴다. 열림도 확인하고 연다.

### 🔴 좌표 클릭이 막힌다

`locator.click()` 이 10초 타임아웃으로 실패한다 — 숨은 `<h1 class="se-help-title">도움말</h1>` 이
에디터 전면(1680×871)을 덮어 Playwright 가 「다른 요소가 가로챈다」로 판정한다.
→ `HTMLElement.click()` 으로 **요소에 직접** 보낸다. 좌표를 쓰지 않으므로 가려져도 되고,
**발행 버튼 옆에서 빗나갈 위험이 없다**. `force:true` 우회는 금지 — 빗나가면 그대로 게시된다.

### 🔴 「로그인 상태 유지」를 안 켜면 창 닫을 때마다 로그아웃

네이버는 그 체크가 없으면 **세션 쿠키만** 준다 — 브라우저를 닫는 순간 `NID_AUT`/`NID_SES` 가 사라진다.
실측: 로그인 직후 `logged_in: true` (쿠키 15) → 창 재시작 후 `logged_in: false` (쿠키 10).
프로필 폴더를 옮겨서가 아니다(폴더명과 무관). **로그인 안내에 이 문구를 반드시 함께** 준다.

### fail-closed

**번호와 이름이 둘 다 맞을 때만** 고른다. 번호만 보면 그 자리에 다른 카테고리가 들어앉아도 모르고,
이름만 보면 동명이 있을 때 못 가린다. 어긋나면 `NAME_CHANGED` 로 **멈추고 실제 이름을 알려 준다**.
고른 뒤에도 버튼 텍스트를 다시 읽어 **반영을 확인**한다(`NOT_APPLIED`).

## 키보드 타이핑 vs 붙여넣기 (사장님 질문 → 실측으로 결정)

```
p.keyboard.type('한글타이핑시험입니다', {delay:30})
→ 정확히 입력됨 ✅ · 471ms (글자당 47ms)
→ 🔴 문단 «한가운데»에 박혔다: "여기까[한글타이핑시험입니다]지 복사"
```

| 축 | 붙여넣기 | 키보드 타이핑 |
|---|---|---|
| 한글 | ✅ | ✅ (IME 문제 없음) |
| 2,000자 | 즉시 | 약 94초 |
| **소제목·굵게·표** | ✅ | 🔴 **불가** — 평문. 서식은 드래그+툴바라 훨씬 잘 깨진다 |
| 커서 | 무관 | 🔴 매번 정밀 제어 |

**결론: 붙여넣기.** 단 **클립보드는 쓰지 않는다**(팀원이 작업 중 복사하면 깨지므로) —
`DataTransfer` 로 paste 이벤트를 에디터에 직접 전달한다. 실측에서 서식 유지된 채 주입 성공.

## 위험에 대해 «증명하지 못한» 것

확인된 것은 **「에디터 주입이 된다」**까지다. **「계정 위험이 낮아진다」는 증명되지 않았다.**

| 확인됨 | 미확인 |
|---|---|
| 자동화 표식(`navigator.webdriver`) 미노출 | 네이버가 **다른 축**으로 탐지하는지 |
| 평소 크롬·IP·쿠키 사용 | 그것으로 **충분한지** |

🔴 감지는 확률적이다(*"수백 개를 똑같이 했는데 몇 개만 걸렸다"* — 운영 경험담).
**무사통과가 안전의 증거가 못 된다.** 그래서 위험을 0으로 만들었다고 주장하지 않고
**줄인다**고만 말한다. **초기 2주는 하루 5편 이하**, 이상 신호 시 즉시 중단.

### 🔴 진짜 원인 — 「붙여넣기가 이미 올라간 이미지를 깨뜨린다」

교대 구간의 DOM 을 1초 간격으로 찍어 잡았다. **업로드는 한 번도 실패하지 않았다.**

```
이미지 4  → 반영 확인 (1.1초)              naverImages 4 / placeholders 0
[텍스트 245자 붙임]  →  naverImages 4 → 2 · placeholders 0 → 2      ← 여기다
```

**이미 서버에 올라가 있던 이미지 2장이, 다음 텍스트를 붙이는 순간 SVG 자리로 되돌아간다.**
그래서 개수가 줄고, 다음 업로드의 「개수가 늘었나」 판정이 어긋나 «업로드 실패»로 오판된다.

| 확인한 것 | 결과 |
|---|---|
| 스크롤해서 화면에 넣으면 되살아나나 (지연 렌더링인가) | ❌ 그대로 — **진짜 손상**이다 |
| 이미지 뒤 대기를 0.8초 → 5초로 늘리면 | ❌ 완전히 동일 — **시간 문제가 아니다** |
| 깨진 자리의 «위치»는 맞나 | ✅ **10곳 전부 원고 그대로** — 자리는 온전하고 그림만 깨졌다 |

🔴 **그래서 `removePlaceholder` 가 상황을 악화시킨다.** 그 SVG 자리는 「업로드 실패 자리」가 아니라
**멀쩡한 자리에서 깨진 그림**인데, 실패로 보고 **지운다** — 위치까지 함께 사라진다.
1회차에서 「fig-02 가 한 칸 밀렸다」고 본 것도 이 삭제 때문에 생긴 착시였다(자리는 원래 맞았다).

**인과 정리**

```
업로드 성공(1.1초) → 다음 텍스트 붙여넣기가 이전 이미지를 깨뜨림(SVG 자리)
   → naverImages 가 줄어 다음 업로드가 「실패」로 오판 → 불필요한 재시도
   → removePlaceholder 가 «깨진 자리»를 지움 → 그림이 통째로 사라짐
```

### 처방 실험 — 무엇이 되고 무엇이 안 되는가

**기준선**: 이미지 **4장이 쌓인 상태**에서 다음 글을 붙이면 **2장이 깨진다**(3회 재현).

| 시도 | 방법 | 결과 |
|---|---|---|
| 깨진 자리에 다시 올리기 ① | 앞 문단 끝에 커서 → 업로드 | ❌ **문장이 글자 단위로 갈라짐**<br>`End` 는 «줄» 끝이지 «문단» 끝이 아니다. 긴 문단은 여러 줄로 감겨 커서가 한가운데 멈춘다<br>(「광고」→「광」+[이미지]+「고를」, 「목록」→「목」+[이미지]+「록 밖의」) |
| 깨진 자리에 다시 올리기 ② | 깨진 자리를 좌표 클릭해 선택 → 업로드 | ⚠️ **글은 온전한데 자리가 어긋난다**<br>새 그림이 «직전 그림 바로 뒤»에 붙는다. 에디터가 삽입 위치를 자기 규칙대로 정한다 |
| 붙여넣기 경로 바꾸기 ① | `document.execCommand('insertHTML')` | ❌ **글이 아예 안 들어간다**(글자 0). 네이버가 무시한다 |
| 붙여넣기 경로 바꾸기 ② | 실제 클립보드 + `Ctrl+V` | ❌ **똑같이 깨진다**(4장 → 2장) |

🔑 **붙여넣기 «방식»의 문제가 아니다.** 세 경로가 같은 결과를 냈다 —
네이버가 붙여넣기를 처리하며 문서를 재구성할 때 이미지가 깨진다.

### 🔑 깨진 것이 «정말로» 사라진 것인가 — 아직 모른다

깨진 이미지의 DOM 을 열어 보면 에디터가 그 이미지를 **여전히 알고 있다**.

```html
<img class="se-image-resource" alt="02_.png" width="500" src="data:image/svg+xml,…">
        ↑ 원본 파일명이 그대로 남아 있다      ↑ 표시용 src 만 플레이스홀더
```

컴포넌트도 정상 `se-image` 다. 즉 **화면만 플레이스홀더이고 내부에는 살아 있을 가능성**이 있다.
그렇다면 그대로 등록해도 정상 발행될 수 있고, 반대로 `removePlaceholder` 로 지운 것은
**멀쩡한 이미지를 지운 것**이 된다(1회차에 실제로 9장이 된 경로).

- `SmartEditor.getEditor('blogpc001')._document` 에서 이미지 URL 을 찾으려 했으나 0건 — 구조를 더 봐야 한다
- **결정적 검증 = 임시저장 후 다시 열기.** 「저장」 버튼은 사람 몫이라 승인이 필요하다

**그동안의 안전장치**: 검증이 화면 개수로 판정하므로 `partial` 로 멈춘다.
사람이 모르고 등록하는 일은 없다 — 빠진 자리는 사람이 채우거나 다시 돌린다.
