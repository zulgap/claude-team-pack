## 무엇을 하나

노션 콘텐츠마스터의 **「8. 타이핑 요청」 네이버블로그 카드**를 네이버 글쓰기 창에 채운다.

```
노션 카드 ──▶ 크롬 글쓰기 창 (본문·서식·사진·제목·태그)
                    │
                    ▼
              카테고리 선택            ← 어느 동료사 자리인지
                    │
                    ▼
              사람이 «등록» 클릭      ← 여기만 사람
                    │
                    ▼
          노션 「9. 타이핑 완료」 + 완료일자
```

🔴 **등록 버튼을 절대 누르지 않는다.** 네이버가 자동 발행을 막아 둔 지점이고, 그 앞까지만 대신한다.

## 준비 (처음 한 번)

```bash
npm install playwright-core --prefix "<스킬폴더>"
node scripts/chrome-session.js open <프로필키> "https://blog.naver.com/<블로그ID>?Redirect=Write"
```

뜬 창에서 **네이버 로그인**을 한 번 한다.

🔴 **로그인할 때 「로그인 상태 유지」를 반드시 켠다.** 안 켜면 네이버가 세션 쿠키만 주기 때문에
**창을 닫는 순간 로그아웃된다** — 다음에 열면 또 로그인해야 하고, 그 사이 자동화는 멈춘다
(2026-08-16 실측: 안 켜고 로그인 → 창 재시작 후 `logged_in: false`).

🔑 **프로필키는 «계정» 단위다 — 동료사 단위가 아니다.** 여러 동료사가 한 블로그를 쓰면
프로필키도 같은 것을 쓰고 **카테고리로 갈린다**(예: 마미사·줄갭·RPG → 전부 `ff1030`).
그때 로그인은 **한 번만** 하면 되고, 크롬 창도 계정당 하나만 열린다.
계정이 진짜로 다른 동료사끼리만 프로필키를 따로 만든다.

설정은 `channels/<동료사명>.md` 한 벌씩 둔다.

## 절차

### 1. 크롬 준비

```bash
node scripts/chrome-session.js status <프로필키>
```

- `open: false` → `open` 명령으로 띄우고 **사람에게 로그인 요청**
- `logged_in: false` → 로그인 요청 후 대기. 이때 **「로그인 상태 유지」를 켜시라고 함께 안내**한다
  (안 켜면 창 닫을 때마다 되풀이된다)
- `PROFILE_BUSY` → **다른 창이 쓰는 중.** 뺏지 말고 알린다

### 2. 밀린 카드 조회 (노션 MCP)

```sql
SELECT url, "기획안(👇클릭해주세요)" AS title, date("date:예상 발행일:start") AS due
FROM "collection://7f410191-5034-4dae-8648-7e109bfffe27"
WHERE "콘텐츠 구분" = '네이버블로그'
  AND "단계" = '8. 타이핑 요청'
  AND "동료사명" = '<동료사명>'
ORDER BY due
```

🔴 **동료사명은 `channels/<동료사명>.md` 의 값을 그대로** 쓴다. 한 글자만 달라도 **0건**이 나오고,
그건 「밀린 게 없다」가 아니라 「못 찾았다」이다 — 0건이면 이름부터 의심한다.

🔴 **`8. 타이핑 요청` 정확일치만.** `8-1. 타이핑 중`은 **다른 사람이 작업 중**이라 건너뛴다.
건너뛴 것이 있으면 **개수와 함께 보고**한다 — 조용히 넘기면 몇 편이 영영 안 나가도 모른다.

### 3. 🔴 선점 (한 편씩)

```
「단계」 8. 타이핑 요청 → 8-1. 타이핑 중
```

이걸 **먼저** 한다. 안 하면 다른 팀원이 같은 카드를 열어 **같은 글이 두 번 올라간다**.
누가·언제는 노션이 `last_edited_by`/`last_edited_time`에 자동 기록한다.

### 4. 카드 본문 읽고 조각내기

카드 본문(마크다운)을 파일로 받아:

```bash
node scripts/card-parser.js <카드본문.md>
```

- `검증: OK` 가 아니면 **채우지 않는다**. 문제를 사람에게 알린다
- 🔴 **내부 메모**(재가공 내역·검수 결과·SEO 제목·담당자 피드백·AI 프롬프트)는 파서가 자른다.
  그게 올라가면 **고객 블로그에 우리 내부 문서가 발행된다**
- 카드에 `# 제목` 줄이 **없는 구조**가 있다(엔노블). 그때는 노션 「기획안(👇클릭해주세요)」 값을
  `validateCard(parsed, { title })` 로 넘기고 `parsed.title` 에도 넣어 준다

🔴 **카드 구조는 동료사마다 다르다** (2026-08-16 전수 실측 — 4개 중 3개가 잘못 다뤄지고 있었다)

| 동료사 | 생김새 | 파서가 하는 일 |
|---|---|---|
| RPG | 원고 → `## 재가공 내역` 메모 | 그 헤딩부터 뒤를 버림 |
| 마미사 | 메모 → `## 네이버 게시용 원고` → 원고 | **그 헤딩 앞을 통째로** 버리고, `### 제목` 다음 줄을 제목으로 |
| 엔노블 | 원고 + `> 🔁` `> ✅` 이모지 인용문 메모 | 이모지 인용문·AI 프롬프트 코드블록을 버림 |
| 검단가온 | `## SEO 제목`·`## 메타 설명` → `# 제목` → 원고 | 머리말 섹션을 버림 |
| 댕묘 | 원고 → `### 참고 자료` → 해시태그 → `### 썸네일` → 그림 | 썸네일 그림만 **본문 맨 끝으로** 옮기고 나머지 메모는 버림 |

🔴 **맨 앞 「붙여넣기 안내」는 버린다** (2026-08-16 실측 — 고객 블로그 «첫 줄»로 나가고 있었다).
RPG `> 네이버 블로그에 그대로 붙여넣는 원고입니다…` · 댕묘 `> **붙여넣기 안내**` + 번호 목록 + `---`.
이모지로 시작하지 않아 메모 걸러내기를 통과했고 유출 지문에도 없어 **검증까지 초록이었다.**
판정축은 **«자리»**다 — *첫 헤딩·첫 본문 줄보다 앞에 있는 인용문*. 문구 목록으로 잡지 말 것(동료사마다 다르다).
**본문 «안»의 인용문은 안 건드린다** — 검단가온 의료 안내·기관 인용은 발행돼야 한다.

🔴 **「참고 자료」를 끝 경계에 «되돌리지 말 것»** (2026-08-16 제거).
원 목록이 RPG 카드 한 장만 보고 지어진 탓에, 댕묘의 **독자용 출처 절**까지 내부 메모로 잘랐다.
그 뒤에 해시태그 10개가 오는 구조라 **출처와 해시태그가 둘 다** 조용히 사라졌는데,
잘린 뒤라 유출 지문에도 안 걸려 **검증은 초록이었다.** 출처 표기는 저작권법상 필수이기도 하다.

⚠️ **새 동료사를 붙일 때는 카드를 먼저 태워 보고** `_test-card-parser.js` 에 축약 픽스처를 추가한다.
목록에 없는 구조는 파서가 못 알아본다 — 그게 이 스킬에서 가장 큰 사고 원인이다.

### 5. 채우기

`scripts/naver-fill.js` 의 `fillCard(page, parsed, imageDir)` 를 쓴다.

| 결과 | 뜻 | 다음 |
|---|---|---|
| `ready_to_register` | 다 채웠다 | 사람에게 확인 요청 |
| `partial` | 일부 실패 | `problems` 를 그대로 보여준다 |
| `blocked` | 이미 내용이 있다 | 덮어쓰지 않는다. 빈 창을 열라고 안내 |

⚠️ **화면에 그림 몇 개가 회색 자리로 보여도 정상이다.** 글을 붙이면 이미 올라간 이미지가
화면에서만 그렇게 바뀐다 — **문서에는 온전히 들어 있다**(2026-08-16 실측: 임시저장분 서버 응답에
이미지 URL 10개 · 플레이스홀더 0개). 발행하면 다 나온다.
🔴 **「고치겠다」고 그 자리를 지우지 말 것** — 그게 멀쩡한 그림을 지우는 길이다(10장 → 9장).
판정은 도구가 «이미지 자리 수»로 하므로, `ready_to_register` 면 다 들어간 것이다.

### 5-1. 🔴 카테고리 고르기

`scripts/naver-category.js` 의 `selectCategory(page, frame, {no, name})` 을 쓴다.
`no`·`name` 은 `channels/<동료사명>.md` 의 **카테고리번호·카테고리** 값이다.

**이걸 빠뜨리면 남의 자리에 글이 올라간다.** 한 블로그를 여러 동료사가 나눠 쓰기 때문에
카테고리가 곧 「누구 글인지」다. 카테고리를 안 고르면 네이버가 **직전에 쓰던 카테고리**를 그대로 쓴다.

| 결과 | 뜻 | 다음 |
|---|---|---|
| `ok: true` | 골라졌고 **화면에서 확인까지 됐다** | 6번으로 |
| `NOT_FOUND` | 그 번호가 이 블로그에 없다 | 카테고리가 지워졌거나 다른 블로그의 번호다 |
| `NAME_CHANGED` | 번호는 있는데 **이름이 다르다** | 네이버에서 이름을 바꾼 것. `actual` 을 보고 채널파일을 고친다 |
| `NOT_APPLIED` | 눌렀는데 안 바뀌었다 | 사람에게 알린다. 그냥 진행하면 안 된다 |

🔴 `ok: true` 가 **아니면 6번으로 넘어가지 않는다.** 카테고리가 틀린 채 등록되면 되돌릴 수 없다.
🔴 **실패했다고 비슷한 이름을 추측해서 고르지 말 것.** 멈추는 것이 이 단계의 정상 동작이다.

### 5-2. 🔴 사람에게 넘기기 «직전»에 카테고리를 다시 본다

```js
const v = await cat.assertCategory(frame, { name: '<카테고리>' });
if (!v.ok) { /* 다시 고르고, 또 어긋나면 사람에게 알린다 */ }
```

**고른 뒤에도 바뀐다.** 2026-08-16 실측: 3편을 연달아 채운 뒤 보니 **세 창 중 둘이 「줄갭이 뭐죠?」로 돌아가 있었다.**
고를 때는 분명 `ok: true` 였고 화면 반영까지 확인한 뒤였다.
창을 여러 개 열어 두면 네이버가 계정 단위로 기억하는 «직전 카테고리»가 되살아난다.

⚠️ **그래서 여러 편을 한꺼번에 채워 두지 않는 편이 안전하다.** 부득이 그렇게 했다면
사람에게 넘기기 전에 **편마다** 이 확인을 거친다 — 그대로 등록되면 남의 자리에 발행되고 되돌릴 수 없다.

### 5-3. 예약발행 — 시각의 정본은 «노션»이다

```js
const r = await cat.setSchedule(page, frame, { at: <노션 「예상 발행일」 값> });
```

**시각을 여기서 정하지 않는다.** 노션 「예상 발행일」에 적힌 것을 옮길 뿐이다 —
카드가 정본이고 발행은 옮기는 쪽이라는 원칙이 여기에도 그대로 적용된다.

**날짜도 함께 넣는다** (2026-08-16 실측 — 그 전에는 「미실측」이라 사람이 창마다 달력을 눌렀다).
화면은 언제나 **오늘**을 기본으로 열기 때문에, 내일 이후로 미루면 **항상** 달력을 만져야 한다.
`setSchedule` 이 날짜가 어긋난 것을 보면 `pickDate()` 로 달력을 열어 그 날을 고르고, **고른 뒤 화면에서 다시 읽어** 확인한다.

| 결과 | 뜻 | 다음 |
|---|---|---|
| `ok: true` | 날짜·시각을 넣었고 **화면에서 다시 읽어 확인**했다 | 5-2 카테고리 재확인 → 6번 |
| `NO_TIME` | 노션에 **날짜만** 있고 시각이 없다 | 노션에 시각을 넣어 달라고 한다 |
| `MINUTE_STEP` | 네이버는 **10분 단위**만 받는다 | 노션 시각을 10분 단위로 고친다 |
| `DATE_MISMATCH` | 달력을 열었지만 그 날짜에 **닿지 못했다** (`cause` 에 이유) | **날짜는 사람이 고른다** — 아래 표 |

`DATE_MISMATCH` 의 `cause` — 넷 다 «모르면 멈춘다»는 원칙의 결과다. 추측해서 아무 날이나 누르지 않는다.

| `cause` | 뜻 |
|---|---|
| `CAL_NOT_OPEN` | 날짜칸을 눌렀는데 달력이 안 열렸다 |
| `CAL_HEAD_UNREADABLE` | 달력의 연·월을 못 읽었다 (표기가 바뀌었을 수 있다 — 아래 🔴 참조) |
| `CAL_MONTH_FAR` | 목표 달이 **6달 넘게** 떨어져 있다 (노션 날짜를 확인할 것) |
| `CAL_MOVE_BLOCKED` | 이전/다음 달 버튼이 막혀 있다 (과거로는 못 간다) |
| `CAL_DAY_NOT_FOUND` | 그 달에 해당 일 칸이 없다 |

🔴 **달력의 월 표시는 `8` 이 아니라 「8월」이다.** `Number("8월")` 은 `NaN` 이고, NaN 비교는 무조건
거짓이라 **「도착했나」 판정이 영원히 실패해 한 방향으로만 계속 넘어간다**(실측: 8월 → 11월까지 밀려갔다).
`monthDistance()` 가 `parseInt` 로 읽는 유일한 자리이고, `_test-naver-category.js` 가 이 함정을 잠근다.

🔴 **노션은 시각을 UTC 로 준다.** SQL 조회에서 `2026-08-16 10:20:00Z` 로 나온 값이 화면에는 **19:20(KST)** 이다.
`parseScheduleAt()` 이 이 변환을 한다 — **빼면 9시간 어긋난 시각에 발행되고, 노션과 대조해도 둘 다 「맞다」고 보인다.**
⚠️ 예약을 넣으면 발행 패널을 만지게 되므로 **5-2 카테고리 확인을 반드시 다시** 한다.

### 5-4. 대표 이미지 (썸네일) — 검색결과에 뜨는 «얼굴»

```js
const r = await fill.setRepImage(page, frame, 0);   // 0부터. 몇 번째 그림을 대표로 할지
const now = await fill.readRepImage(frame);          // { index, total }
```

**발행 패널에는 이 항목이 없다** (2026-08-16 실측 — 패널은 카테고리·주제·공개설정·태그·발행시간·공지사항이 전부).
본문 그림마다 붙은 `.se-set-rep-image-button` 이 그 일을 하고, `se-is-selected` 가 지금 대표를 가리킨다.

**실측 4단계**

| | |
|---|---|
| ① 그림 2장을 넣은 직후 | **첫 장이 자동으로 대표**가 된다 |
| ② 2번 그림을 클릭 | 대표는 **안 바뀐다** — 클릭만으론 안 된다 |
| ③ 2번의 대표 버튼을 누름 | |
| ④ 확인 | 대표가 1번 → 2번으로 **옮겨간다**(배타적) |

🔴 **이미 그 그림이 대표면 누르지 않는다.** 이 버튼은 토글이라 한 번 더 누르면 대표가 «풀리고»,
그러면 네이버가 다시 첫 장을 쓴다. `setRepImage` 가 그 판정을 스스로 하므로 **직접 클릭하지 말 것**.

#### 썸네일이 있는 카드는 `fillCard` 가 «알아서» 얼굴로 세운다 (2026-08-16)

네이버는 대표를 **본문에 있는 그림 중에서만** 고른다. 그래서 카드의 「썸네일」 절을 버리면
아무리 정성껏 만들어도 **얼굴로 쓸 수가 없고**, 검색결과에는 본문 첫 도식이 나간다.

- `card-parser` 가 썸네일을 **본문 맨 끝에 한 장** 얹고(사장님 결정 2026-08-16), `thumbnailIndex` 로 자리를 알려준다
- `fillCard` 가 채우기를 마친 뒤 그 자리를 `setRepImage` 로 세운다 — **따로 부를 것이 없다**
- 썸네일이 **없는** 카드(엔노블·검단가온)는 건드리지 않는다. 네이버 기본(첫 장)이 맞다

🔴 **자리가 동료사마다 다르다** (2026-08-16 카드 4장 실측)

| 동료사 | 썸네일 절 | 카드 안 자리 |
|---|---|---|
| 댕묘 | `### 썸네일 (1080 x 1080)` | 해시태그 **뒤**, `## 재가공 내역` **앞** — 이 헤딩이 본문 경계를 «켠다» |
| RPG | `## 썸네일 (1080 x 1080)` | `## 재가공 내역` **뒤** — 경계 «너머»에 있다 |
| 엔노블 · 검단가온 | 없음 | 썸네일을 아예 안 만든다 |

그래서 파서는 본문 파싱과 **별개의 훑기**로 뽑는다. 경계 상태에 얽으면 한쪽을 반드시 놓친다.

🔴 **URL 로 판정하지 말 것** — 검단가온은 **본문 첫 사진**이 노션 S3(`…amazonaws`)다.
URL 을 축으로 삼으면 본문 사진이 얼굴로 둔갑한다. 축은 «썸네일 헤딩»이다.

🔴 **썸네일 주소는 «5분»이면 죽는다.** 카드 그림은 호스팅이 두 계열이다 —
본문 AI 그림은 supabase **영구** 주소, 썸네일·실사진은 노션 `prod-files-secure` **서명 URL(`X-Amz-Expires=300`)**.
카드를 받아 두고 몇 분 뒤에 파싱하면 **썸네일만** 죽고, 본문은 멀쩡해서 조용히 얼굴만 빠진다.
회수 경로는 하나뿐 — **노션에서 카드를 다시 받는 것**(주소를 손으로 이을 수 없다).
`describeImageFailure` 가 그때 만료라고 말해 준다.

### 6. 🔴 등록 «전»에 먼저 적는다

```bash
node -e "require('./scripts/typing-state').markBeforeRegister({card_id:'<url>', card_title:'<제목>', blog_key:'<프로필키>'})"
```

등록은 되돌릴 수 없다. **적기 전에 등록하면**, 그 사이에 죽었을 때 흔적이 0이라
다음 실행이 같은 카드를 또 올린다(= 중복 게시).

### 7. 사람이 등록 — 🔴 «버튼만 누르면 되는 상태»로 넘긴다

```bash
node scripts/ready-to-register.js --category "<카테고리>" --front 1
```

**등록은 사람이 누른다. 그러면 누르기 직전까지는 도구가 다 해야 한다** —
그러지 않으면 사람이 창마다 카테고리·날짜·그림을 눈으로 훑게 되고, 그게 이 스킬이 없애려던 수고다.

이 스크립트가 하는 일:

| | |
|---|---|
| **순서** | 열린 글쓰기 창을 **예약이 이른 순**으로 늘어놓는다 — 사람이 누르는 순서가 곧 발행 순서다 |
| **점검** | 편마다 제목·본문·그림 자리·카테고리·예약(날짜·시각)·발행 버튼 유무를 읽는다 |
| **판정** | 하나라도 걸리면 그 편은 **「누르지 마세요」** 로 표시하고 사유를 적는다 |
| **안내** | `--front N` 으로 N번 창을 **앞으로 가져온다** |

🔴 **이 스크립트는 아무 버튼도 누르지 않는다.** 발행 버튼이 **있는지 확인만** 한다.

🔴 **예약이 안 걸린 창은 반드시 걸러진다** — 그 상태로 누르면 **그 자리에서 발행된다.**
판정 사유에 「지금 나갑니다」라고 적어 준다(`_test-ready-to-register.js` [4]가 이 문구를 잠근다).

사람에게는 **한 줄로** 안내한다 — *"각 창에서 「발행」 버튼만 누르시면 됩니다.
예약이 걸려 있어 지금 나가지 않고 그 시각에 나갑니다."*

⚠️ 창이 여럿이면 **카테고리가 되돌아갈 수 있다**(5-2). 이 스크립트가 편마다 다시 읽으므로
넘기기 «직전»에 한 번 더 돌리는 것이 안전하다.

### 8. 완료 처리

사람이 「올렸다」고 답하면:

```
「단계」 → 9. 타이핑 완료   (예약 등록이면 10. 예약발행완료)
「타이핑 완료일자」 → 오늘 (KST)
```

성공하면 `markPosted`, 노션 갱신이 실패하면 **`markUnknown`** 으로 남기고 **사람에게 알린다**.
🔴 `unknown` 을 「안 올렸음」으로 뭉개면 다음에 또 올려 **중복 게시**가 된다.

### 9. 실패했을 때

```
「단계」 8-1. 타이핑 중 → 8. 타이핑 요청 (되돌림)
```

되돌리지 않으면 그 카드는 **아무도 손대지 않는 상태로 남는다**.

## 함정

- ⚠️ **빈 글쓰기 창도 글자가 있다** — 네이버 안내 문구다. 그 문구는 캠페인이라 수시로 바뀌므로
  문구로 판정하지 말 것. `naver-fill.js` 가 네이버 자신의 표시(`.se-placeholder`)로 가른다
- ⚠️ **「작성 중인 글이 있습니다」 팝업에서 «확인»을 누르면 안 된다** — 이전 원고를 불러와 섞인다.
  스킬이 자동으로 «취소»(새로 쓰기)를 누른다
- ⚠️ **네이버는 외부 이미지 URL 을 안 가져간다** — 그래서 사진을 내려받아 올린다.
  카드에 붙은 이미지 주소를 그대로 두면 발행 후 우리 서버 주소가 노출되고, 나중에 깨진다
- ⚠️ **한 번에 몰아치지 않는다** — 조각 사이에 쉬고, 초기에는 하루 5편 이하로 시작한다
- ⚠️ **네이버에서 카테고리 이름을 바꾸면 그날부터 멈춘다** — 번호와 이름을 둘 다 대조하기 때문이다.
  `NAME_CHANGED` 가 알려 주는 `actual` 로 `channels/` 파일을 고치면 다시 돈다. **멈추는 게 정상이다**
- ⚠️ **카테고리 이름의 공백은 보통 공백이 아니다** — 네이버가 `&nbsp;`(U+00A0)로 넣는다.
  눈에는 똑같아 보여 사람이 친 공백과 안 맞는다. `normalize()` 가 흡수하므로 **그 치환을 빼지 말 것**
- ⚠️ **드롭다운은 토글이다** — 열려 있는데 또 누르면 닫힌다. 닫힌 채로 목록을 읽으면
  **공개설정 라디오(전체공개/이웃공개/비공개)** 가 잡혀서 카테고리로 오인된다.
  🔴 그대로 누르면 **글이 비공개가 된다.** `listCategories` 는 열림을 확인하고 연다
- ⚠️ **하위 카테고리는 목록에 `하위 카테고리 ○○` 로 뜬다** — 스크린리더용 접두사다.
  `channels/` 파일에는 접두사 없이 자기 이름만 적는다(둘 다 통하게 해 뒀다)
- ⚠️ **발행 패널을 열 때 좌표 클릭이 막힌다** — 숨은 `.se-help-title` 이 화면을 덮고 있어
  Playwright 가 「다른 요소가 가로챈다」로 거부한다. `naver-category.js` 는 요소에 직접 이벤트를 보낸다.
  🔴 `force: true` 좌표 클릭으로 우회하지 말 것 — **발행 버튼 바로 옆이라** 빗나가면 그대로 게시된다
