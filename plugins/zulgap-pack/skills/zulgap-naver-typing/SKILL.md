## 무엇을 하나

노션 콘텐츠마스터의 **「8. 타이핑 요청」 네이버블로그 카드**를 네이버 글쓰기 창에 채운다.

```
노션 카드 ──▶ 크롬 글쓰기 창 (본문·서식·사진·제목·태그)
                    │
                    ▼
              사람이 «등록» 클릭      ← 여기만 사람
                    │
                    ▼
          노션 「9. 타이핑 완료」 + 완료일자
```

🔴 **등록 버튼을 절대 누르지 않는다.** 네이버가 자동 발행을 막아 둔 지점이고, 그 앞까지만 대신한다.

## 준비 (처음 한 번)

```bash
npm install playwright-core --prefix "<스킬폴더>"
node scripts/chrome-session.js open <프로필키> "https://blog.naver.com/<블로그ID>?Redirect=Write"
```

뜬 창에서 **네이버 로그인**을 한 번 한다. 그 뒤로는 유지된다.
🔴 맡은 채널이 여러 개면 **채널마다 프로필키를 따로** 만든다(계정이 다르므로).

## 절차

### 1. 크롬 준비

```bash
node scripts/chrome-session.js status <프로필키>
```

- `open: false` → `open` 명령으로 띄우고 **사람에게 로그인 요청**
- `logged_in: false` → 로그인 요청 후 대기
- `PROFILE_BUSY` → **다른 창이 쓰는 중.** 뺏지 말고 알린다

### 2. 밀린 카드 조회 (노션 MCP)

```sql
SELECT url, "기획안(👇클릭해주세요)" AS title, date("date:예상 발행일:start") AS due
FROM "<콘텐츠마스터 data_source>"
WHERE "콘텐츠 구분" = '네이버블로그'
  AND "단계" = '8. 타이핑 요청'
  AND "동료사명" = '<동료사명>'
ORDER BY due
```

🔴 **`8. 타이핑 요청` 정확일치만.** `8-1. 타이핑 중`은 **다른 사람이 작업 중**이라 건너뛴다.
건너뛴 것이 있으면 **개수와 함께 보고**한다 — 조용히 넘기면 몇 편이 영영 안 나가도 모른다.

### 3. 🔴 선점 (한 편씩)

```
「단계」 8. 타이핑 요청 → 8-1. 타이핑 중
```

이걸 **먼저** 한다. 안 하면 다른 팀원이 같은 카드를 열어 **같은 글이 두 번 올라간다**.
누가·언제는 노션이 `last_edited_by`/`last_edited_time`에 자동 기록한다.

### 4. 카드 본문 읽고 조각내기

카드 본문(마크다운)을 파일로 받아:

```bash
node scripts/card-parser.js <카드본문.md>
```

- `검증: OK` 가 아니면 **채우지 않는다**. 문제를 사람에게 알린다
- 🔴 본문 뒤 **내부 메모**(재가공 내역·검수 결과·썸네일·발행 전 체크)는 파서가 자른다.
  그게 올라가면 **고객 블로그에 우리 내부 문서가 발행된다**

### 5. 채우기

`scripts/naver-fill.js` 의 `fillCard(page, parsed, imageDir)` 를 쓴다.

| 결과 | 뜻 | 다음 |
|---|---|---|
| `ready_to_register` | 다 채웠다 | 사람에게 확인 요청 |
| `partial` | 일부 실패 | `problems` 를 그대로 보여준다 |
| `blocked` | 이미 내용이 있다 | 덮어쓰지 않는다. 빈 창을 열라고 안내 |

### 6. 🔴 등록 «전»에 먼저 적는다

```bash
node -e "require('./scripts/typing-state').markBeforeRegister({card_id:'<url>', card_title:'<제목>', blog_key:'<프로필키>'})"
```

등록은 되돌릴 수 없다. **적기 전에 등록하면**, 그 사이에 죽었을 때 흔적이 0이라
다음 실행이 같은 카드를 또 올린다(= 중복 게시).

### 7. 사람이 등록

화면을 보여주고 **직접 「등록」을 누르시라고** 안내한다.
예약 발행이면 발행 시각을 카드의 「예상 발행일」로 맞추시라고 함께 안내한다.

### 8. 완료 처리

사람이 「올렸다」고 답하면:

```
「단계」 → 9. 타이핑 완료   (예약 등록이면 10. 예약발행완료)
「타이핑 완료일자」 → 오늘 (KST)
```

성공하면 `markPosted`, 노션 갱신이 실패하면 **`markUnknown`** 으로 남기고 **사람에게 알린다**.
🔴 `unknown` 을 「안 올렸음」으로 뭉개면 다음에 또 올려 **중복 게시**가 된다.

### 9. 실패했을 때

```
「단계」 8-1. 타이핑 중 → 8. 타이핑 요청 (되돌림)
```

되돌리지 않으면 그 카드는 **아무도 손대지 않는 상태로 남는다**.

## 시작할 때 먼저 볼 것

```bash
node scripts/typing-state.js pending
```

`확인안된것` 이 있으면 **그것부터 정리**한다 — 지난번에 등록했는지 아닌지 모르는 카드다.
노션에서 실제 단계를 확인해 `posted` 인지 `not_posted` 인지 가른다.

## 하지 않는 것

- 등록·저장 버튼 클릭 (사람 몫)
- 카드 본문 수정 (원고는 이미 확정된 것)
- 「8-1. 타이핑 중」 자동 회수 (시간으로 뺏으면 남이 편집 중인 카드를 가로챈다)
- 모르는 팝업 클릭 (사람에게 넘긴다)

## 함정

- ⚠️ **빈 글쓰기 창도 글자가 있다** — 네이버 안내 문구다. 그 문구는 캠페인이라 수시로 바뀌므로
  문구로 판정하지 말 것. `naver-fill.js` 가 네이버 자신의 표시(`.se-placeholder`)로 가른다
- ⚠️ **「작성 중인 글이 있습니다」 팝업에서 «확인»을 누르면 안 된다** — 이전 원고를 불러와 섞인다.
  스킬이 자동으로 «취소»(새로 쓰기)를 누른다
- ⚠️ **네이버는 외부 이미지 URL 을 안 가져간다** — 그래서 사진을 내려받아 올린다.
  카드에 붙은 이미지 주소를 그대로 두면 발행 후 우리 서버 주소가 노출되고, 나중에 깨진다
- ⚠️ **한 번에 몰아치지 않는다** — 조각 사이에 쉬고, 초기에는 하루 5편 이하로 시작한다

## 관련

- 카드를 «만드는» 쪽: 채널별 재가공 스킬 (이 스킬은 만들어진 카드를 «옮긴다»)
- 근거·실측 이력: `PROVENANCE.md`
