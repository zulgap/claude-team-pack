## 개요

댕묘는 홈페이지(`dangmyo.com`)와 네이버 블로그 두 채널을 쓴다.
홈페이지 글이 발행되면 같은 주제를 네이버에도 올리는데, **본문을 그대로 복사하면 안 된다.**
중복 콘텐츠가 되면 구글 원본성 평가에서 자체 도메인이 손해를 본다(발행 배선 저널, 「같은 데이터 재가공 → 네이버 발행 — 보류」).

이 스킬은 그 재가공을 규칙대로 수행하고, 붙여넣기만 하면 되는 상태의 노션 카드를 만든다.
**발행은 하지 않는다.** 네이버는 자동 발행 배선이 없고, 사람이 노션에서 복사해 직접 올린다.

## 언제 쓰나

```
"/zulgap-dangmyo-naver"
"댕묘 네이버 재가공해줘"
"홈페이지에 올라간 글 네이버에도 올리게 카드 만들어줘"
"댕묘 8월 발행분 네이버용으로 만들어줘"
```

대상을 지정하지 않으면 아직 네이버 카드가 없는 홈페이지 발행글을 **전부** 찾아 한 번에 처리한다.

## 안 되는 경우

- **새 글을 쓰는 작업** → 블로그 작성 스킬이 할 일이다. 이 스킬은 이미 발행된 글만 다룬다
- **홈페이지에 아직 발행되지 않은 글** → 원문 URL이 있어야 본문에 넣을 수 있다. 「11. 발행완료」가 아니면 건너뛴다
- **네이버에 실제로 올리는 것** → 사람이 한다. 이 스킬은 카드까지만
- **댕묘 외 브랜드** → 편집 기준·카테고리·도메인이 전부 다르다

**댕묘 편집 기준** — 출처 없는 문장을 쓰지 않는다. 브랜드·업체를 지목하지 않는다. 수의학적 판단은 다루지 않고 "이런 신호면 병원"까지만 쓴다.

## 동작 방식

### STEP 1 — 대상 찾기

노션 MCP의 SQL 모드로 조회한다. 아직 네이버 카드가 없는 홈페이지 발행글이 대상이다.

```sql
SELECT url, "기획안(👇클릭해주세요)" AS title, "발행 링크", "키워드", "주제",
       "date:실 발행일:start" AS pub
FROM "collection://7f410191-5034-4dae-8648-7e109bfffe27"
WHERE "동료사명" = '댕묘'
  AND "콘텐츠 구분" = '홈페이지 블로그'
  AND "단계" = '11. 발행완료'
```

같은 조건에서 `콘텐츠 구분 = '네이버블로그'` 카드도 함께 뽑아 **주제가 겹치는 것은 제외한다.**
중복 카드를 만들면 같은 글이 두 번 발행된다.

대상이 0건이면 "대상 없음"으로 보고하고 끝낸다. 단계가 7에 머문 글을 대신 끌어오지 않는다
(도구가 갈 수 있는 끝이 7이고 11은 사람이 바꾸는 칸이라, 7은 "아직 사람이 확인 안 함"을 뜻한다).

### STEP 2 — 원문 읽기

각 카드의 본문 전체를 읽는다. 문장·수치·출처·이미지 URL·캡션을 모두 확보한다.
**이미지는 마크다운 URL을 그대로 복사해 쓴다** — 다시 생성하지 않는다.

🔴 **글 맨 아래 「참고 자료」 섹션을 반드시 함께 떠 온다.** 본문만 읽고 지나가기 쉬운 자리인데,
댕묘는 공적 출처 위에 선 채널이라 이걸 빠뜨리면 글의 근거가 통째로 사라진다(STEP 3-7).
노션 카드에 원문이 없고 홈페이지에만 있는 경우가 있으니, 카드가 아니라 **발행된 홈페이지 글을
WebFetch 로 확인**한다. 항목·법조문·기관명을 그대로 받아 두고, 없는 출처를 지어내지 않는다.

### STEP 3 — 재가공 (본체)

🔴 **복사 금지.** 아래를 전부 적용한다.

**하드리밋 (수치)**

| 항목 | 값 |
|---|---|
| 표의 열 수 | **최대 3열** — 네이버 모바일에서 4열 이상은 잘린다 |
| 카드 제목 | 재작성 제목 뒤에 **홈페이지 실 발행일 ` (M/D)`** (앞자리 0 없이). 미발행이면 ` (홈 미발행)`, 네이버 전용 글이면 붙이지 않는다 |
| 해시태그 | **정확히 10개** |
| 썸네일 | 1080 x 1080, 제목 **최대 3줄 · 줄당 6자 이내** (검색결과 가독성 하한) |
| FAQ | 3~4건 (원문보다 줄인다 — 본문과 중복되는 항목을 뺀다) |

**금지 리터럴 — 아래가 결과물에 하나라도 있으면 실패다**

- 원문 문장을 그대로 옮긴 문단 (수치·법조문·인용문은 예외 — 바꾸면 거짓이 된다)
- 마크다운 링크 `[텍스트](주소)` — 네이버 붙여넣기에서 깨진다. `기관명 — 주소` 텍스트로 바꾼다
- 특정 브랜드·제품명, 그리고 그것을 암시하는 별칭
- 출처가 없는 새 문장

**해야 할 것**

1. **문장을 다시 쓴다.** 사실·수치·출처는 원문과 동일하게 유지한다
2. **구성을 네이버 검색 의도에 맞춰 재배치한다.** 검색어가 묻는 답(결론 표·핵심 목록)을 앞으로 당긴다
3. **표를 3열 이하로 줄인다.** 빠진 열은 본문 문장으로 흡수하고, 전체 표는 홈페이지 원문으로 넘긴다
4. **홈페이지 이미지를 전부 넣는다.** 절대 순서가 아니라 **그 이미지가 설명하는 내용 옆**에 붙인다. 구성을 바꿨으면 이미지도 따라 움직인다. 캡션은 원문 그대로
5. **본문 말미에 홈페이지 원문 URL과 `dangmyo.com`을 넣는다.** 자체 도메인으로 넘기는 통로이자 어느 쪽이 원본인지 알리는 신호다
6. **해시태그 10개.** 앞 3~4개는 카드의 「키워드」 속성값과 같게 맞춘다(순위체크가 읽는 값과 어긋나지 않게). 뒤쪽은 붙여쓰기 롱테일·제도 키워드. `#댕묘`는 전 글 공통
7. **참고 자료를 옮긴다.** 원문 하단의 출처를 본문 맨 끝 **해시태그 바로 앞**에 `### 참고 자료` 로 넣는다

**참고 자료 — 옮길 때 지키는 것 세 가지**

| 규칙 | 이유 |
|---|---|
| **주소를 쓰지 않는다** | 도메인을 한 글자라도 적으면 노션이 자동으로 마크다운 링크로 바꾼다. 위 「금지 리터럴」과 부모 검사기 ③을 동시에 어긴다. `국가법령정보센터에서 조회` 처럼 기관명으로 끝낸다 |
| **표기 형식을 바꾼다** | 원문 줄을 그대로 옮기면 부모 검사기 ①(원문 재사용)에 걸린다. 법령명·기관명·논문 제목은 바꾸면 거짓이 되므로 **형식만** 바꾼다 — 「」 씌우기, 학술지명 괄호로 묶기, 설명 문구 다시 쓰기 |
| **없는 출처를 지어내지 않는다** | 원문에 참고 자료가 없으면 옮길 것이 없는 것이다. 그 상태로 두고 원문 쪽을 고치도록 알린다 |

원문의 **댕묘 자기 글 링크**는 본문 말미 홈페이지 안내 한 줄로 합쳐도 된다. 다만 합쳤다면
그 사실을 「재가공 내역」에 적는다 — 적지 않으면 다음 사람이 누락으로 보고 다시 넣는다.

**셀프체크 — 눈으로 세지 말고 도구를 돌린다**

원고를 파일로 저장한 뒤 부모 스킬(범용 블로그 스킬)의 검사기를 돌린다. **FAIL 0이 아니면 카드를 만들지 않는다.**

```bash
python ../<블로그 스킬 폴더>/scripts/check-naver-repurpose.py <홈페이지원문.md> <네이버원고.md>
```

폴더명은 설치 형태마다 다르다 — 형제 폴더를 확인하고 실제 이름을 쓸 것.

여섯 판정(원문 문장 재사용 0건 · 표 3열 이하 · 마크다운 링크 0개 · 이미지 1장 이상 · 해시태그 10개 · 본문 1,500~8,000자)은 부모 STEP 8과 같다. 위반 문장은 도구가 전부 인용해 준다.

🔴 **손으로 세지 말 것.** 실측(2026-08-09) 즉석 bash 검사가 같은 파일에서 위반을 8건 → 5건으로 다르게 셌고, 해시태그 10개를 17개로 봤고, 원문 재사용 1건을 **놓쳤다**(위반인데 PASS).

**그다음, 참고 자료를 따로 판정한다. 이것도 FAIL 0이어야 카드를 만든다.**

```bash
python ../<블로그 스킬 폴더>/scripts/check-references.py <홈페이지원문.md> <네이버원고.md> \
       --internal-domain dangmyo.com --internal-name 댕묘
python ../<블로그 스킬 폴더>/scripts/check-references.py --selftest   # 12건
```

> 🔴 **검사기는 2026-08-12에 부모(블로그 스킬)로 옮겼다.** 홈페이지·네이버를 함께 쓰는 동료사가
> 실측 6곳이라 댕묘에만 두면 나머지 5곳이 무방비였다. 댕묘 폴더에는 **사본을 두지 않는다** —
> 두 벌이 되면 부모 쪽 개선이 이쪽에 영영 안 온다.
> `--internal-*` 두 값이 댕묘 고유값이고, 나머지 판정은 채널과 무관하다.

🔴 **부모 검사기만 믿으면 안 된다.** 부모 검사기는 「원문을 베꼈나」를 보지 **「빠뜨렸나」를 보지
않는다.** 실측(2026-08-09) e2e 로 만든 카드 3장(고양이 화장실 · 고양이 습식 사료 · 강아지
스케일링)이 **참고 자료 없이 나갔는데 부모 검사기는 FAIL 0을 찍었고**, 이틀 뒤 사람이 발견해
손으로 되메웠다. 참고 자료를 넣은 **뒤에** 이 검사기를 돌린다 — 사람은 부모 검사기가 PASS 하면
다 됐다고 여기고 손을 뗀다.

다섯을 판정한다 — 섹션 존재 · 외부 출처 개수 · 주소 유무(노션 자동 링크) · 원문 그대로 복사 · 해시태그보다 앞인지.

⚠️ **`--internal-*` 를 빠뜨리면 댕묘 자기 글까지 외부 출처로 세어 `[MISSING-REFS]` 오탐이 난다.**
틀리는 방향이 안전한 쪽(놓치지 않는 쪽)이라 진행은 되지만, 자기 글 링크를 본문 말미 안내로
합쳤다면 두 값을 주는 편이 정확하다.

도구가 판정하지 않는 댕묘 고유 항목만 사람이 확인한다.

- [ ] 해시태그에 브랜드·제품명이 없나
- [ ] `#댕묘`가 들어갔나

### STEP 4 — 예상 발행일

🔴 **사람이 날짜를 지정하지 않았으면 요일 정원제로 배치한다(2026-08-09 확정).**
「홈페이지 실 발행일 + 1일」에서 시작하되, **그 날 정원이 차 있으면 다음 발행 가능일로 넘긴다.**

| 월 | 화 | 수 | 목 | 금 | 토·일 |
|---|---|---|---|---|---|
| 4 | 4 | 4 | 4 | **5** | 0 |

합계 21건 = 홈페이지 주간 생산량(하루 3건 × 7일)이다.

🔴 **같은 날 홈페이지에 나간 글이어도 정원이 차면 갈라진다 — 이게 의도한 동작이다.**
예: 8/10(월)에 이미 4건이 잡혀 있으면, 홈페이지 8/9 발행분 중 다섯 번째 글은 8/11로 간다.

**왜 묶지 않고 흩나** — 홈페이지는 주말 포함 매일 나가고(주 21건) 네이버는 평일 5일만 받는다.
+1일만 쓰면 금·토·일 3일치 9건이 전부 월요일로 몰린다. 하루 9건은 네이버에서 저품질 신호로
읽힐 수 있고, 한 주가 앞쪽에 쏠려 뒤가 빈다.

**계산은 도구가 한다. 손으로 세지 말 것.**

```bash
python scripts/assign-publish-dates.py < plan.json
python scripts/assign-publish-dates.py --selftest   # 7건
```

`plan.json` 에 넣을 것 — `items`(제목·홈페이지 실 발행일), 그리고 **`occupied`**(이미 그 날짜에
잡혀 있는 기존 카드 수). `occupied` 를 빼먹으면 남의 자리에 겹쳐 넣는다. 아래로 센다:

```sql
SELECT "date:예상 발행일:start" AS due, COUNT(*) AS n
FROM "collection://7f410191-5034-4dae-8648-7e109bfffe27"
WHERE "동료사명" = '댕묘' AND "콘텐츠 구분" = '네이버블로그' AND "단계" != '보류'
GROUP BY due
```

지키는 것들(도구가 이미 처리한다):

- **월요일 발행 가능** — 이 스킬은 네이버블로그 월요일 제외 규칙을 쓰지 않는다
- **토·일만 제외** — 걸리면 다음 발행 가능일로 민다
- 🔴 **공휴일은 보지 않는다(2026-08-09 확정).** 홈페이지가 공휴일에도 발행하므로 네이버만 쉬면 그만큼 적체가 쌓일 뿐이다. 댕묘 네이버는 공휴일과 무관하게 월~금으로 돈다 — 배치기에 공휴일 입력 자체가 없다
- 계산한 날이 **이미 지났거나 오늘이면** 다음 발행 가능일로 당겨 올린다(`today` 를 넘길 것)
- **홈페이지 발행 순서를 뒤집지 않는다** — 뒤 글이 앞 글보다 먼저 나가면 원본성 신호가 어긋난다
- 한 건이 14일 이상 밀리면 `[PUSHED]` 로 경고한다. 배치가 아니라 **적체** 신호이므로 사용자에게 알린다

### STEP 5 — 썸네일

`scripts/make_thumbnail.py` 로 만든다. 배경·서체·색·레이아웃은 고정이고 **바뀌는 것은 제목뿐**이다.

🔴 **배경은 전 글 공통 한 종류다(2026-08-05 확정).** 축종별·주제별로 배경을 나누자는 제안이 나오면
이 결정을 먼저 확인할 것 — 블로그 목록에서 썸네일이 한 줄로 보일 때 **톤이 같아야 채널로 읽힌다.**
배경이 글마다 다르면 브랜드가 아니라 낱장 이미지 모음이 된다. 구분은 배경이 아니라 **제목 문구**가 한다.

```bash
python scripts/make_thumbnail.py --title "고양이 모래|종량제 봉투|안 됩니다" --out thumb.png
```

🔴 **카피는 3줄 × 줄당 6자 이내다(2026-08-05 v2).** 이게 이 단계의 진짜 제약이다.

**왜 이렇게까지 짧은가** — 네이버 검색결과는 썸네일을 **약 110px**로 줄여 보여준다.
1080에서 글자가 147px은 돼야 거기서 15px이 되어 읽힌다. v1은 스티커 프레임이 사방 265px을
먹어 글자가 72px까지 작아졌고, 검색결과에서 **글자 높이 7px** — 사실상 안 보였다(실측).
v2는 배경 위에 흰 카드를 얹어 166px을 확보한다. 카피가 길면 카드가 있어도 다시 작아진다.

- 스크립트가 **글자 크기 하한 147px을 스스로 검사**한다. 미달이면 `[TOO-SMALL]` 을 찍고 종료코드 2로 끝나며, **PNG 를 만들지 않는다**
- 🔴 **실패는 산출물을 남기지 않는다.** 파일이 있으면 성공, 없으면 실패다 — 종료코드를 놓쳐도 결과가 뒤바뀌지 않게 한 것이다. `[TOO-SMALL]`·`[TOO-MANY-LINES]`·`[EMPTY-TITLE]` 셋 다 같다
- 🔴 **`[TOO-SMALL]` 이 뜨면 레이아웃·여백을 만지지 말고 카피를 줄인다.** 카드 폭을 넓히면 스티커 프레임이 가려져 브랜드가 사라진다
- 카드 제목을 그대로 넣지 말고 **후킹 문구만** 넣는다. 검색 키워드를 첫 줄에 둔다
  - 좋음: `고양이 모래|종량제 봉투|안 됩니다` · `사료 성분표|이상과 이하|정반대입니다`
  - 나쁨: `고양이 모래|종량제 봉투에|버리면 안 됩니다` (줄당 8자 → 하한 미달)
- 줄바꿈은 `|` 로 직접 지정한다. 자동 분할은 의미 단위를 못 지킨다
- **`|` 는 2개까지(= 3줄)** 다. 3개 이상이면 `[TOO-MANY-LINES]` 로 중단한다 — 넘치는 줄을 말없이 잘라내면 제목 일부가 빠진 채 완성된 것처럼 보인다
- 배경·폰트는 첫 실행 때 자동으로 내려받아 캐시한다. 저장소에 넣지 않는다
- 🔴 **한글을 이미지 생성 모델에 그리게 하지 말 것.** 오탈자가 나고 재시도 비용이 크다. 이 스크립트는 글자를 직접 그린다
- 🔴 **한글에 `stroke_width` 를 쓰지 말 것.** 자소 사이가 메워져 오히려 안 읽힌다. 굵기는 서체로만 낸다

### STEP 6 — 카드 만들기

콘텐츠마스터에 새 카드를 만든다. 원본 카드는 건드리지 않는다.

- `동료사명` = `댕묘` / `콘텐츠 구분` = `네이버블로그` / `단계` = `5. 초안작성완료`
- `월`·`연`을 **직접 채운다**(형식 `26년 8월` · `2026년`) — 이 스킬은 노션 MCP 직접 생성이라 도구 자동 기입 대상이 아니다
- `참고링크`에 홈페이지 원문 URL, `특이사항`에 재가공 메모와 배정한 네이버 카테고리

🔴 **제목은 「재작성 제목 + 공백 + (M/D)」 로 조립한다.** 날짜는 STEP 1 조회가 이미 가져온
`실 발행일`(`pub`)을 쓴다 — 새로 캐는 값이 아니다. 월·일에 앞자리 0을 붙이지 않는다(`8/7` 이지 `08/07` 이 아니다).

```
고양이 모래 버리는법, 종량제 봉투에 담으면 수거가 거부됩니다 (8/3)
```

- 홈페이지가 아직 발행 전이면 날짜 대신 **`(홈 미발행)`** — 그 표기 자체가 「네이버가 원본보다 먼저 나가려 한다」는 경고다
- 소개글·공지글처럼 **홈페이지에 대응 원문이 없는 네이버 전용 글은 붙이지 않는다.** 빈칸이 정상이며 누락으로 보고 채우지 말 것

**왜 붙이나** — 네이버용은 제목을 재작성하므로 홈페이지 제목과 글자가 달라, 노션 리스트에서
두 채널의 짝을 눈으로 못 찾는다. 홈페이지가 하루 3건씩 나가면 격차가 빠르게 벌어진다
(2026-08-09 실측: 카드 19장에서 대조가 막혀 전량을 손으로 되짚었다).

**카드를 만들기 전에 도구로 판정한다. FAIL이면 `create_blog_card` 를 호출하지 않는다.**
🔴 **`tenant_id`를 넣지 말 것** (2026-08-11 신설) — 자동 주입된다. 자칭 `tenant_id`가 내 토큰의 회사와 다르면 그 자리에서 `tenant_mismatch`로 끊긴다(관문 순서 ③ → ④). `create_blog_card`는 `write_tenant_id`를 받지 않는다.

```bash
python scripts/check-card-title.py --title "<조립한 제목>" --homepage-pub <YYYY-MM-DD>
```

- 홈페이지 미발행: `--homepage-pub ""` (빈 문자열)
- 네이버 전용 글: `--homepage-pub` 대신 `--naver-only`
- 자가검사: `python scripts/check-card-title.py --selftest` (11건)

날짜 누락뿐 아니라 **홈페이지 실 발행일과 다른 날짜**, **두 번 붙은 날짜**도 잡는다.
눈으로 세지 말 것 — 이 접미사는 매번 기억해서 붙여야 하는 종류라 문서 규칙으로는 샌다.

🔴 **네이버 카테고리는 확정하지 말고 「1순위 + 후보 + 근거」로 적는다(2026-08-05 확정).**
9개 중 실제로 겹치는 자리가 있어 한쪽으로 단정하면 조용히 잘못 분류된다.
특히 **`성분·가격 비교` ↔ 축종별 `사료·급여`** 가 늘 갈린다 — 사료 성분을 다루는 글은 양쪽 다 말이 된다.

- 자리가 분명하면: `카테고리: 묘 · 고양이 > 모래·화장실 (명확)`
- 애매하면: `카테고리: 1순위 묘 · 고양이 > 사료·급여 / 후보 성분·가격 비교 — 성분을 다루지만 제품 간 단가 비교가 아니라 라벨 읽는 법이라 축종 칸으로 봄`

근거를 함께 적는 것이 핵심이다. 근거가 없으면 다음 사람이 같은 고민을 처음부터 다시 한다.
**붙여넣는 사람이 3초 안에 판단할 수 있으면 성공**이고, 틀렸다고 판단되면 그 자리에서 바꾸면 된다.

카드 본문 구성:

```
> 붙여넣기 안내 — **제목 끝 괄호 (날짜)는 떼고 붙여넣을 것**, 카테고리, 소제목 재지정, 링크 걸기
---
## 본문
(재가공 본문 + 홈페이지 이미지 + 원문 링크 + dangmyo.com)
### 참고 자료          ← 해시태그 바로 앞. 주소 없이 기관명·법령명만
해시태그 10개
썸네일 (1080 x 1080)
---
## 재가공 내역 (홈페이지 원문과 달라진 것)
## 발행 전 체크
```

썸네일은 노션에 **파일로 업로드**해 카드 안에서 바로 보이게 한다(file upload → `markdown_source`).
네이버는 외부 이미지 URL을 막으므로, 카드의 이미지는 붙여넣기용이 아니라 **내려받기용**이다.
「발행 전 체크」에 "이미지를 내려받아 네이버 에디터에 직접 업로드"를 반드시 적는다.
