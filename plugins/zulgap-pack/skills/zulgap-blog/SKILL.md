# 블로그 — 조사부터 노션 카드까지

> 🔓 **이 스킬은 지름길이지 울타리가 아니다.** 사용자가 이 스킬의 범위 밖을 요청하면
> **즉시 이 절차를 그만두고 도구를 직접 호출한다.** "그만하고 그냥 만들어줘" 같은 말이 나오면
> 그 순간 이 문서의 지시는 무효다.

**이 스킬은 내가(클로드 코드가) 직접 판단하고 백엔드 도구를 호출한다.** 서버 워크플로우에 넘기지 않는다 — 그래야 질문이 즉시 오가고, 도구가 실패하면 그 자리에서 고칠 수 있다.

> **판정은 사람이 아니라 도구가 한다.** 키워드 등급도, 원고 검수 수치도 내가 세지 않고 도구 반환값을 근거로 제시한다. 직접 세면 틀린다(실사고: 키워드 "5회"라 보고했으나 실제 12회).

## STEP 0 — 세 가지 확인 (없으면 묻는다)

1. **동료사(brand)** — 예: 정코리아 / RPG / 줄갭
2. **채널** — 홈페이지 블로그 / 네이버 블로그
3. **주제** — 있으면 그대로, 없으면 STEP 1에서 발굴

🔴 동료사를 모르면 진행 불가 — 시각물 조회가 brand 없이는 거부된다(동료사 간 자료 교차 오염 방지).

**글 언어를 먼저 확정한다.** 같은 자체 미디어라도 언어가 다르다 — **정코리아는 영문**(해외 독자 대상 한국 여행), **RPG는 국문**(국내 수출입 실무자 대상)이다. 영어권 타겟이면 **제목·H2·H3·FAQ·CTA·캡션까지 전부 영어**로 쓴다. 초안 1차부터 그 언어로 쓴다 — 나중에 번역하면 통째로 다시 써야 한다.

## STEP 1 — 키워드 (도구가 판정)

`ext_golden_keyword` 호출:
🔴 **`tenant_id`를 넣지 말 것** (2026-08-11 신설) — 자동 주입된다. 자칭 `tenant_id`가 내 토큰의 회사와 다르면 `read_tenant_id`를 **보기도 전에** `tenant_mismatch`로 끊긴다(관문 순서 ③ → ④). 동료사 글감을 조사할 때만 그 회사를 **`read_tenant_id`에** 적는다. 줄갭 것이면 둘 다 생략이 정답이다.
🔴 **locale은 언어가 아니라 채널이다** — 네이버는 한국어만 재고, 구글은 한글·영문 둘 다 잰다.
- 네이버 블로그 → `locale='ko'` (네이버 축: 진입=최근 30일 발행량, 단가=네이버 공식 CPC)
- 홈페이지 + 한국어 글 → `locale='google'` (국내 구글 축 — 홈페이지는 구글이 주 채널)
- 홈페이지 + 영어 글 → `locale='en'` (구글 축: Google Ads 미국 기준)
- 네이버가 전부 🔴포화면 같은 키워드를 `locale='google'`로 다시 재서 대조한다.
  실측: `재혼` = 네이버 포화(발행 100+) ↔ 구글 한국 40,500·LOW. 채널이 다르면 판정이 뒤집힌다.
- 주제만 있고 키워드가 없으면 `mode='topic'`, 고객이 실제로 묻는 걸 찾으려면 `mode='question'`

**진입(경쟁도)이 1차 축이다** — 단가가 높아도 노출이 안 되면 소용없다.

결과를 표로 보여주고 추천 1개를 근거와 함께 제시한다. 도구가 안 되면 **추정으로 때우지 말고 그 사실을 말한다.**

🔴 **STEP 4에 넘길 키워드는 도구가 추천한 1~2개만.** 검수 규칙이 **키워드마다 4~6회 반복**을 요구하므로, 5개를 넣으면 억지 조합이 0회로 잡혀 전부 위반이 된다. 실제 타겟 키워드와 그 부분매치 1개면 충분하다.
- seed는 **짧게**. 문장형(`living in Korea as a foreigner — practical guides`)은 `no_candidates`로 0건이 나온다. 짧은 seed(`living in Korea`)로 재시도할 것.

### 🔴 제목에 넣을 키워드는 «연관어»를 보고 고른다 (2026-08-16 실측)

도구가 돌려주는 **연관어 목록이 그 채널에서 그 말이 무슨 뜻으로 통하는지**를 알려 준다.
검색량·발행량만 보고 원어를 제목에 넣으면 **엉뚱한 의도의 검색자**를 부른다.

**실측** — 마미사 UTM 편에서 `seed: "UTM"` 을 네이버 축으로 조사한 결과:

| 나온 연관어 | 무슨 뜻인가 |
|---|---|
| SDN · 항온항습기 · 데이터센터 · VPN · 실시간CCTV · SECURITY | **기업 보안 장비**(Unified Threat Management) |

마케팅 파라미터는 하나도 없었다. 그 글 자체가 「같은 세 글자가 네 가지를 뜻합니다」라며
맥용 가상머신·보안장비·만능재료 시험기를 표로 세고 있었으니, **제목에 원어를 넣는 것은 글의 논지와도 어긋났다.**

**롱테일로 내려가면 풀린다** — `seed: "UTM 파라미터"` → 발행량 **9건 · 진입 쉬움 · 추천**.
수요는 작지만(월 45) 의도가 정확하다.

**판단 순서**
1. 연관어가 **다른 분야**를 가리키면 그 말은 제목에서 쓰지 않는다 (다의어)
2. 발행량 100건+ 이면 **롱테일로 내려간다** — 원어를 고집하지 않는다
3. 롱테일도 포화면 **현행 제목을 그대로 둔다.** 바꿔서 얻는 게 없으면 안 바꾸는 것이 맞다

⚠️ **순화어를 원어로 바꾸는 것이 항상 옳지는 않다.** 「이름 짓기」를 「네이밍」으로 바꾸는 안도
같은 날 검토했는데 `네이밍` 이 발행량 100건+ 포화라 **바꿔도 이득이 0**이었다.

## STEP 1.5 — 프리퀀시 (개요 전에 한다)

> 📖 **`references/blog-theory.md` §1을 읽고 온다.**

키워드를 골랐으면 **그 키워드를 검색한 사람이 지금 어디쯤 있는지**부터 정한다. 건너뛰면 개요 2·3번 칸이 추측이 된다.

| 정할 것 | 어떻게 |
|---|---|
| **온도** (25 / 50 / 75 / 99) | 그 키워드가 증상만 아는 자리인가, 업체를 고르는 자리인가 |
| **컨슈머 프리퀀시** | 그 온도의 사람이 속으로 하는 말 — **지어내지 말고 도구로 가져온다** |
| **동료사 프리퀀시** | 우리는 누구로서 답하나 |

🔴 **속마음은 `ext_golden_keyword({ mode: 'question' })`의 지식iN 실제 질문에서 뽑는다.** **추정으로 채운 속마음은 근거가 없다.**

측정 채널(`locale`)은 §1 표대로 — 네이버 `ko` / 홈페이지 국문 `google` / 홈페이지 영문 `en`.

### 15번 english_slug — 이걸 비우면 크론 자동 발행이 멈춘다

한국어 제목은 URL로 바꿀 수 없어서(`slugify`가 null) **이 칸이 유일한 통로**다. 개요를 확정할 때 **같이** 정한다 — 나중에 따로 물으면 왕복이 한 번 더 는다.

**하드리밋 3개**
1. 영문 소문자 + 하이픈만. 길이 **60자 이하**, 단어 **3~6개**
2. 🔴 **번호를 적지 않는다** — 번호는 발행할 때 레포 파일 목록에서 자동으로 붙는다
3. 제목의 핵심 명사를 쓴다(조사·부사 제외)

**금지 리터럴** — 하나라도 있으면 도구가 거부한다
- 한글 (`고양이-사료`) · 공백 (`cat food`) · 대문자 (`Cat-Food`) · 번호 접두 (`3-cat-food`) · 언더바 (`cat_food`)

**예시**

| 제목 | ❌ | ✅ |
|---|---|---|
| 고양이 사료 리콜을 검색해도 안 나오는 이유 | `3-고양이-사료-리콜` | `cat-food-recall-and-label` |
| 컨테이너 반납 지연료, 하루 늦으면 얼마씩 붙나요 | `Container Detention` | `container-detention-fee` |

**셀프체크** — 도구에 넘기기 전에 5개 다 예인지 본다
- [ ] 한글·공백·대문자·언더바가 하나도 없나
- [ ] 숫자로 시작하지 않나
- [ ] 60자 이하 · 단어 3~6개인가
- [ ] 제목을 안 본 사람이 이 주소만 보고 무슨 글인지 짐작되나
- [ ] 같은 사이트에 같은 이름이 이미 있지 않나

> **비워도 되는 경우**: 정코리아처럼 **영문 제목**인 사이트. 제목에서 자동 생성되므로 비우는 것이 정상 경로다.
> **네이버블로그**는 이 칸을 쓰지 않는다 — 주소를 네이버가 정한다.

**갭언어 9종** — 후킹·제목·소제목에 섞는다. 📖 **정의·예시는 이론 §3** (여기 나열하지 않는다 — 두 곳에 두면 갈라진다)

**시각물 자리 후보**: 도입부 / 핵심 예시 / 신뢰 강화 / 마무리 / 별도 후기 섹션 / FAQ 보강

12번 칸을 정하기 전에 `ext_search_partner_assets`로 **동료사 보유 자료를 먼저 확인한다**(있으면 소싱=동료사실사진, 0건이면 **다음 순위인 도식으로 내려간다** — STEP 5).
> ⚠️ 자체 미디어(우리 자산 사이트)는 이 DB에 **없다** — `invalid_brand`가 정상이고 에러가 아니다. 바로 **표·도식**으로 간다.
> 🔴 **「도식 또는 AI생성」이 아니다.** 소싱은 **위계**이고 AI생성은 **4순위**다(STEP 5 — 위가 있으면 아래로 안 간다).
> 도식으로 되는 것을 AI로 만들면 API 비용이 그대로 나간다. 실측(2026-08-15): 발행 48편에 AI 이미지 **336장**,
> 상당수가 도형+텍스트 도식이었다.

🔴 **표를 다 넣은 뒤 반드시 자문한다 — "표로는 안 되는 대비·흐름이 아직 남았나?"**
표로 되는 것을 표로 넣는 것은 맞지만(STEP 3), 그러고 **끝내면 이미지가 1장으로 주저앉는다**.
`min`은 하한이지 목표가 아니다 — 실측 사고 2건이 전부 "하한만 채운 과소 배치"였다.

## STEP 3 — 초안

> 📖 **`references/blog-theory.md` §5를 읽고 온다** — 본론 한 개를 어떻게 짜는지가 거기 있다.

### 본론 한 개의 모양 (이론 §5-2·5-3)

```
소제목 1개
  주 : 주장
  이 : 왜냐하면 …
  사 : 실제로 …
  강 : 따라서 …
  퍼널글 : [다른 글 링크]        ← 「강」 바로 다음
  "다음 본론으로 넘기는 질문"     ← 원문 명칭 "인용구"
```

- **소제목 3개 이상** · **두괄식** (이론 §5-4)
- **마지막 본론에는 퍼널글도 인용구도 붙이지 않는다**
- 퍼널글 = 내부 링크. 실무 규칙은 아래 § 내부 링크


개요대로 쓴다. 표로 표현되는 것은 **본문 표**로 넣는다(이미지로 만들지 않는다).

이미지가 들어갈 자리에는 마커를 남긴다. **자리마다 도구가 두 개라 표기가 두 가지다** — 헷갈리는 지점이니 표로 못박는다.

| 어디 | 표기 | 왜 |
|---|---|---|
| 원고(`validate_blog_draft` 에 넘기는 markdown) | `![img 1](img-1)` | 시각물 검사가 **이미지 문법**을 세므로 마크다운 이미지 형태여야 한다 |
| 카드 본문 · `attach_blog_card_images` 의 `marker` | `img 1` | 도구가 **마커 문구를 그대로 Storage 파일 키로** 쓴다 |

🔴 **마커에 한글을 쓰지 않는다** (2026-08-13 실측, 2026-08-14 재확인). 전에는 이 자리에
*"글이 영어여도 한글 `[이미지 …]` 로 시작할 것"* 이라고 적혀 있었으나 **그대로 하면 첨부가 죽는다**:

```
Storage 400: InvalidKey — 키 끝이 `…-이미지-1.png` 로 만들어졌다
```

Supabase Storage가 **비ASCII 키를 거부**한다. `rehost:false` 로 피하면 노션 S3 서명 URL(300초 만료)이
그대로 발행돼 **라이브에서 이미지가 깨진다** — 우회가 아니다.

🔴 **그 대신 잃는 것을 알고 쓴다.** 한글 규칙의 이유는 발행 게이트가 대괄호 안의 `^이미지` 를
결정론으로 잡아 **미완성 원고를 차단**하는 것이었다. 영문 마커는 그 그물에 안 걸린다.
**첨부가 성공하면 마커가 0개가 되므로 문제가 없지만, 중간에 실패하면 영문 마커가 남아 게이트가 못 잡는다.**
그래서 `attach_blog_card_images` 반환의 `markers_removed` 확인이 **선택이 아니라 필수**다(STEP 6).

⚠️ **첨부가 마커 하나에서 죽으면 앞쪽도 안 붙는다 — 부분 성공이 아니다.** 실측(2026-08-09 댕묘 21번):
7개 중 6번째가 `marker_not_found` 로 죽었는데 **앞의 2~5도 전혀 안 붙어 있었다.** 실패하면
남은 것만 재호출하지 말고 **카드를 fetch해 어느 마커가 남았는지 센다.**

🔴 **FAQ는 `### 질문` 형식이어야 파서가 읽는다**:

```markdown
## FAQ

### Can I get a phone plan without an ARC?

You can get a prepaid SIM with only your passport...
```

`**Q: …?** A: …` 형식은 **한 건도 안 잡혀** `faq_missing`이 된다. 섹션 헤딩도 `## FAQ` 또는 `## Frequently Asked Questions`만 인정된다.

**외부 자료 인용 하드리밋** (발행 콘텐츠 전체):
- 직접 인용 = 출처당 **1개**, 한국어 공백포함 **40자 미만**(영문 15단어 미만)
- **출처(매체명·저작자) 명시 필수** — 저작권법 §37 별도 형사처벌
- 공표된 자료만. 타사 이미지·차트 캡처 삽입 금지. 가사·시 인용 전면 금지

## STEP 3.5 — 리뷰 3회 (도구 검수 전에 사람 눈으로)

> 📖 **`references/blog-theory.md` §7** — 원문 8문항 그대로.

*"초안은 쓰레기다"* — 빠르게 쓰고 **세 번** 본다. STEP 4 도구 검수는 규격을 세는 것이고, 이건 **논리를 보는 것**이라 축이 다르다.

| 회차 | 문항 |
|---|---|
| **1 주제** | ① 서·본·결이 목적에 부합하는가 ② 표면적 주제가 일관되는가 ③ **실질적 주제를 너무 빨리 보여주진 않았나** ④ 소주제당 주제가 1개로 명확한가 |
| **2 문장** | ① **주이사강이 틀어지지 않았나** ② 더 추가할 예시·사례는 없나 |
| **3 형식** | ① 오타는 없나 ② 키워드를 **4~6회** 넣었나 |

🔴 **3회차 키워드 횟수는 4~6이다** — 이론 원문은 6~7이지만 2026-07-29 확정으로 양 채널 4~6으로 통일했다. **원문을 보고 되돌리지 말 것.**


### 후킹 판정 — 이 후킹이 「센가」

리뷰 3회를 끝냈으면 **후킹 하나만 따로** 본다. 규격이 아니라 «세기»라 도구가 못 세고 **사람·LLM이 판정한다.**

판정 모양 — STEP 4에 `outline.hook_verdict`로 넘긴다:

```
hook_verdict: { gap_type: <갭언어 9종 중 1>, verdict: 'strong' | 'weak', reason: '<한 줄>' }
```

🔴 **건너뛸 수 없다** — 안 붙이면 검수가 `hook_verdict_missing`으로 막는다. 「가리키기는 자주 무시된다」를 구조로 막은 자리다.

**`weak`이면 고쳐서 다시 쓴다.** 다만 `weak`을 적어 넘기는 것 자체는 위반이 아니다 — **판정을 안 한 것만** 위반이다.

📏 판정 참고로 도구가 `hook_chars_per_sentence`(문장당 길이)를 함께 돌려준다. 발행 코퍼스 p75를 넘으면 경고가 붙지만 **위반은 아니다** — 그 구간에도 정상 후킹이 있어 길이만으로는 못 가른다.

🔴 **임계 수치를 여기 옮겨 적지 않는다** — 도구가 응답(`p75`)에 실어 준다. 문서가 값을 복제하면 한쪽만 바뀌었을 때 **에러 없이 조용히 갈린다.**

## STEP 4 — 검수 (도구가 센다)

`validate_blog_draft({ markdown, channel, keywords, outline })` 호출.

🔴 **`outline`을 반드시 함께 넘긴다.** 빼면 **시각물 검사(이미지 개수·소싱·블라인딩)가 통째로 실행되지 않는데**, 반환은 `violations: []`로 와서 **"통과"처럼 보인다**. STEP 2에서 확정한 개요 객체를 그대로 넘기면 된다:

```js
// 🔴 STEP 2의 원고 15칸을 **통째로** 넘긴다. visuals만 넣으면 나머지 14칸이 missing으로
//    위반 11건이 뜬다(실측 2026-08-04).
//    ⚠️ 15번 english_slug는 **여기 넣지 않는다** — URL이라 원고 검사 축이 아니다(STEP 6에서 도구로 직행).
outline: {
  doc_type, author_identity, target_reader, surface_topic, real_topic, keyword_title,
  hook, hook_gap_type, hook_verdict, intro, body, conclusion, faq, visual_facts, references,
  visuals: [ { type: '도식', sourcing: 'AI생성' } ],
}
// type: 표 | 도식 | 사진   ·   sourcing: 동료사실사진 | 제디작성 | 공공캡쳐 | AI생성
// ⚠️ conclusion enum은 「허들낮추기형」처럼 **'형'이 붙는다** (사회적증거·희소성·통념깨기는 안 붙음)
```

반환된 `checks`·`violations`를 **그대로 보여준다**. 위반이 있으면 고쳐서 다시 호출한다. 통과할 때까지 반복하되, **내가 직접 세서 "통과했습니다"라고 말하지 않는다.**

🔴 **`checks`에 `visuals` 키가 있는지 눈으로 확인한다.** 없으면 `outline`을 안 넘긴 것이므로 **그 검수는 "통과"라고 말할 자격이 없다.**

### `checks.ai_voice` — 문체(AI티) 축 (2026-08-05 합류, v7.867.0)

같은 호출에 **AI 말투 판정이 함께** 온다. 규격(분량·키워드·FAQ·출처·시각물)과 **축이 다르다**.

- 🔴 **이 축은 지금 `violations`가 아니라 `warnings`로만 온다** — 두 블로그 채널 프로파일이 `evidence: 'provisional'`(실측 전)이기 때문이다. **발행을 막지 않는다.**
- 그래서 **「위반 0」을 「문체 합격」으로 말하지 않는다.** `checks.ai_voice.warnings`를 열어 보여주고, `evidence`가 `provisional`이면 *"이 장르는 아직 실측 전이라 기호·종결률 2축만 봤습니다"* 를 함께 밝힌다.
- 자주 나오는 것: `voice_symbol_max`(화살표·원숫자 — 말로 풀 것) · `voice_ending_min_ratio`(개조식 명사 종결 조각을 문장으로) · `voice_slop_lexicon_per_1000`(상투 표현) · **`voice_opening_cliche_max`**(아래).

#### 🔴 `voice_opening_cliche_max` — 첫 문장이 상투 도입구인가 (2026-08-16 신설)

「먼저 결론입니다」 「결론부터 적겠습니다」 같은 **도입구로 글이 시작하는지**를 본다.
위 `slop_lexicon` 은 「1000자당 몇 회」인 **밀도 축**이라 첫 줄에 한 번 나오는 도입구를 **원리적으로 못 잡는다** —
그래서 자리를 보는 축을 따로 뒀다.

**왜 생겼나** — 마미사 네이버 3편이 **전부** 이 도입구로 시작했는데 검수는 `ok: true` 였다.
사장님이 발행 직전에 직접 발견하셨다.

**어떻게 고치나** — 대개 **그 한 마디만 떼면 된다.** 바로 뒤 문장이 이미 후킹인 경우가 많다.

```
전: 먼저 결론입니다. 직접 유입이 크다고 브랜드가 알려진 게 아닙니다.
후: 직접 유입이 크다고 브랜드가 알려진 게 아닙니다.
```

🔴 **막지 않는다.** 한 편만 놓고 보면 정상적인 도입일 수 있다. 나쁜 것은 **여러 편이 같을 때**인데
그 판단은 원고 1장을 보는 도구가 못 한다 — 그래서 `metrics.opening.first_sentence` 를 **항상** 돌려준다.

⚠️ **시리즈를 연달아 쓸 때는 이 값을 편끼리 대조한다.** 세 편의 첫 줄이 사실상 같으면
개별로는 전부 통과해도 **읽는 사람에겐 한 글처럼 보인다.** 갭 9종(위 STEP 2)을 편마다 다르게 잡는다.
- `human_review_notes` 4축(시점·감정·추상어 연속·슬로건 주어)은 **코드가 못 세는 것**이라 그대로 옮겨 사람이 보게 한다.

### 광고 기준 (홈페이지 채널만)

홈페이지 글은 **애드센스 기준**이 같은 검수에 함께 걸린다. 네이버는 애드포스트라 해당 없다(네이버 블로그는 애드센스 자체가 불가).

| 위반 | 뜻 | 하한 |
|---|---|---|
| `ad_thin_content` | 분량 부족 | 영문 **600단어** / 한글 **1,500자** |
| `ad_too_few_sections` | 광고 삽입 여지 부족 | H2 **3개** |

🔴 **분량은 언어에 따라 재는 자가 다르다** — 영문은 **단어**, 한글은 **공백 제외 글자**. 도구가 본문에서 언어를 판별하므로 따로 넘기지 않는다. (같은 자로 재면 영문 2,000단어가 12,000자로 잡혀 상한을 6배 초과한 것처럼 보인다.)

🔴 **네이버에는 분량 하한이 따로 없다** — 기존 `too_short`(1,500~2,000자)가 이미 같은 축이라 하한을 또 두면 같은 글에 위반이 2개 뜬다.

⚠️ 한글 하한 1,500은 **영문 600단어의 환산 대응**이지 실측 갭이 아니다(자사 라이브 글이 전부 3,000자대라 thin 사례를 아직 못 봤다). 정상 글을 막지 않는다는 것만 확인된 값이다.

## STEP 5 — 시각물 (위에서부터, 위가 있으면 아래로 안 간다)

1. **동료사 보유 실사진** — `ext_search_partner_assets`
   - 반환에 `degraded`가 있으면 "동료사 자료를 못 읽었습니다"를 결과에 **반드시 남긴다**
   - `blinding_blocked > 0`이면 "얼굴·개인정보 처리가 안 된 사진 N장을 제외했습니다"를 **개수까지** 남긴다
2. **도식(직접 작성)** — 표로 안 되는 구조·흐름. 🔴 **AI를 부르지 않는다**

   도식은 도형+텍스트라 **그림 실력이 필요 없다.** HTML로 그리면 API **0콜**이고 글자도 안 틀린다.

   ```js
   // ① 표로 안 되는 것만 HTML로 그린다 (대비·순서·구조·화면의 어느 지점)
   // ② 렌더 → Storage 영구 URL
   ext_render_html({ html, format: 'png' })
   //   → { file_urls: [...], storage_paths: [...], cloud_run_duration_ms: ~1700 }
   // ③ STEP 6에서 카드에 붙인다
   attach_blog_card_images({ notion_page_id, images: [{ marker, url: file_urls[0], caption }] })
   ```

   🔴 **넘기면 깨지는 것 둘 — 둘 다 실제로 막혔던 것이다(2026-08-15 실증).**

   1. **`tenant_id` 를 넣지 마라.** 넣으면 `tenant_mismatch` 로 **차단된다.**
      친절하게 채우는 게 오히려 깨뜨린다 — 토큰의 테넌트가 서버에서 자동으로 들어간다.
   2. **외부 `<link rel="stylesheet">` 는 로드되지 않는다.** CSS 를 `<style>` 로 **인라인해서** 넘겨라.
      (도구는 HTML 문자열 하나만 받는다. 옆 파일을 읽어 오지 못한다)

   ⚠️ `width`·`height` 는 **최종 픽셀을 정하지 못한다.** 2240 을 줘도 1120 을 줘도 결과가 같았다
   (서버가 `deviceScaleFactor: 2` 고정 + `fullPage` 캡처). **크기를 줄이려면 CSS 에서 `html{zoom:2}` 를 빼라.**

   📊 실측(2026-08-15, 이 경로로 직접 렌더): HTML **209KB·4480px** ↔ AI 생성 **1,100KB·1536px**.
   5배 가볍고 **해상도는 3배**다. 한글 폰트도 정상(Cloud Run 에 들어 있다).

3. **공공 캡쳐** — 공개된 통계·기관 자료만
4. **AI 생성** — 🔴 **위 셋이 다 없을 때만.** `ext_generate_image`

   그림 실력이 필요한 것(사진·일러스트·인물·분위기)만 여기로 온다. **도식은 2번이다.**
   ⚠️ 실사고(2026-08-15): 마미사 5편이 도식 10장을 HTML로 렌더해 놓고 **4분 뒤 같은 것을 AI로 다시** 만들었다.
   그때는 2번의 업로드 통로가 없었지만 **지금은 열려 있다**(`ext_render_html` external 개통).

> ℹ️ **URL 만료는 신경 쓰지 않아도 된다.** 노션 업로드 URL은 1시간이면 만료되지만,
> STEP 6의 `attach_blog_card_images`가 `rehost: true`(기본)로 **Storage 영구 URL로 재호스팅**한 뒤 삽입한다.

🔴 **`ext_generate_image` 반환은 base64가 통째로 온다 — 1.4M 문자로 컨텍스트를 날린다.**
반환이 "exceeds maximum allowed tokens"로 잘리면 **당황하지 말 것. 이미지는 이미 만들어졌다.**
저장된 파일에서 URL만 뽑아 쓴다:

```bash
grep -oE 'https://[a-z0-9.-]+/storage/v1/object/public/[^"]{10,200}\.(png|jpg|jpeg|webp)' "<저장된 경로>" | head -1
```

🔴 **`save_image_asset`을 부르지 않는다** — MCP에 노출되지 않은 내부 도구라 호출 자체가 불가능하다.
필요도 없다: `ext_generate_image`의 post-hook이 **이미 `content_asset`에 자동 등록**한다.

## STEP 6 — 노션 카드

1. `create_blog_card({ markdown, title, partner, content_type, keywords, english_slug })` → 단계 **6(초안_관리자컨펌중)** 으로 생성
2. `attach_blog_card_images({ notion_page_id, images: [{ marker, url, caption }] })` → 마커 자리에 이미지 삽입 + 마커 제거

**마커가 하나라도 남으면 발행이 차단된다.** 첨부 후 `markers_removed`가 이미지 수와 같은지 확인한다.

### 🔴 표는 파이프 표로 넘긴다 — `<table>` 태그로 넘기면 평문으로 박힌다

`create_blog_card`가 노션 표 블록으로 바꿔주는 것은 **마크다운 파이프 표**뿐이다.

```markdown
| 구분 | 값 |
| --- | --- |
| 기본 | 연 1회 |
```

`<table header-row="true">…</table>`을 넣으면 **에러가 안 난다.** 대신 태그가 통째로 이스케이프된
텍스트 덩어리(`\<table header-row="true"\> \<tr\>\<td\>…`)로 본문에 박힌다. 발행되면 그 자리가 깨져 나간다.

**왜 헷갈리나 — 두 도구의 표 문법이 반대다.** `notion-fetch`는 표를 `<table>`로 **출력**하므로,
기존 카드를 읽어 형식을 흉내 내면 그 출력 형식을 그대로 입력에 쓰게 된다.

| 도구 | 받는 표 문법 |
|---|---|
| `create_blog_card` (제디) | 마크다운 파이프 표 |
| `notion-update-page` (노션 MCP) | `<table header-row="true">` + 탭 들여쓴 `<tr><td>` |

✅ **반환값의 `table_count`가 원고의 표 개수와 같은지 본다.** 이 한 줄이 유일한 게이트다 —
안 보면 `ok: true`와 `block_count: 62`만 보고 정상이라 판단하게 된다(2026-08-14 댕묘 실사고).

이미 만든 카드는 `update_content` **부분 교체**로 `<table>` 문법을 넣어 고친다.
`replace_content`로 본문을 통째로 갈지 말 것 — 이미지 마커까지 재생성되며 다른 사고가 난다.

🔴 **`english_slug`는 홈페이지 블로그면 반드시 넘긴다** — STEP 2의 15번 칸 값이다. 안 넘기면 노션 칸이 비고, **한국어 제목은 크론 발행이 그 자리에서 멈춘다**(`need_english_slug`). 잘못된 값은 카드를 만들기 전에 거부되므로(`invalid_english_slug` / `english_slug_has_number`) 반환값을 보고 고쳐 다시 부른다. 반환의 `english_slug`가 **실제 저장된 값**이다(정규화됨).

### 날짜 칸 — 도구가 채운다. 사람은 「채워졌는지」만 확인한다

🔴 **오늘 날짜부터 확인한다.** `date "+%Y-%m-%d %H:%M"` 를 찍고 그 값을 쓴다. 추측하지 않는다 —
세션이 길어지면 **작업 중에 날짜가 넘어간다**(실측 2026-08-09: 자정을 넘겨 진행한 새벽 작업에서 발생).

| 칸 | 값 형식 | 누가 채우나 |
|---|---|---|
| `연` | `2026년` | **도구 자동** — `create_blog_card`, 작성일(KST) 기준 |
| `월` | `26년 8월` | **도구 자동** — 〃 |
| `예상 발행일` | 날짜 **+ 시각** | **도구** — `schedule_publish` (STEP 7 예약 경로). 손으로 채우면 시각이 빠져 새벽 0시에 나간다 |
| `실 발행일` | 발행한 날(KST) | **도구 자동** — 발행 파이프라인 |

- ✅ **`create_blog_card` 반환값의 `year`·`month` 를 본다.** 값이 들어 있으면 끝이다. 손댈 것 없다
- 🔴 **`date_notes` 가 있을 때만 손으로 채운다** — 노션 옵션에 그 이름이 없다는 뜻이고 사유가 그대로 적혀 있다(예: 해가 바뀌었는데 `2027년` 옵션 미생성). 이때는 **노션에서 옵션을 먼저 만든 뒤** 채운다
- 🔴 **왜 자동으로 바꿨나** — 이 문서로 세 번 강화했는데도 **8월 생성분 22건이 `연` 공란**이었다. `월` 이름에 연도가 이미 들어 있어(`26년 8월`) 사람이 `연`을 「다 됐다」고 여기고 건너뛴다. 라이브도 정상이고 에러도 0이라 **월별 뷰에서 사라진 걸 아무도 모른다.** 문서는 게이트가 아니다
- 🔴 **`월` 선택지에 옛 계열이 섞여 있다** — `8월` · `8월 기획안` · `25년 8월` · `26년 8월` 이 함께 있다. 손으로 채울 일이 생기면 반드시 `NN년 N월` 형식을 고른다
- ⚠️ **서버는 UTC, 우리는 KST** — 도구는 KST로 찍는다(v7.1080.0~). 그 전에 나간 글은 **KST 00~09시 발행분이 하루 앞으로 기록돼 있다**(실측 27%). 옛 카드 날짜가 하루 어긋나 보이면 이 때문이고, **소급 수정하지 않는다**(고치면 본문이 바뀐 것으로 판정돼 재발행된다)
- ⚠️ **`실 발행일` ≠ `예상 발행일`** — 발행이 밀리면 둘이 다르다. 예상일을 그대로 복사하지 말 것
- ⚠️ 아직 발행하지 않은 카드(네이버 재가공 등)는 **`실 발행일`을 비워 두는 것이 정상**이다

**발행 전 마지막 확인 1줄** — 단계 7로 올리기 직전, 그 카드의 `연`·`월` 이 채워져 있는지 본다. 비어 있으면 채우고 올린다(발행 후에는 월별 뷰에서 빠진 것을 알아채기 어렵다).
### 🔴 만든 것으로 끝이 아니다 — 올라간 것을 되읽어 대조한다

카드를 만들었다고 **원고가 그대로 올라간 것이 아니다.** 실측 사고(2026-08-09 RPG 재가공): 로컬 원고에는 오타가 0개인데 **노션 카드 본문에 한글 오타가 11개** 생겼다(12편 0 / 13편 8 / 14편 3). 카드는 이미 `8. 타이핑 요청` 단계였고 사람은 카드 본문을 그대로 복사해 올리므로, **사장님이 확인을 시키지 않았으면 그대로 발행됐다.**

🔴 **사람 눈으로 세지 않는다.** 이 세션에서 이미 실패했다 — 12편을 훑고 "정상"이라 판단한 뒤 13편에서야 발견했다. **코드가 센다.**

```bash
# 1) 카드 본문을 되읽어 파일로 저장 (notion-fetch 결과의 <content> 부분을 그대로)
# 2) 원고와 대조
python plugins/zulgap-pack/skills/zulgap-blog/scripts/check-notion-card.py <원고.md> <카드본문.txt>
```

무엇을 세나 — **틀어진 글자**(문장을 양쪽 인용 + 바뀐 글자 표시) · **이미지 수** · **해시태그 수**.

- ✅ **PASS면 그대로 진행**한다
- 🔴 **FAIL이면 `update_content` 부분 교체로만 고친다.** `replace_content`로 본문을 통째로 갈면 이미지·표 블록이 재생성되며 **다른 사고가 난다**
- ⚠️ 「카드에만 있는 문장」 경고는 재가공 내역·검수 결과처럼 **카드에만 붙이는 섹션**이면 정상이다
- ⚠️ **홈페이지 흐름에서는 이미지 캡션이 전부 이 경고로 뜬다** — 원고에는 마커(`img 1`)가 있고 카드에는
  캡션이 있으니 당연히 「카드에만 있는 문장」이다. **FAIL이 아니라 경고**이고, 정상이다

🔴 **`FAIL 글자가 틀어진 문장` 이 이미지 자리 근처에서만 나오면 스크립트를 의심하기 전에 버전을 본다** —
2026-08-14 이전 판은 이 흐름에서 **항상 FAIL 7건쯤을 냈다.** 원고를 문장으로 자르기 전에 줄바꿈을
공백으로 뭉개는 바람에, 마침표로 안 끝나는 줄(제목·이미지 자리)이 **다음 문장에 들러붙어**
멀쩡한 문장이 「틀어졌다」로 잡혔다. 고쳐졌고 회귀 테스트(`--selftest` T5)가 지킨다.

```
원고: img 1 The short answer, and why it is no longer one line There is no tipping in Korea.
카드: Diagram: Jeong, Korea The short answer, and why it is no longer one line There is no tipping in Korea.
      ^^^^^^^^^^^^^^^^^^^^ 이 앞부분만 다른데 문장 전체가 오타로 잡혔다
```

⚠️ **오탐이 반복되면 사람이 검사를 안 믿게 된다** — 그게 이 검사가 막으려던 사고(카드 본문 오타 11건)를
다시 부른다. 오탐은 「불편」이 아니라 **검사 자체를 무력화하는 것**이라 갭으로 올린다.

> **원인은 미상이다.** 12편(단독 호출) 0개 / 13·14편(2장 동시 호출) 11개라 「동시 호출」이 의심되지만 표본이 3편뿐이고, 오타 형태가 전부 **한글 자모 하나가 바뀐 것**(`나뉜니다`·`낙개`·`왜복`·`퐕니다`)이라 글자를 만드는 쪽의 확률적 오류로 보인다. 지어내지 않는다 — **대조는 원인이 무엇이든 잡으므로** 원인 규명을 기다리지 않는다.
> ⚠️ **캡션도 대조 대상이다** — 실사고의 `나뉜니다`가 이미지 캡션에 있었다. 캡션을 빼고 검사하면 그 오타를 원리적으로 못 잡는다(실전 검증에서 7곳 중 2곳을 놓쳤다).

## STEP 7 — 발행 (사람이 확정할 때만)

카드 링크와 요약을 보여주고 **"지금 낼까요, 날짜를 잡을까요?"** 묻는다. 세 갈래다.

| 대답 | 무엇을 하나 |
|---|---|
| **지금** | `publish_blog_card_now` → 즉시 발행 (아래 § 즉시 발행) |
| **날짜·시각을 말함** | `schedule_publish` → 예약 (아래 § 예약 발행) |
| **아직** | 아무것도 하지 않는다. 카드는 단계 6에 남는다 |

🔴 **묻지 않고 어느 쪽도 실행하지 않는다.** 동료사 홈페이지에 공개되는 행위다.

---

### 예약 발행 — 🔴 두 단계다. 하나만 하면 영원히 안 나간다

| # | 무엇 | 누가 |
|---|---|---|
| 1 | 「예상 발행일」에 **날짜+시각** 기입 | **도구** `schedule_publish` |
| 2 | 단계를 **`7. 초안_관리자컨펌완료`** 로 올려 예약을 완결 | **도구** — 단 **사람이 승인했을 때만** `promote: true` |

발행 크론이 보는 조건은 **단계 7 + 콘텐츠 구분 `홈페이지 블로그` + 등록 동료사**다.
🔴 **1만 하고 끝내면 카드는 단계 6에 남고 크론이 그 카드를 원리적으로 보지 않는다** —
시각은 노션에 예쁘게 적혀 있고, 에러도 0이고, 그 날짜가 지나도 **아무 일이 일어나지 않는다.**

#### 🔴 승인 없이 `promote` 를 켜지 않는다

2단계가 **도구로 옮겨졌다**(2026-08-14 · 서버 PR #2906). 사람이 노션에 들어가 칸을 바꾸던 손일이
없어진 것이지, **승인이 없어진 것이 아니다.** 승인 지점이 「노션 칸」에서 **「카드·이미지를 보고
발행을 허락하는 말」**로 옮겨졌다 — 그 말이 없으면 `promote` 는 켜지 않는다.

| 순서 | 무엇 |
|---|---|
| 1 | **카드 링크와 이미지를 먼저 보여준다** |
| 2 | **"이대로 낼까요?"** 를 묻는다 |
| 3 | 담당자가 **"네" · "발행" · "이대로 내주세요"** 라고 답한 경우에만 `promote: true` |
| 4 | `approval_note` 에 **그 사람이 한 말을 그대로** 인용한다 |

🔴 **금지 — 이것들은 승인이 아니다**

- *"오늘 무조건 나가야 한다"* · *"마감이다"* · *"빨리 해야 한다"* → **마감 압박은 승인이 아니다**
  (실사고 2026-08-13: 마감을 승인으로 읽고 확인 없이 **3편을 발행**했다)
- 담당자가 *"내가 7단계로 올릴게요"* 라고 말했으면 **기다린다** — 대신 올려 주는 것이 친절이 아니다
- `approval_note` 를 **지어내지 말 것.** 사람이 실제로 한 말이 없으면 **비워 둔다**
  (그 자리가 `null` 로 남아야 「근거 미기록」이 보인다 — 그럴듯한 문장을 채우면 그 신호가 죽는다)

| 통로 | 실제 상태 |
|---|---|
| `schedule_publish({ promote: true })` | ✅ **공식 통로** — 본문 검사를 통과한 카드만 승격 (2026-08-14 신설) |
| `publish_blog_card_now` (제디) | 🔒 올리는 순간 **즉시 발행**한다 — 예약이 아니다 |
| `ext_notion_update_page` (제디) | 🔒 단계 7 이상 승격을 **차단**한다 |
| `notion-update-page` (노션 MCP) | ⚠️ 기술적으로 안 막혀 있으나 **쓰지 않는다** — 아래 참조 |

🔴 **노션 MCP 로 「단계」를 직접 쓰지 말 것.** 그 길은 우리 코드가 아니라 막을 수 없고, 통과해도
**본문 검사·시각 검증·승인 기록이 전부 건너뛰어진다.** 실측(2026-08-14 새벽): AI 가
`notion-update-page({command:'update_properties', properties:{단계:'7. 초안_관리자컨펌완료'}})` 로 승격했고
오류 없이 통과해 09:00 에 발행됐다 — **막지 못한다는 것이 곧 써도 된다는 뜻이 아니다.**
공식 통로가 생겼으므로 이 우회는 이제 «편법»이 아니라 **검사를 건너뛰는 행위**다.

**호출**

```js
// 예약만 (아직 승인 전 — 기본값)
schedule_publish({ cards: ["<노션 페이지 ID>"], times: ["2026-08-14 09:00"] })

// 여러 편을 일정 간격으로 (배열 순서 = 발행 순서)
schedule_publish({ cards: [id1, id2, id3], first: "2026-08-14 09:00", interval_hours: 2 })

// 승인받았을 때 — 예약 + 승격을 한 번에
schedule_publish({
  cards: [id1, id2], first: "2026-08-14 09:00", interval_hours: 2,
  promote: true,
  approval_note: "확인했어요, 이대로 내주세요",   // 담당자가 한 말 그대로
})

// 승격만 재시도 (원고를 고친 뒤 — 시각은 이미 들어가 있다)
schedule_publish({ cards: [id1], promote: true, approval_note: "이미지 다시 봤습니다, 진행하세요" })
```

**승격이 막히는 경우** — `blocked[]` 에 사유가 담겨 온다. 셋 다 **막은 것이 맞다**

| 사유 | 왜 막나 | 어떻게 푸나 |
|---|---|---|
| 본문 게이트(`empty_body`·`typing_directives`·이미지 마커 잔존) | 미완성 원고가 나간다 | 원고를 고치고 **시각 없이 `promote` 만** 주고 다시 부른다 |
| 「예상 발행일」이 **비어 있음** | 승격하면 크론이 **즉시 발행**한다 | 시각을 **함께** 주고 부른다 |
| 「예상 발행일」이 **이미 지남** | 같은 이유로 즉시 발행된다 | **새 시각**을 주고 부른다 |

**하드리밋**

| 규칙 | 어기면 |
|---|---|
| `times` 와 `first`/`interval_hours` 를 **같이 주지 않는다** | `conflicting_schedule` |
| `times` 는 `cards` 와 **개수·순서가 같아야** 한다 | `times_length_mismatch` |
| 과거 시각을 넣지 않는다 | `past_time` — 지금 내보내려면 `publish_blog_card_now` |
| `interval_hours` 는 **0.5 단위 · 최대 168**(1주) | `invalid_interval` |
| 한 번에 **최대 50장** | `too_many_cards` |
| 같은 카드를 두 번 넣지 않는다 | `duplicate_cards` |

- 한 장이라도 계산이 틀리면 **아무것도 쓰지 않는다**(전량 사전검사) — 절반만 들어가는 일은 없다
- 🔴 **시각을 반드시 붙인다.** 날짜만 넣으면 크론이 그날 **KST 00:00** 으로 읽어 **새벽 0시 4분**에
  나간다. 블로그 발행 시각으로 못 쓴다. 사람이 시각을 안 말하면 **09:00 을 제안하고 확인받는다**
- ⚠️ **네이버블로그 카드에는 시각을 넣지 않는다.** 크론이 `홈페이지 블로그` **정확일치**로만 보므로
  네이버는 원리적으로 자동 발행되지 않는다 — 시각이 적혀 있으면 「자동으로 나갔겠지」 오해로
  사람이 안 올려 **그날 발행이 0** 이 된다 (`zulgap-scheduling` v1.7 과 같은 규칙)

**예약 뒤 반드시 남긴다** — 승인 전인지 완결인지가 한눈에 보여야 한다

승인 전(`promote` 미지정):

> 「예상 발행일」에 **8/14(목) 09:00** 을 넣었습니다. **지금은 단계 6이라 대기 상태입니다.**
> 카드와 이미지를 보시고 **"이대로 내주세요"** 라고 하시면 단계 7로 올려 예약을 완결합니다.
> 🔴 올리지 않으면 그 시각이 지나도 **아무 일이 일어나지 않습니다.**

승인 후(`promote: true`):

> 「예상 발행일」 **8/14(목) 09:00** · **단계 7 승격 완료** — 그 시각에 자동으로 나갑니다.
> 승인 근거: *"확인했어요, 이대로 내주세요"*

**셀프체크 — 「예약했습니다」라고 말하기 전에 5개 다 예인가**

- [ ] 반환의 `scheduled` 에 그 카드가 있고 `failed` 가 비었나
- [ ] 넣은 시각에 **시·분이 있나** (날짜만이면 새벽 0시에 나간다)
- [ ] 홈페이지 블로그 카드인가 (네이버면 시각을 넣으면 안 된다)
- [ ] 🔴 `promote: true` 를 켰다면 — **담당자가 카드를 보고 승인하는 말을 실제로 했나**
      (마감 압박·재촉은 승인이 아니다. 없으면 켜지 않는다)
- [ ] 반환의 **`promoted` 와 `blocked` 를 둘 다 봤나** — 메시지가 「N편 예약 / M편 승격 / K편 승격 보류」로
      나뉘어 온다. **`blocked` 를 안 보면 「예약됐다」고 보고하는데 실제로는 안 나간다**
      (보류분은 원고를 고친 뒤 **시각 없이 `promote` 만** 주고 다시 부른다)

> 여러 편을 **월 단위로 한꺼번에** 배치하는 것은 이 스킬이 아니라 `zulgap-scheduling` 이다
> (평일·공휴일 계산과 채널별 자동/수동 판정을 스크립트가 한다). 이 STEP 은 **방금 쓴 글 1편**을
> 언제 낼지 정하는 자리다.

### 즉시 발행

승인받으면 `publish_blog_card_now({ notion_page_id, slug })`.

- 이것은 **즉시 발행** 통로다. 예약 경로의 승격은 `schedule_publish({ promote: true })` 가 한다 — 둘 다 본문 검사(빈 본문·지시문·이미지 마커 잔존)를 통과해야만 단계 7로 올라간다. 차이는 **지금 나가느냐(이쪽) / 정한 시각에 나가느냐(저쪽)** 뿐이다.
- `status: 'blocked'`가 오면 **우회하지 말고** 사유를 보여주고 원고를 고친다.
- 발행 실패 시 자동으로 단계 6으로 롤백된다.

### 🔴 호출로 끝이 아니다 — 라이브와 노션을 둘 다 센다

**도구 반환값이 곧 결과가 아니다.** 실측(2026-08-09) 세 편에서 전부 어긋났다.

| 도구가 준 것 | 실제 |
|---|---|
| `ok:false · status:pending_deploy · reason:not_created` | 라이브 **이미 200** |
| MCP `502 Application failed to respond` | **발행 성공** — 응답만 끊겼다 |

🔴 **502·타임아웃에서 재호출하지 말 것.** 서버는 이미 끝냈을 수 있다 — 확인 없이 재시도하면 **중복 발행**이다. 먼저 라이브 URL을 찍어 본다.

**발행 호출 뒤 두 축을 반드시 센다.**

1. **라이브** — `curl -s -o /dev/null -w "%{http_code}" -L <URL>` 이 **200**인가
2. **노션 역기록** — 그 카드의 `단계`=`11. 발행완료` · `발행 링크` · `월`·`연` · `실 발행일`이 채워졌나

라이브가 200인데 노션이 비어 있으면 **직접 채운다.** 이건 발행 트리거가 아니라 **이미 일어난 일의 기록**이다. 도구가 「15분 내 자동으로 다시 확인한다」고 답해도 **믿지 말 것** — 실측에서 **2시간 뒤에도 단계 7**에 머물러 있었다.

### 왜 이 전제가 깨졌나 — 다른 도구에도 같은 클래스가 있다

깨진 전제는 **「도구가 성공을 반환하면 그 일이 끝났고, 실패를 반환하면 안 일어났다」**였다. 세 갈래로 깨진다.

| 깨지는 지점 | 이번 사례 | 왜 |
|---|---|---|
| **판정 계층이 다르다** | `not_created` 인데 라이브 200 | 도구는 자기 확인 경로를 보고 판정하는데 **실제 공개 여부는 배포·CDN 이 정한다.** 둘 사이에 시차가 있다 |
| **응답 실패 ≠ 작업 실패** | 502 인데 발행 성공 | 서버가 일을 마쳐도 **응답이 못 돌아오면** 호출자는 실패로 본다 |
| **「나중에 자동으로」는 아무도 안 센다** | 15분 재확인이 2시간 뒤에도 미이행 | 그 시각엔 세션이 다른 일을 하고 있다. **약속의 이행을 확인하는 주체가 없다** |

**재발방지 원칙 — 되돌릴 수 없는 외부 행위 전부에 적용한다** (발행 · 메일 발송 · 계산서 발행 · 영상 업로드 …)

1. **반환값은 「호출 결과」지 「세상의 상태」가 아니다.** 상태는 **그 행위의 직접 효과**로 따로 센다 — 라이브 HTTP, 수신함, 목록 조회처럼 **도구 밖에서** 보이는 것
2. **실패처럼 보이면 재시도 전에 「이미 됐나」부터 센다.** 502·타임아웃·연결 끊김이 특히 그렇다 — 확인 없는 재시도는 **중복 실행**이다
3. **도구가 「나중에 자동으로 한다」고 하면 그건 완료가 아니라 확인 대상이다.** 그 자리에서 확인할 수 없으면 **무엇이 미확정인지 명시해 사람에게 남긴다**

🔴 **승인 없이 발행하지 않는다.** 동료사 홈페이지에 공개되는 행위다.

### 발행 가능한 곳

자동 발행은 **등록된 동료사 + 콘텐츠 구분** 조합에서만 된다(미등록 조합은 안전하게 거부된다 — 엉뚱한 사이트에 올라가느니 멈춘다).

🔴 **`list_publishable_cards`는 사이트 목록이 아니다** — **지금 발행을 기다리는 카드**(단계 7)만 보여준다.
대기 카드가 없으면 빈 목록이 오는데, 그건 "그 사이트가 안 열렸다"는 뜻이 **아니다**. 빈 목록을 보고
사이트가 막혔다고 판단하지 말 것(2026-08-04 실제로 이렇게 오해할 뻔했다).

발행이 되는지는 **`publish_blog_card_now`를 불러 보면 안다** — 미등록 조합이면 `unregistered_target`으로
안전하게 거부되고 카드는 단계 6으로 되돌아온다(잘못 올라가지 않는다).
거부되거나 `missing_token`이 뜨면 **직접 git·서버 설정을 건드리지 말고 사장님께 요청**한다
(사이트 추가는 repo·토큰이 필요한 작업이다).

## STEP 8 — 네이버 재가공 (홈페이지 발행 후, 같은 글을 네이버에도 올릴 때)

🔴 **본문을 그대로 복사하면 안 된다.** 중복 콘텐츠가 되면 구글 원본성 평가에서 **자체 도메인이 손해를 본다.**
네이버에 올릴 것은 *같은 사실을 다시 쓴 글*이지 같은 글이 아니다.

**언제** — 홈페이지 글이 발행된 뒤. 원문 URL이 있어야 본문 말미에 넣을 수 있으므로 **발행 전에는 하지 않는다.**

**누구에게** — 묻지 말고 **데이터로 판정한다.** 콘텐츠마스터에서 그 동료사의 네이버블로그 카드 수를 센다.

```sql
SELECT "동료사명", "콘텐츠 구분", COUNT(*) AS n
FROM "<STEP 7에서 쓰는 콘텐츠마스터 데이터소스>"
WHERE "동료사명" = '<동료사>' AND "콘텐츠 구분" = '네이버블로그'
GROUP BY "동료사명", "콘텐츠 구분"
```

| 결과 | 판정 |
|---|---|
| 네이버 카드 **1장 이상** | 두 채널 운영 — 홈페이지 발행 후 STEP 8을 **이어서 제안한다** |
| 네이버 0장 · 홈페이지 카드는 있음 | 홈페이지 전용 — STEP 8을 **건너뛴다**(묻지도 않는다) |
| 둘 다 0장 (신규 동료사) | 이력이 없다. **이때만** 사람에게 묻는다 |

🔴 **기억으로 판정하지 말 것.** 실측(2026-08-09) — 「어느 동료사는 네이버 전용」이라고 단정했다가
데이터에서 홈페이지·네이버 양쪽으로 나온 사례가 있다. 동료사 목록을 이 문서에 표로 박지 않는 이유도
같다 — 동료사가 늘거나 채널 운영이 바뀌면 박아 둔 표가 **조용히 틀린다.**

### 🔴 키워드를 네이버 축으로 다시 잰다 (가장 먼저)

홈페이지 키워드를 그대로 쓰지 않는다. `ext_golden_keyword`를 **`locale='ko'`** 로 다시 호출한다.
**채널이 다르면 판정이 뒤집힌다** — 실측(2026-08-08): 구글 축에서 LOW(23~28)로 진입 가능했던 세 주제가
네이버 축에서는 **전부 「발행량 100건+ 포화」**였다. 포화로 나오면 제목을 **지역·상황어를 붙인 롱테일**로 잡는다.

### 🔴 여러 편을 연달아 재가공할 때 — 첫 줄을 편끼리 대조한다 (2026-08-16 사고)

한 동료사의 밀린 글을 **여러 편 한 번에** 재가공하는 것이 보통이다. 그때 나는 사고가 따로 있다.

**실측** — 마미사 3편을 연달아 재가공했더니 첫 문장이 이렇게 됐다:

| | 첫 문장 |
|---|---|
| 1편 | **먼저 결론입니다.** 직접 유입이 크다고… |
| 2편 | **결론부터 적겠습니다.** 광고 성과가 안 읽히는 이유는… |
| 3편 | **먼저 결론입니다.** 이름을 고를 때 어감보다… |

**세 편이 개별로는 전부 검수를 통과했다.** 규격도 문체도 위반 0이었다.
그런데 나란히 놓으면 한 사람이 쓴 한 글처럼 보인다 — 읽는 사람에게는 그게 결함이다.

🔴 **도구는 이걸 못 잡는다.** 원고 1장을 입력받기 때문이다. **여러 편을 쥔 쪽이 대조해야 한다.**

**어떻게** — 편마다 `checks.ai_voice.metrics.opening.first_sentence` 를 받아 **표로 늘어놓는다.**
같거나 비슷하면 갭 9종(STEP 2)에서 **서로 다른 것**을 골라 다시 쓴다.

⚠️ **대개 새로 지어낼 필요가 없다.** 좋은 문장이 이미 본문에 있고 상투 도입구에 가려져 있는 경우가 많다 —
위 3편도 상투구 한 마디를 떼거나 문장 순서를 바꾸는 것으로 전부 해결됐다.

🔴 **없는 숫자를 후킹에 끌어오지 말 것.** 같은 사고에서 *"일곱에 하나"* 라는 수치를 2편 후킹에 넣으려던 안이 있었는데,
그 숫자는 **1편 본문의 것**이었다(세션 1,382 중 직접 201). 편을 오가며 고칠 때 가장 나기 쉬운 사고다 —
후킹에 숫자를 넣으려면 **그 편 본문에 그 숫자가 있는지 먼저 확인**한다.

### 하드리밋 (수치)

| 항목 | 값 |
|---|---|
| 표의 열 수 | **최대 3열** — 네이버 모바일에서 4열 이상은 잘린다 |
| 해시태그 | **정확히 10개** |
| FAQ | **3~4건** (원문보다 줄인다 — 본문과 겹치는 항목을 뺀다) |
| 마크다운 링크 | **0개** |

> ⚠️ **이 「0개」는 원고 기준이지 카드 기준이 아니다.** 노션이 `law.go.kr` 같은 **도메인 문자열을 자동으로 하이퍼링크로 바꾼다** — 원고에서 0개로 만들어도 카드에는 링크가 생긴다(2026-08-09 실물 확인). **규칙이 깨진 게 아니니 되돌리려 들지 말 것.** 영향도 없다 — 네이버 에디터는 하이퍼링크를 받는다.

### 금지 리터럴 — 결과물에 하나라도 있으면 실패다

- 원문 문단을 **그대로 옮긴 것** (수치·법조문·인용문은 예외 — 바꾸면 거짓이 된다)
- 마크다운 링크 `[텍스트](주소)` — 네이버 붙여넣기에서 깨진다. `기관명 — 주소` 텍스트로 바꾼다
  - ⚠️ **단 「참고 자료」 줄에는 주소를 아예 쓰지 않는다** — 아래 7번 참조. 본문과 규칙이 다르다
- **출처 없는 새 문장** — 재가공은 사실을 늘리는 작업이 아니다

### 해야 할 것

1. **문장을 다시 쓴다.** 사실·수치·출처는 원문과 동일하게 유지한다
2. **구성을 네이버 검색 의도에 맞춰 재배치한다.** 검색어가 묻는 답(결론·핵심 목록)을 앞으로 당긴다
3. **표를 3열 이하로 줄인다.** 빠진 열은 문장으로 흡수하고, 전체 표는 홈페이지 원문으로 넘긴다
4. **홈페이지 이미지를 전부 넣는다.** 절대 순서가 아니라 **그 이미지가 설명하는 내용 옆**에. 구성을 바꿨으면 이미지도 따라 움직인다
5. **본문 말미에 홈페이지 원문 URL을 넣는다.** 자체 도메인으로 넘기는 통로이자 **어느 쪽이 원본인지 알리는 신호**다
6. **해시태그 10개.** 앞 3~4개는 카드 「키워드」 속성값과 같게 맞춘다(순위체크가 읽는 값과 어긋나지 않게)
7. **참고 자료를 옮긴다.** 원문 하단의 출처를 본문 맨 끝 **해시태그 바로 앞**에 `### 참고 자료`로 넣는다

🔴 **7번은 실사고에서 나왔다.** 재가공 절차에 이 단계가 없어 2026-08-09 카드 3장이 **전부 출처 없이** 나갔고, 옆 검사기(`check-naver-repurpose.py`)는 **FAIL 0**을 찍었다 — 그쪽은 「베꼈나」를 보지 **「빠뜨렸나」를 안 보기** 때문이다. 이틀 뒤 붙여넣던 사람이 눈으로 발견했다. 법령·정부 통계 위에 선 글은 출처가 빠지면 근거가 통째로 사라진다.

**옮길 때 지키는 것 세 가지**

| 규칙 | 이유 |
|---|---|
| **주소를 쓰지 않는다** | 도메인을 한 글자라도 적으면 노션이 자동으로 링크로 바꾼다(2026-08-11 `law.go.kr`로 실측). `국가법령정보센터에서 조회`처럼 기관명으로 끝낸다 — 본문의 `기관명 — 주소` 규칙과 **여기만 다르다** |
| **표기 형식을 바꾼다** | 원문 줄을 그대로 옮기면 위 ①(원문 재사용)에 걸린다. 법령명·기관명·논문 제목은 바꾸면 거짓이 되므로 **형식만** 바꾼다 — 「」 씌우기, 학술지명 괄호로 묶기, 설명 문구 다시 쓰기 |
| **없는 출처를 지어내지 않는다** | 원문에 참고 자료가 없으면 옮길 것이 없는 것이다. 그대로 두고 원문 쪽을 고치도록 알린다 |

**자기 사이트 글 링크**(원문이 자기 다른 글을 인용한 것)는 5번의 홈페이지 안내 한 줄로 합쳐도 된다. 다만 합쳤으면 그 사실을 「재가공 내역」에 적는다 — 적지 않으면 다음 사람이 누락으로 보고 다시 넣는다.

### 카드 만들기

🔴 **`create_blog_card`는 「네이버블로그」를 못 만든다** — 등록값이 `홈페이지 블로그` / `유튜브 미드폼`뿐이라
`unknown_content_type`으로 거부된다. **노션 MCP로 직접 만든다**(그래야 단계·담당자도 한 번에 넣는다).

- `콘텐츠 구분` = `네이버블로그` (**띄어쓰기 없음**)
- 🔴 `단계` = **`8. 타이핑 요청`** — 네이버는 자동 발행 배선이 없어 **사람이 직접 옮겨 적는다.** 그 대기 자리가 이 단계다. 홈페이지 흐름의 `6. 초안_관리자컨펌중`을 그대로 쓰면 **아무도 집어가지 않는다**
  - 실측(2026-08-09): 네이버 카드 중 `8. 타이핑 요청` **15건** ↔ `6. 초안_관리자컨펌중` **0건**
- `타이핑 담당자`는 **비워 둬도 된다** — 실측 18건 중 12건이 미지정. 지정은 사람이 한다
- **`월`·`연`을 직접 채운다** — 안 넣으면 월별 뷰에서 빠진다

### 셀프체크 — 눈으로 세지 말고 도구를 돌린다

원고를 파일로 저장한 뒤 검사기를 돌린다. **FAIL 0이 아니면 카드를 만들지 않는다.**

```bash
python scripts/check-naver-repurpose.py <홈페이지원문.md> <네이버원고.md>
```

| 판정 | 기준 |
|---|---|
| ① 원문 문장 재사용 | **0건** (완전일치 + 90% 부분일치) |
| ② 표 최대 열 수 | 3열 이하 |
| ③ 마크다운 링크 | 0개 |
| ④ 이미지 | 1장 이상 |
| ⑤ 해시태그 | 정확히 10개 |
| ⑥ 본문 글자수 | 1,500~8,000자 |

①에 걸린 문장은 도구가 전부 인용해 주므로 그 문장만 다시 쓰면 된다.

**그다음, 참고 자료를 따로 판정한다. 이것도 FAIL 0이어야 카드를 만든다.**

```bash
python scripts/check-references.py <홈페이지원문.md> <네이버원고.md> \
       --internal-domain <자기 사이트 도메인> --internal-name <브랜드명>
python scripts/check-references.py --selftest    # 12건
```

| 판정 | 무엇을 보나 |
|---|---|
| `[NO-REFS]` | 네이버 원고에 참고 자료 섹션이 없다 (원문 목록을 그대로 찍어 준다) |
| `[MISSING-REFS]` | 외부 출처 개수가 모자라다 |
| `[URL-IN-REFS]` | 주소가 들어갔다 (노션 자동 링크) |
| `[COPIED-REFS]` | 원문 줄을 그대로(또는 90% 이상) 옮겼다 |
| `[REFS-AFTER-TAGS]` | 해시태그보다 뒤에 있다 |

🔴 **위 검사기를 통과시킨 «뒤에» 돌린다.** 참고 자료는 앞 검사를 통과한 다음에 넣는 일이 잦고, 사람은 PASS를 보면 손을 뗀다. `[COPIED-REFS]`가 ①과 같은 판정을 다시 보는 이유다.

⚠️ **`--internal-*`를 안 주면 자기 사이트 글까지 외부 출처로 세어 판정이 더 엄격해진다.** 틀리는 방향이 안전한 쪽이라 그대로 둬도 되지만, 자기 글 링크를 5번으로 합쳤다면 값을 주는 편이 오탐이 없다.

### 원문이 출처를 본문에 흩어 놓은 경우 — `[REFS-NOT-SECTIONED]`

이 검사기는 **「맨 아래 참고 자료 섹션」**을 센다. 그런데 출처를 **각 문단 끝에 한 줄씩** 다는 글이 있다.

🔴 **실측(2026-08-12) — 두 채널이 그 형식이고, 그 둘이 네이버 카드가 가장 많다.**

| 동료사 | 네이버 | 원문 형식 |
|---|---|---|
| RPG · 마미사 · 댕묘 | 20 · 65 · 24 | `## 참고 자료` 섹션 ✅ |
| **엔노블** | **221** | 본문 각 문단 끝에 `출처: …` **분산** |
| **검단가온** | **141** | 섹션 없음 (초안 규격도 주장 옆 인용구) |

그래서 **섹션이 없는데 본문에 `출처:` 표기가 있으면 통과시키지 않는다.** 「못 센다」를 「없다」로 흘려보내면 **아무것도 안 보면서 초록불**이 되기 때문이다. 실측: 엔노블 원문으로 돌리면 `exit=2`(승격 전에는 `exit=0`).

받았을 때 할 일은 둘 중 하나다.

1. **원문 하단에 `## 참고 자료`로 모은다** (권장 — 그래야 다음 편부터 자동으로 잡힌다)
2. 옮긴 출처를 **사람이 원문과 직접 대조한다**

⚠️ 「출처」가 콜론 없이 문장에 나오는 것(`출처를 밝히지 않은`)은 잡지 않는다 — 표기는 예외 없이 콜론이 따라온다.

🔴 **즉석 bash로 대신 세지 말 것.** 실측(2026-08-09) 결함 3종 — 같은 파일에서 위반을 **8건 → 5건**으로 다르게 셌고(문자수 임계가 흔들림), 해시태그 10개를 **17개**로 봤고(`##` 헤딩을 태그로 오인), 원문 재사용 1건을 **놓쳤다**(마침표 뒤 `**` 강조가 문장 경계를 가려 **위반인데 PASS**).

도구가 판정하지 않는 것 하나는 사람이 확인한다 — **키워드를 네이버 축(`locale='ko'`)으로 다시 쟀나.**

> 브랜드별 세부(썸네일 규격·네이버 카테고리·계정·편집 기준)는 그 브랜드 전용 스킬에 있다. 이 STEP은 **브랜드 무관 공통 규칙**이다.

### 🔴 썸네일은 «필수»다 — 카드에 반드시 넣는다 (2026-08-16 사장님 확정)

> **왜 이 절이 생겼나** — 위 한 줄이 *"브랜드 전용 스킬에 있다"* 고 **위임만 하고 손을 뗐다.**
> 그런데 **받는 쪽 절차에 그 단계가 없었다** — 댕묘만 썸네일이 붙고 검단가온·엔노블·마미사는 조용히 빠졌다.
> 도구가 없어서가 아니다. 동료사별 생성기는 **이미 다 있었고 아무도 부르지 않았다.**

**네이버는 대표 이미지를 «본문에 있는 그림 중에서만» 고른다.** 카드에 썸네일이 없으면
타이핑 도구가 만들어낼 수 없고, 검색결과에는 **본문 첫 도식**이 얼굴로 나간다.

#### 🔴 만드는 법 = **HTML → `ext_render_html`** (사장님 확정 2026-08-16)

도식과 **같은 경로**다(위 「시각물」 소싱 2번). 썸네일은 도형+글자라 그림 실력이 필요 없다.

```js
// 1080×1080 한 장. CSS 는 <style> 로 «인라인» (외부 stylesheet 는 로드되지 않는다)
ext_render_html({ html, format: 'png', width: 1080, height: 1080 })
//   → { file_urls: [...] }   ← Storage «영구» URL
```

🔴 **`tenant_id` 를 넣지 말 것** — 넣으면 `tenant_mismatch` 로 차단된다(토큰에서 자동으로 들어간다).

**왜 HTML인가** — 파이썬 생성기(`make_thumbnail.py`)가 동료사마다 있지만, 그건 **직원 PC에 Python + Pillow가 있어야** 돌고 (`No module named PIL` 함정이 스킬마다 적혀 있다) 결과가 **로컬 PNG**라 따로 올려야 한다.
`ext_render_html` 은 설치가 필요 없고 **Storage 영구 URL** 을 바로 준다 —
노션 업로드 URL의 **5분 만료** 문제가 애초에 생기지 않는다(2026-08-16 실측으로 데인 자리).

⚠️ **파이썬 생성기는 브랜드 «규격의 정본»으로 남는다** — 배경·색·서체·줄 수 규격은 거기에 실측으로 박혀 있다.
HTML 로 옮길 때 **그 값을 그대로 가져다 쓴다**(눈으로 새로 정하지 말 것).

| 동료사 | 규격 정본 | 줄 규격 |
|---|---|---|
| 댕묘 | `zulgap-dangmyo-naver/scripts/make_thumbnail.py` | 3줄 · **줄당 6자** |
| RPG | `zulgap-rpg-thumbnail` | 2줄 |
| 엔노블 | `zulgap-ennoble-thumbnail` | 2~3줄 |
| 검단가온 | `zulgap-gaon-thumbnail` | 4줄 이내 |

#### 카드에 넣는 법

```
## 썸네일 (1080 x 1080)
![](<ext_render_html 이 준 Storage URL>)
```

🔴 **헤딩만 만들고 `⬜ 미제작` 으로 두지 말 것** — 검사는 «그림이 있나»를 보므로 그대로 막힌다
(실측: RPG 16편 중 3편이 이 상태였다).

#### 빠뜨리면 어디서 잡히나

`zulgap-naver-typing` 의 `validateCard` 가 **차단**한다(경고 아님).
문서 규칙만으로는 안 지켜진 전례가 있어 **결정론 게이트가 SSOT**다.
급히 없이 내보내야 하면 사람이 `requireThumbnail: false` 를 **명시**해야 열린다 — 기본값은 막는 쪽이다.

**왜 짧아야 하나** — 네이버 검색결과는 썸네일을 **약 110px**로 줄여 보여준다.
줄 수·글자 수 규격은 그 축소를 견디기 위한 것이지 미적 취향이 아니다.

## 사이트 층 — 원고로는 알 수 없는 것 (검수에 안 뜬다)

애드센스 승인은 글 한 편이 아니라 **사이트 전체**를 본다. 아래는 `validate_blog_draft`가 **판정하지 않는다** — 원고에 그 정보가 없기 때문이다. 사람이 따로 확인한다.

- [ ] About / Contact 페이지 존재
- [ ] 개인정보처리방침
- [ ] 글 20편 이상
- [ ] 구글 색인 (`site:도메인` 으로 검색해 결과가 나오는지)
- [ ] `ads.txt` (승인 후 필요)

🔴 **이걸 원고 검수에 섞지 말 것.** 섞으면 글 하나 쓸 때마다 "About 페이지 없음"이 뜬다 — 고칠 수 없는 위반이 매번 뜨면 진짜 위반이 묻힌다.

⚠️ **병목은 보통 글 수가 아니라 색인이다.** 색인 0이면 글을 20편 써도 신청이 거절된다. 도메인 연결 후 색인까지 보통 2~4주가 걸리므로, 신청 시점은 **색인이 잡힌 뒤**로 잡는다.

| 함정 | 증상 |
|---|---|
| 영어 채널에 한국어 초안 | 통째로 재작성 — 1차부터 목표 언어로 |
| **키워드를 3개 이상 넘김** | 각 4~6회 규칙에 전부 걸려 위반 폭증 — 도구 추천 1~2개만 |
| **FAQ를 `**Q:** A:` 로 씀** | `faq_missing` — `### 질문` + 다음 줄 답변만 인정 |
| **`ext_generate_image` 반환 통째로 받기** | base64 1.4M 문자 → 컨텍스트 붕괴. **URL만 grep** |
| **`save_image_asset` 호출 시도** | MCP 미노출 도구라 호출 불가. 자동 등록되므로 불필요 |
| 마커 잔존 | 발행 게이트가 차단(`typing_directives`) |
| 검수를 직접 세기 | 실제와 다름 — `validate_blog_draft` 반환값만 근거 |
| **광고 위반을 사이트 층과 섞기** | 글마다 "About 없음"이 떠서 진짜 위반이 묻힘 — 사이트 층은 위 체크리스트로 |
| **영문 글 분량을 글자로 세기** | 2,000단어가 12,000자로 잡혀 초과처럼 보임 — 도구가 언어별로 잰다 |
| 동료사 미지정 시각물 조회 | 거부됨(교차 오염 방지) |
| `tenant_not_allowed` | 본인 토큰의 회사 자료만 조회된다. 다른 회사 자료가 필요하면 사장님께 요청 |
| **`outline` 없이 검수 호출** | 시각물 검사가 **통째로 skip**되는데 `violations: []`로 와서 통과처럼 보임 — `checks.visuals` 유무로 확인 |
| **이미지를 하한만 채움** | 표를 아무리 넣어도 **이미지는 따로 센다**. `min 5 · 권장 10~14` — 실측 사고 2건이 전부 이 패턴 |
| **도식 없이 사진으로만 채움** | 이미지의 **40% 이상이 도식**이어야 한다 — 미달이면 `diagram_ratio_low` 위반 |
| **자체 미디어를 `ext_search_partner_assets`로 조회** | `invalid_brand`가 **정상**(등록 목록은 동료사뿐). 에러로 보고 멈추지 말 것 |
| **네이버에 원고를 그대로 복사** | 중복 콘텐츠 — **자체 도메인이 원본성에서 손해**를 본다. STEP 8 재가공 필수 |
| **`create_blog_card`에 `<table>` 태그로 표를 넘김** | 에러 없이 태그가 **평문으로** 박힌다. `table_count: 0`만 조용히 나옴 — 파이프 표로 넘기고 `table_count`를 확인할 것 |
| **`create_blog_card`로 네이버 카드 생성** | `unknown_content_type` (등록값은 홈페이지 블로그/유튜브 미드폼뿐) — 노션 MCP로 직접 |
| **홈페이지 키워드를 네이버에 그대로 사용** | 채널이 다르면 판정이 뒤집힌다 — 구글 LOW가 네이버 포화. `locale='ko'`로 재측정 |
| **예약만 하고 카드를 단계 6에 둠** | 시각은 들어갔는데 **크론이 그 카드를 안 본다**. 에러 0·조용한 미발행 — 승인받았으면 `promote: true` 가 **짝**이다 |
| **승인 없이 `promote: true` 를 켬** | 되돌릴 수 있지만 **동료사 홈페이지에 공개된 뒤**다. 마감 압박은 승인이 아니다 (2026-08-13 실사고 3편) |
| **`blocked` 를 안 보고 「예약 완료」 보고** | 본문 검사에 걸린 카드는 단계 6에 남는다. 메시지가 「N편 예약 / M편 승격 / **K편 승격 보류**」로 나뉘어 오는데 앞만 읽으면 **안 나가는 줄 모른다** |
| **예약에 날짜만 넣음** | 크론이 KST 00:00으로 읽어 **새벽 0시 4분** 발행. 시각을 반드시 붙인다 |
| **네이버 카드에 발행 시각 기입** | 자동 발행이 안 되는 채널 — 「나갔겠지」 오해로 사람이 안 올려 **그날 발행 0** |

> 위 함정 중 **다수가 2026-07-29 첫 실전에서 나왔다.** 배선 검증(단위 테스트)으로는 하나도 안 잡혔다.

## 🔴 네이버블로그 카드는 «포맷 정본»을 따른다

채널이 **네이버블로그**면 원고를 쓰기 전에 이걸 읽는다:

```
plugins/zulgap-pack/shared/naver-format/FORMAT.md
```

포맷 규칙이 거기 **한 벌**로 있고 **발행 스킬이 같은 것을 본다.** 원소스 멀티유즈.

- 소제목은 `## 소제목` 또는 `**줄 전체 볼드**` → 발행이 **인용구**로 바꾼다 (🔴 `<h2>` 는 네이버에서 사라진다)
- 문단은 그냥 줄바꿈으로 나눈다 → 발행이 **여백**을 넣는다 (기존 글은 빈 문단이 56~61%)
- 표는 `<table header-row="true">` 그대로 → 발행이 **머리 색**을 입힌다
- 이미지는 넣을 **자리에** `![설명](주소)` → 발행이 그 순서대로 올린다.
  🔑 **어디에 넣을지는 「작성」의 판단이다** — 발행은 옮길 뿐 판단하지 않는다
- **밑줄은 쓰지 않는다** (기존 발행글 4편 모두 0개)

⚠️ 홈페이지 문법으로 쓰면 발행이 번역해야 하고, **번역 규칙이 늘수록 깨진다.**
