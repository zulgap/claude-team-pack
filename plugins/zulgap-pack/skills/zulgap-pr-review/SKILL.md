# PR 검토 — 팀팩 거버넌스 전용

> **`/review`(범용 코드 리뷰)와 축이 다르다.** 팀팩 PR은 대부분 **마크다운 문서**라 버그가 거의 없다.
> 진짜 위험은 **"이게 전 직원 PC에 어떻게 도달하고, 무엇을 같이 바꾸는가"** 다.
> 이 스킬의 체크리스트는 **2026-07-30에 실제로 터진 사고 7건**에서 그대로 나왔다.

## 입력

| 입력 | 예 |
|---|---|
| **PR 번호** (필수) | `/pr검토 65` · "PR 65 검토해줘" |
| repo (선택) | 기본 `zulgap/claude-team-pack`. 다르면 명시 |

번호 없이 부르면 → **열린 PR 목록을 먼저 보여주고** 고르게 한다. 추측해서 아무거나 열지 말 것.

```bash
gh pr list -R zulgap/claude-team-pack --state open --json number,title,author,additions,deletions
```

🔴 **열린 PR이 2개 이상이면** 고르기 전에 **§ 열린 PR이 2개 이상일 때**(문서 끝)로 먼저 가서 **겹치는 파일**을 확인한다. 각각 통과해도 합치면 깨질 수 있다.

## STEP 1 — 수집 (결정론, LLM 판단 0)

```bash
cd ~/claude-team-pack
git branch --show-current                # 지금 어디인지 기록 — 검토가 끝나면 여기로 돌아온다
git status --porcelain | grep -v '^??'   # 🔴 먼저 확인. 출력이 있으면 아래 checkout을 하지 말 것
git checkout main                        # 위가 비었을 때만. 검토는 main에서 한다
git fetch origin main --quiet
git rev-parse HEAD origin/main           # 두 줄이 같아야 로컬이 최신 (🔴 --short 붙이면 fatal — 다중 rev 불가)

gh pr view <N> --json number,title,author,body,files,additions,deletions,mergeable,isDraft
gh pr checks <N>
gh pr diff <N>

# 🔑 파일별 status(added/modified/removed/renamed) — ①②④ 판정의 기준. --json files엔 status가 없다
gh api repos/zulgap/claude-team-pack/pulls/<N>/files --jq '.[] | "\(.status)\t\(.filename)"'
```

⚠️ 클론이 두 벌 있다: `~/claude-team-pack`(정본) · `~/Documents/claude-team-pack`(뒤처져 있음). 위 `rev-parse` 두 줄이 다르면 **그 클론에서 나온 수치를 버리고** `git pull` 후 다시 시작한다.

⚠️ `gh` 명령은 **cwd의 repo**를 본다 — 다른 폴더에서 돌리면 조용히 **다른 레포**를 조회한다(실측: `~/.claude`에서 실행해 `zulgap/claude-config`로 404). 위 `cd`를 먼저 하거나 **`-R zulgap/claude-team-pack`을 붙일 것.**

🔴 **feature 브랜치에서 검토를 시작하지 말 것** — 방금 PR을 올린 브랜치에 서 있으면 `rev-parse` 두 줄이 **당연히** 다르고(실측: `4ea58cb` vs `6351190`), 위 클론 경고가 그걸 "stale 클론"으로 읽게 만든다. `git pull`을 해도 브랜치에 있는 한 영원히 안 맞는다. 그래서 `main`으로 옮겨 시작한다.

🔴 **순서가 중요하다 — `status`가 `checkout`보다 먼저다.** `git checkout main`은 변경된 파일이 **두 브랜치에서 내용이 같으면 `exit 0`으로 그 변경을 main 위에 얹어 옮긴다**(실측 — 거부하지 않는다). 그러면 ③의 로컬 게이트가 스스로 경고하는 *"PR도 main도 아닌 제3의 상태"* 를 **STEP 1이 직접 만든다.** 먼저 확인하고 깨끗할 때만 옮기면 그 창이 닫힌다.

🔴 **`git checkout main`이 실패하면(`exit 1` — 두 브랜치에서 그 파일 내용이 다를 때) 거기서 멈춰라.** 그대로 다음 줄을 실행하면 feature 브랜치에 남은 채 `rev-parse` 두 줄이 어긋나고, 위 클론 경고가 그걸 "stale 클론"으로 오판한다 — **없애려던 바로 그 오판이 재현되는데, 원인이 checkout 실패라 더 안 보인다.** 작업분을 커밋하거나 `git stash`한 뒤 다시 시작할 것.

⚠️ **검토가 끝나면 처음 기록한 브랜치로 돌아갈 것** — 이 스킬은 사용자를 `main`에 남겨두고 끝난다. 자기 작업 중이었다면 `git checkout <기록한 브랜치>` (+ stash했으면 `git stash pop`).

⚠️ **untracked(`?? `)는 무시한다** — 게이트는 **추적되는 파일만** 읽으므로 `mcp-bridge/package-lock.json` 같은 잔여 파일이 결과를 바꾸지 않는다. 그것만 남았으면 "깨끗함"으로 본다. (이 필터가 없으면 26일 전부터 있는 그 파일 하나 때문에 ③ 로컬 게이트 경로가 **영구 봉쇄**된다 — 실측)

🔴 **`gh pr diff`를 반드시 볼 것.** 제목·본문만 읽고 판정하면 **올린 사람이 쓴 설명을 그대로 믿는 것**이다.

## STEP 2 — 위험도 판정 (경로만 보고 **기계적으로**)

바뀐 파일 경로로 등급을 매긴다. **LLM이 "괜찮아 보인다"로 낮추지 말 것.**

| 등급 | 경로 | 왜 |
|---|---|---|
| 🔴 **최고** | `hooks/**` | 전 직원 PC에서 **권한 확인 없이 실행**된다. 서명·해시 검증 없음 |
| 🔴 **최고** | `install.ps1` · `install.sh` · `install.bat` · `install.command` · `install-dev.bat` | 설치 동작 자체. 잘못되면 신규 설치가 전부 깨짐 |
| 🔴 **최고** | `.claude-plugin/**` · `.github/workflows/**` · `.mcp.json` · **`scripts/check-plugin-consistency.js`** | 로드 경로·게이트. 여기가 틀어지면 **다른 검사가 전부 무의미**. 게이트 **본체**도 여기다 — 워크플로우를 깨는 것과 스크립트를 비우는 것은 효과가 같다 |
| 🔴 **최고** | **`^skills/**`** (루트 = `plugins/` 밖) | **죽은 경로.** 테스트·CI·git 전부 통과하는데 **아무에게도 안 간다**. 게이트는 이 자리를 **아예 스캔하지 않는다**(실측: `plugins/` 단일 진입점) → **사람만 잡을 수 있다** |
| 🟠 **높음** | `team-CLAUDE.md` · `team-CLAUDE-en.md` | 직원 **개인 파일**로 설치되고 **갱신 경로가 없다**(§즉시경고). 파급이 큰 만큼 등급도 올린다 |
| 🟠 **높음** | `plugins/*/skills/*/SKILL.md` | **스킬 본체 = 전원 영향.** 한 채널 요청이 다른 채널까지 바꾼다 |
| 🟠 **높음** | `scripts/**`(게이트 본체 제외 — 위 🔴) · `mcp-bridge/**` · 루트 `*.js`(`teampack-config.js` 등) | 실행 코드 |
| 🟠 **높음** | `plugins/*/skills/*/templates/**` | **산출물 모양을 실제로 결정**하는데 ③ 게이트가 **스캔하지 않는** 구역이다 |
| 🟠 **높음** | `plugins/*/skills/*/scripts/**` | 실행 코드. ⚠️ **Tier F-1이 스캔한다**(2026-08-03~) — OS 종속 경로 단일 계열이면 CI가 막는다. 초록이어도 로직은 사람이 봐야 함 |
| 🟠 **높음** | `plugins/*/skills/*/assets/**` | 번들 자산(폰트·템플릿 이미지). **폰트는 Tier F-2가 라이선스 사본 동봉을 강제**한다 — 레포가 public이라 **커밋이 곧 재배포**다. 라이선스 파일이 함께 들어왔는지 눈으로도 확인할 것 |
| 🟡 **중간** | `team-guide.md` · `docs/skill-packaging-spec.md` | 앞은 매 세션 전 직원 주입, 뒤는 **검토 기준 정본** — 이걸 고치면 *다음 검토의 잣대*가 바뀐다 |
| 🟢 **낮음** | `plugins/*/skills/*/channels/*.md` | **값 파일 = 그 채널만.** 모태 무영향. ⚠️ 단 **게이트 미스캔 구역**이라 A급은 사람이 봐야 한다(③) |
| 🟢 **낮음** | `CHANGELOG.md` · `README.md` · 그 외 `docs/**` · `plugins/*/skills/*/PROVENANCE.md` | 기록·설명. `PROVENANCE.md`는 정본이 **C급 리터럴의 지정 거처**로 규정한 파일. ⚠️ 여기도 **게이트 미스캔**이라 A급은 사람이 봐야 한다(실측: #60에서 노션 ID가 `PROVENANCE.md`→`SKILL.md`로 이동한 흔적이 있다) |

**우선순위 — 2단으로 적용한다**

1. **파일 하나가 여러 행에 걸리면 표에서 위쪽(더 높은) 행이 이긴다.** 예: `docs/skill-packaging-spec.md`는 마지막 행 `docs/**`(🟢)에도 걸리지만 **위쪽 🟡 행이 이긴다** (검토 기준 정본이므로). 실측상 이 규칙이 실제로 발화하는 파일은 현재 그 하나다
2. **한 PR에 여러 등급이 섞이면 가장 높은 것**이 그 PR의 등급이다

🔴 루트 판정은 **앵커된** grep으로 — 그냥 `grep skills/`면 `plugins/*/skills/**`(정상 경로 12개)이 전부 오탐된다:

```bash
gh api repos/zulgap/claude-team-pack/pulls/<N>/files \
  --jq '.[] | "\(.status) \(.filename) <= \(.previous_filename // "-")"' | grep -E " skills/"
```

🔴 **판정은 "들어가나 나오나"(방향)로 한다.** `renamed`는 `.filename`이 **새 경로**, `previous_filename`이 **옛 경로**다 — 이걸 안 보면 *살아있는 스킬을 죽은 자리로 옮기는 PR*이 수리분으로 오판된다.

🔴 **`^`(줄 시작) 앵커로 읽어라.** `renamed plugins/jedi-core/skills/… <= skills/…` 처럼 **새 경로 중간에도 `skills/`가 들어있다** — 부분문자열로 읽으면 수리분을 🔴로 오판한다. 판정 대상은 **경로가 `skills/`로 시작하는가**다.

| 나온 모양 | 뜻 | 등급 |
|---|---|---|
| `added ^skills/…` · `modified ^skills/…` | 그 자리에 **넣거나 살려둔다** | **🔴** |
| `renamed ^skills/… <= plugins/…` (**새** 경로가 루트 `skills/`로 시작) | 죽은 자리로 **옮긴다** | **🔴** |
| `removed ^skills/… <= -` · `renamed plugins/… <= ^skills/…` (**옛** 경로만 루트) | 그 자리를 **없앤다** = 수리분 | 🔴 아님 |

실측 대조 — #60은 `removed skills/…` 7건 + `renamed plugins/… <= skills/…` 2건이라 **전부 나오는 방향** → 🔴 아님. #59는 `added skills/…` 9건 → 🔴.

🔴 **표에 없는 경로가 나오면 🟠 높음으로 본다** (안전측 기본값). "새 폴더라 잘 모르겠으니 낮음"은 금지 — 모르는 자리일수록 위험하다.

⚠️ 표에 `*.md`(문서) 같은 **의미 판정 항목을 두지 않았다** — 이 STEP의 제목이 "경로만 보고 **기계적으로**"인데 "이게 문서인가"는 의미 판정이라 그 원칙을 스스로 깬다. 새 경로가 생기면 **glob으로 이 표에 추가**할 것.

### 🚨 즉시 경고 (등급과 무관하게 별도 표시)

- `team-CLAUDE.md` / `team-CLAUDE-en.md` 변경 → **개인 파일(`~/.claude/CLAUDE.md`)로 설치되는 것**이다. 갱신 경로가 없어 **기존 직원에겐 안 간다**(신규 설치자만). "고쳤으니 전달됐다"고 쓰면 **틀린 설명**이다
- `plugin.json` / `marketplace.json`에 `version` 필드 추가 → **CI가 막지만** 의도를 물을 것 (스킬 자동갱신 동결 사고 v1.17)
- 파일 **삭제**가 포함 → 무엇이 그 자리를 대신하는지 확인

🔴 **이 3개는 "표시"로 끝내지 말 것.** STEP 4 보고 표 **⑧행에 적고, 해당하면 최소 보류**다(승인 금지). 되돌리기가 어렵거나(삭제) 도달 자체가 안 되는(개인 파일) 축이라 **등급·CI와 별개로** 사람 확인이 필요하다. 표시만 하고 승인으로 넘기면 — 이 스킬이 잡으려는 바로 그 실패(검사는 했는데 판정에 안 닿음)를 스스로 저지르는 것이다.

## STEP 3 — 검토 ①~⑦ (+ ⑧ 즉시경고는 STEP 2에서 확인해 보고 표에 적는다)

### ① 어디에 넣었나 — **로드되는 자리인가**

🔴 **선행 질문 — 아래 둘 중 하나라도 해당하는가?**
- **(ㄱ)** `SKILL.md`를 **새로 추가(`added`)하거나 옮긴다(`renamed`)**
- **(ㄴ)** **루트 `skills/**` 아래 파일을 `added`·`modified`** 하거나 **거기로 `renamed`** 한다 — **파일 종류 무관**(`SKILL.md`가 아니어도 `channels/`·`scripts/`·`templates/` 뭐든)

- **둘 다 아니오** → `N/A + "스킬 파일 추가·이동 없음"`. **반려 트리거가 아니다.** `docs/`·`hooks/`·`.github/`·`scripts/`만 고치는 PR을 ①로 반려하는 것은 오판이다
- **하나라도 예** → 아래를 본다. ①은 **이 PR이 만드는 자리**를 따진다

🔴 **(ㄴ)가 왜 필요한가**: (ㄱ)만 두면 **이미 죽은 자리에 있는 파일을 `modified`만 하는 PR**(= 죽은 사본에 수리를 얹는 PR)이 게이팅을 빠져나가 ① 칸에 `N/A`가 적히고, 반려 트리거가 발화하지 않아 **승인까지 간다.** STEP 2는 그걸 🔴로 보므로 등급과 판정이 어긋난다 — 두 곳의 status 집합을 일부러 맞춰 뒀다.

```bash
# 1) 이 PR이 SKILL.md를 어떻게 건드렸나 — added/renamed 만 ①의 대상이다
gh api repos/zulgap/claude-team-pack/pulls/<N>/files --jq '.[] | "\(.status)\t\(.filename)"' | grep "SKILL.md$"

# 2) 로드 경로 선언은 PR head 기준으로 — PR이 배열을 함께 건드렸는지 먼저 본다
gh pr diff <N> | grep -B2 -A6 '"skills"'

# 3) 건드리지 않았으면 현행 배열이 기준
git show origin/main:./.claude-plugin/plugin.json | grep -A6 '"skills"'
```

⚠️ 3번 경로 앞의 **`./`를 빼면 안 된다** — Git Bash가 `origin/main:.claude-plugin/…`을 PATH 목록으로 오인해 `fatal: ambiguous argument`를 낸다(실측). 대안: `MSYS_NO_PATHCONV=1`.
🔴 **base(`origin/main`)만 보고 판정하지 말 것** — 새 팩을 만들면서 `plugin.json`에 그 팩을 함께 추가한 PR은 base엔 배열이 없으므로 **정상인데도 "죽은 경로"로 오판**된다.

새 스킬이면 **`plugins/<팩>/skills/` 아래 + `skills` 배열이 그 팩을 가리켜야** 한다. 둘 중 하나만 만족하면 도달하지 않는다.
🔴 **루트 `skills/`는 로드 경로가 아니다** — 테스트도 통과하고 git에도 있는데 **아무에게도 안 간다**(실사고 #59). 게이트는 `plugins/` 아래만 스캔하므로 **이 검사가 유일한 방어선이다.**

### ② 설정인가 스킬 본체인가

| | 판정 |
|---|---|
| `channels/*.md` | **설정** — 그 채널만. 가볍게 봐도 됨 (단 ③의 A급은 사람이 봐야 함 — 게이트 미스캔) |
| `SKILL.md` 본문 | 🟠 **본체 — 전원 영향.** *"○○ 채널 요청인데 본체를 고쳤다"*면 **다른 채널에 미치는 영향을 반드시 적을 것** |

**본체 변경인데 PR 설명에 "○○ 채널용"이라고만 쓰여 있으면 → 반려 사유**다. 올린 사람이 영향 범위를 모르고 있다는 뜻이다.

### ③ 회사 정보가 들어갔나 — **자동검사에 구멍이 있다**

🔴 **게이트는 파일이 2개다.** 하나만 보고 판정하지 말 것:

| 파일 | 범위 | 로컬 실행 |
|---|---|---|
| `scripts/check-plugin-consistency.js` | **Tier A~I** (아래 표) | ✅ 가능 |
| `scripts/check-skill-ownership.js` | **소유권** (남의 스킬 = 소유자 승인 필요) | ❌ **CI 전용** — *"로컬에서는 PR 컨텍스트가 없어 판정이 성립하지 않으므로 안내 후 통과"*(스크립트 주석) |

→ **로컬 `exit=0`은 소유권에 관해 아무것도 증명하지 않는다.** 그 축의 유일한 근거는 CI `ownership` 체크다(⑤).

`check-plugin-consistency.js`가 **실제로 보는 범위** — 전부 실측 확인:

| 대상 | 검사됨 | 비고 |
|---|---|---|
| `plugins/*/skills/*/SKILL.md` **본문** | ✅ | **Tier C·D·E·G·I의 대상** (같은 `skillFiles` 배열 공유) |
| A급 리터럴 | ⚠️ **`tier: shared`일 때만 FAIL** | `tier: tenant-only`는 탐지·집계만 하고 **exit 0** (경보 피로 방지, 의도된 설계) |
| `tier` 미선언 | ✅ FAIL | |
| **`scripts/**` 코드**(`.js`·`.mjs`·`.cjs`·`.py`·`.ps1`·`.sh`) | ✅ **Tier F-1이 본다** | 2026-08-03 신설. OS 종속 경로가 **단일 계열뿐**이면 FAIL(대안 없음 = 다른 OS에서 즉사). 실행 검증함 |
| **번들 폰트**(`.ttf`·`.otf`·`.ttc`·`.woff`) | ✅ **Tier F-2가 본다** | 같은 폴더에 라이선스 사본(`OFL`/`LICENSE`/`NOTICE`) 없으면 FAIL. 레포가 public = 커밋이 곧 재배포 |
| `team-CLAUDE.md` / `-en.md` | ✅ **Tier H가 본다** | 갱신 안 가는 stub에 「N시간마다」류 **낡을 값** 0건 |
| `channels/*.md` · `templates/*` | ❌ **미스캔** | 아이러니: FAIL 메시지가 *"값은 채널 파일로"* 라고 안내하는데 **그 채널 파일이 사각지대** |
| 루트 `skills/**` | ❌ **미스캔** | 진입점이 `plugins/` 하나뿐 — **파일 존재조차 모른다**(실측: 위반 파일을 넣어도 개수 불변, exit 0) |
| **B급**(회사·브랜드·채널명·담당자 실명·색상 지정) | ❌ **정규식 0개** | 사람만 잡을 수 있다 |

🔴 따라서 **"CI 초록"이 회사정보에 관해 증명하는 것은 "`plugins/` 아래 `tier: shared` SKILL.md 본문의 A급 0건" 뿐이다.** 그 밖은 아무도 안 봤다 — 보고에 *"CI 초록이라 회사정보 없음"* 이라고 쓰면 **틀린 진술**이다.

⚠️ 다만 초록은 **회사정보 외의 것도** 증명한다 — `tier` 값과 무관하게 전수 검사되는 축: **C**(이름 규격·명령 충돌) · **E**(형제 폴더명 하드코딩 0) · **F**(이식성·폰트 라이선스) · **G**(되돌릴 수 없는 도구 호출 지시 0) · **H**(stub 신선도) · **I**(상속 선언·부모 변경 반영). 즉 ③에서 손으로 다시 볼 축은 **B급 + 미스캔 구역(`channels/`·`templates/`·루트 `skills/`)의 A급**이다.

⚠️ **`make-skill`의 *"자동검사는 SKILL.md만 읽는다"* 는 낡은 문장이다** — Tier F가 2026-08-03에 뒤집었다(위 표). 그 문장을 근거로 *"scripts/는 사람이 봐야 한다"* 고 적힌 PR 설명을 그대로 믿지 말 것.

**B급은 사람이 본다** (`tier: shared`인데 들어왔으면 값 파일로 내려야 함):

```bash
gh pr diff <N> | grep -E "^\+" | grep -inE "줄갭|엔노블|검단가온|노블냥|정코리아|마미사"
```

⚠️ 이 grep은 **브랜드명만** 잡는다. B급의 나머지 절반 — **담당자 실명 · 브랜드 색상 지정 · 특정 회사 운영 규칙** — 은 패턴이 없어 **눈으로 읽어야** 한다 (아래 ✅good 예시의 *"금색→흰색"*·*"나래님 채널"*이 정확히 그 사각지대다).
⚠️ 기존 B급이 **파일 간 이동**한 것도 `+`로 잡힌다 → **신규 유입인지 이동인지** 확인 후 판정. 정의·설명문에 등장한 브랜드명(정본의 등급 표 등)은 오탐이다.

- `tier: shared` + B급 **신규** 추가 → **반려** (값 파일로 내려야 함)
- `tier: tenant-only` + B급 → 정상 (그 회사 전용)

**A급은 게이트가 안 보는 구역까지 직접 본다** (채널 파일·루트 `skills/`·tenant-only 포함). 🔴 **한 줄에 섞지 말고 두 명령으로 나눈다** — 백슬래시가 셸 인용 방식에 따라 다르게 해석돼 같은 PR이 1건과 3건으로 갈렸다(실측):

```bash
gh pr diff <N> -R zulgap/claude-team-pack | grep -E "^\+" > /tmp/added.txt
grep -inE '\b[0-9a-f]{32}\b|\b[0-9a-f]{8}(-[0-9a-f]{4}){3}-[0-9a-f]{12}\b' /tmp/added.txt   # 노션 ID·UUID
grep -inF ':\Users\' /tmp/added.txt                                                          # 개인 PC 절대경로(드라이브 무관, -F = 리터럴)
```

⚠️ **매치 0이면 grep은 `exit 1`이다 — 명령 실패가 아니라 "깨끗함"이다.** 정상 신호로 읽을 것.
⚠️ `\b` 앵커를 빼면 **40자 커밋 SHA·`sha512-` 무결성 문자열**이 32-hex로 걸린다(게이트 원본도 `\b…\b`를 쓴다). 지금 레포엔 40-hex가 없어 조용하지만 lockfile이 커밋되면 발화한다.
⚠️ **UNC 경로(`\\서버\공유`)는 이 grep에 넣지 않았다** — 백슬래시가 셸·grep을 거치며 다르게 해석돼 **오탐이 폭발한다**(실측: UNC 리터럴을 넣으면 #59 히트가 2건 → **53건**). UNC는 **게이트만 잡고**(그것도 `plugins/` 아래 `SKILL.md`만) 채널·템플릿·루트 `skills/`의 UNC는 **자동으로 아무도 안 본다** → 그 구역이 diff에 있으면 **눈으로 확인**할 것.
⚠️ B급과 똑같이 ① **정의·설명문의 예시는 오탐** ② **파일 간 이동**일 수 있다. 실측 카탈로그:
- #59 → 노션 ID 1 + PC경로 2 = **진짜 신규 유입** (루트 `skills/`라 게이트는 못 봤다)
- #60 → 노션 ID 1 + PC경로 2 = 전부 **이동분**(#59에서 온 것. 노션 ID는 `PROVENANCE.md` → `SKILL.md`로 옮겨진 흔적)
- #64 → PC경로 1 = **오탐** (정본의 *"A 절대금지 … 개인 PC 절대경로(`C:\Use…`)"* 정의 표)
- #62 → 0

**게이트 스크립트를 로컬에서 돌릴 거라면** — 스크립트는 자기 위치(`__dirname/..`)의 **워킹트리를 읽는다**(`:15,21` + A급 경로는 `:109,123,128` 실측). 체크아웃 없이 돌리면 **PR이 아니라 지금 워킹트리를 검사한다.** 실증: 커밋도 스테이징도 안 한 한 줄로 exit 1이 났다.

```bash
cd ~/claude-team-pack
git status --porcelain | grep -v '^??'   # 출력 없어야 함 — tracked 변경이 있으면 PR도 main도 아닌 제3의 상태를 검사한다
git fetch origin pull/<N>/head    # ← gh pr checkout은 머지된 PR에서 실패한다(§승인 후의 --delete-branch 때문)
git checkout FETCH_HEAD
node scripts/check-plugin-consistency.js; echo "exit=$?"
git checkout main && git rev-parse HEAD origin/main   # 원복 + 두 줄 일치 확인
```

체크아웃이 부담되면 **로컬 실행을 건너뛰고 ⑤ CI 결과 + 위 diff grep 2개만 근거로 쓴다.** 오답은 하나뿐이다 — **체크아웃 없이 돌린 로컬 게이트 결과를 보고에 적는 것.**

🔴 **CI가 빨강인데 "사소해 보여서" 넘기지 말 것.** 게이트를 넘기는 순간 게이트가 없는 것과 같다.

### ④ 모태가 갈라지나

🔴 **판정 단위는 "이 PR이 만드는 변화"** 다 — *지금 두 벌인가*가 아니라 **머지하면 두 벌이 되는가**.
- 두 벌을 **해소하는** PR(사본 제거·한쪽으로 통합)은 ④ **통과**다. diff에 옛 경로가 보이는 이유가 `removed`·`renamed`면 갈라짐이 아니다
- rename은 diff 표면에 old·new가 **동시에** 보인다 → **net 결과**를 세라

```bash
# 이 PR이 SKILL.md를 어떻게 바꾸나 (added가 관심 대상)
gh api repos/zulgap/claude-team-pack/pulls/<N>/files --jq '.[] | "\(.status)\t\(.filename)"' | grep "SKILL.md$"

# base에 이미 같은 계열 스킬이 있나 — added 경로와 대조
git ls-tree -r origin/main --name-only | grep "SKILL.md$"
```

새 폴더가 기존 스킬의 **복사본**이면 🔴 — 그 순간부터 모태 개선이 그쪽에 **영원히 안 간다**(2026-07-30 두 벌 사고). 값만 다르면 **채널 파일로 내려야** 한다.
⚠️ **역할이 다른 동명 스킬**(예: `dev-pack`과 `jedi-core`에 목적이 다른 것)은 갈라짐이 아니다 — 내용이 복사본인지 확인하고, 아니면 통과 + 사유 1줄.

### ⑤ 자동검사 통과했나

```bash
gh pr checks <N>
```

**체크는 3종이다** — `consistency` · `guard` · **`ownership`**. 셋 다 `pass`여야 한다.

| 체크 | 워크플로우 | 무엇을 보나 |
|---|---|---|
| `consistency` | `plugin-consistency.yml` | Tier A~I (③ 표) |
| `guard` | `no-plugin-version.yml` | `plugin.json`/`marketplace.json`에 `version` 필드 0 |
| **`ownership`** | `skill-ownership.yml` | 남의 스킬 본체를 고쳤으면 **그 소유자의 승인** |

🔴 **`ownership` 빨강은 «코드 결함»이 아니다** — 스크립트 주석이 명시한다: *"PR을 처음 열 땐 아직 승인이 없어 **이 검사가 실패하는 게 정상이다.** 소유자가 승인을 눌렀을 때 다시 돌아야 초록불이 된다"* · *"막는 게 아니라 «승인이 필요하다»고 알린다"*.
판정은 **반려 그대로**지만(§추천 규칙 불변), **반려 사유를 정확히 써야 한다** — 자세한 문구는 § 반려할 때 참조.

⚠️ 체크가 **목록에 아예 없으면**(그 워크플로우 배선 이전에 만들어진 PR 등) *fail로 취급하지 말고* `해당 체크 미존재`로 적고 **③의 diff grep으로 보완**한다. 현행 기준으로는 **3종 전부** 존재해야 정상이다.
⚠️ ③에서 CI-only 경로를 택했다면 이 칸과 ③ 칸의 **근거가 같다**. 두 칸을 독립 검사 2개처럼 적지 말고, ③에는 **diff grep 결과**(B급·A급)를 적어 근거를 분리한다.

### ⑥ 개인 파일을 건드리나

`team-CLAUDE.md` 계열은 **직원 개인의 `~/.claude/CLAUDE.md`로 설치**된다. 개인이 자기 메모를 넣었을 수 있어 **덮어쓰기 위험**이 있고, **갱신 경로도 없다**. 변경이 있으면 위 § 즉시 경고대로 표시한다.

### ⑦ 과거에 같은 사고가 있었나

```bash
grep -rl "<핵심 키워드>" ~/.claude/projects/C--Users-admin/memory/ | head -3
git -C ~/claude-team-pack log origin/main --oneline -S "<바뀐 리터럴>" | head -3
```

CHANGELOG에 같은 자리를 고친 이력이 있으면 **왜 되돌아왔는지** 확인한다.

### 🔴 추천 규칙 (하드리밋)

**0. 먼저 ①④의 적용 대상인지 가른다** — 🔴 **여기서 판정을 다시 하지 말고 § ① 선행 질문 (ㄱ)·(ㄴ)의 결과를 그대로 가져온다.**
- ① 칸이 `N/A`였으면 → ①④는 반려 트리거에서 **제외**. 🔴 **`N/A`는 `NO`가 아니다**
- ① 칸이 `NO`였으면 → 아래 반려 트리거를 적용

🔴 **이 문장을 (ㄱ)만으로 다시 쓰지 말 것** — 판정 기준을 두 곳에 복사하면 갈라진다. 실제로 v1.3.0에서 ①은 (ㄴ)까지 확장됐는데 이 0번 게이트는 (ㄱ)만 물어서, **루트 `skills/`에 `SKILL.md`가 아닌 파일 하나만 넣는 PR**이 ①에서 `NO`인데 여기서 `N/A`로 되돌아가 승인까지 갔다. 기준은 ① 한 곳에만 둔다.

**반려 (하나라도 걸리면)**
- **① 로드되는 자리가 아니면(NO) → 반려 (예외 없음)** — CI·테스트·게이트가 전부 초록이어도. 초록은 *"내용이 옳다"* 만 말하고 *"직원에게 도달한다"* 는 **아무도 검사하지 않는다**(게이트는 루트 `skills/`를 스캔조차 안 한다 — ③ 표)
- **④ 이 PR이 모태를 갈라놓으면 → 반려.** 단 **갈라짐을 해소하는 PR(`removed`·`renamed`)은 통과**다
- 위험도 🔴이고 **PR 설명에 "왜"가 없으면** → **반려** (내용이 맞아도)
- 본체 변경인데 **영향 범위가 안 적혀 있으면** → **반려**
- 자동검사 **빨강이면** → **반려** (예외 없음). 🔴 **`ownership` 빨강도 반려다** — 여기에 예외를 만들면 다음 사람이 다른 게이트 빨강에도 같은 논리를 적용한다. 다만 **반려 사유 문구가 달라진다**(§ 반려할 때) — *"고쳐서 다시 올리세요"* 가 아니라 *"고칠 것은 없고 소유자 승인이 필요합니다"* 다
- `tier: shared` + **B급 신규 추가** → **반려** (③)

**보류 (반려는 아니지만 승인도 못 하는 것)**
- **⑧ 즉시경고 3종**(개인 파일 · `version` 필드 · 파일 삭제) 중 하나라도 해당 → **최소 보류.** 대체물·전달 경로를 확인한 뒤 승인으로 올릴 수 있다
- 판단이 안 서면 → **보류 + 사장님께 물을 것 1개**를 명시. 억지로 추천하지 말 것

**승인 (위 반려·보류 트리거가 하나도 없을 때만)**
- 🟢 **낮음** → 승인
- 🟠 **높음** / 🟡 **중간** → **되돌리기가 가능하면 승인. 불가·불확실하면 보류**
- 🔴 **최고** → **되돌리기 경로를 보고서 「되돌릴 수 있나」 칸에 쓸 수 있으면 승인.** 못 쓰면 보류

⚠️ 승인 블록은 **반려 조건을 다시 묻지 않는다** — "왜"·영향 범위는 위에서 이미 걸렀다. 중복하면 같은 입력에 *반려*와 *보류* 두 답이 나온다. 여기서 보는 것은 **되돌리기 가능성 하나**이고, 판정 주체는 **작성자가 아니라 검토자(당신)** 다 — PR 본문에 "revert 방법"이 적혀 있어야 하는 게 아니다.

🔴 **🟠에 승인 경로가 반드시 있어야 한다** — 팀팩 PR의 최빈 유형이 `SKILL.md` 본문 수정(=🟠)이다. 여기가 막히면 이 스킬은 **"전부 보류" 기계**가 되어 아무도 쓰지 않는다. 반려는 근거가 있을 때만.

## 🚫 금지 (리터럴)

- ❌ **"문제없어 보입니다"** 로 끝내기 — 무엇을 봤는지 **8항목 표**로 남길 것
- ❌ `gh pr diff` 안 보고 판정하기 — 제목·본문은 **올린 사람의 주장**이다
- ❌ CI 빨강인데 "사소해서" 승인 추천
- ❌ **사장님 대신 머지하기** — 이 스킬은 **추천까지**다. 머지는 사장님이 "승인"이라고 말한 뒤에만
- ❌ 코드 스타일·변수명 지적 — 그건 `/review` 몫이고 팀팩 PR엔 거의 무의미하다

## ✅ good / ❌ bad

```
❌ bad
"PR #65 확인했습니다. 프레임 색상 변경이고 테스트도 통과해서 문제없어 보입니다. 머지할까요?"
   → 무엇을 봤는지 없음 · 본체인지 설정인지 없음 · 영향 범위 없음

✅ good
"PR #65 — 위험도 🟠높음 (SKILL.md 본체)
 바뀌는 것: 썸네일 테두리가 금색 → 흰색 2px
 영향: 엔노블뿐 아니라 나래님 '테스트' 채널도 같이 바뀝니다
 되돌리기: 가능 (3줄, 이 PR만 취소)
 ⚠️ 설명에 '엔노블용'이라고만 적혀 있는데 실제로는 전원 영향입니다
 → 추천: 보류. 지연님께 '다른 채널도 흰색이 되는데 괜찮은지' 확인 후 승인"

✅ good — 같은 🟠인데 **승인**이 나오는 경우 (🟠에도 승인 경로가 있다)
"PR #66 — 위험도 🟠높음 (SKILL.md 본체)
 ①④ N/A (스킬 추가·이동 없음) · CI 2종 pass · 삭제 0 · A/B급 신규 0
 바뀌는 것: 키워드 조사 결과 표에 '진입 난이도' 열이 하나 붙습니다
 영향: /jedi-keyword 쓰는 전원 — PR 본문에 '전 채널 공통'으로 명시됨
 되돌리기: 가능 (이 PR revert 1회, 외부 배선 무변경)
 → 추천: 승인"
```

## 셀프체크 (보고 전 7문항 — **1~5·7이 NO** 이거나 **6이 YES**면 **해당 STEP으로** 재진입)

> 재진입 지점이 문항마다 다르다: 1 → STEP 1(수집) · 2 → STEP 2(등급표) · 3 → STEP 3 + ⑧은 STEP 2(즉시경고) · 4~6 → STEP 4(보고·추천) · 7 → STEP 3 ③. "STEP 3으로만" 돌아가면 등급·보고 문제는 고쳐지지 않는다.

1. `gh pr diff`를 **실제로** 봤는가? + 파일별 `status`를 뽑았는가?
2. 위험도를 **경로 기준**으로 매겼는가? (인상이 아니라) — 파일이 표의 두 행에 걸릴 때 **위쪽(높은) 행**을 썼는가?
3. **8항목을 전부** 채웠는가? 특히 ②(본체면 다른 채널 영향)·⑥(개인 파일 전달 경로)·⑧(즉시경고)을 *"확인함"이 아니라 **무엇을 봤는지**로* 적었는가? (해당 없으면 `N/A + 사유`)
4. *"누가 영향받나"*를 **사람·채널 이름으로** 적었는가?
5. 추천이 위 하드리밋(반려 → 보류 → 승인 순)과 **어긋나지 않는가**?
6. ⚠️ **이 문항만 YES가 문제다** — **①·④가 `NO`(`N/A` 아님)인데 추천이 '승인'·'보류'인가?** → 그러면 **반려로 고친다.** 등급·CI·설명 품질로 상쇄되지 않는다
7. ③에 **로컬 게이트 결과를 적었다면** PR을 체크아웃했고 **tracked 변경이 0**이었는가(untracked `?? `는 무관)? (아니면 그 줄을 지우고 **CI 결과 + diff grep**만 남긴다) — 로컬 게이트를 **아예 안 돌렸으면 `N/A`이고 재진입 사유가 아니다**(그게 권장 경로다)

## 승인 후 (사장님이 "승인"이라고 말한 뒤에만)

```bash
gh pr merge <N> --squash --delete-branch
sleep 3 && git -C ~/claude-team-pack pull --ff-only origin main   # fetch만으론 워킹트리가 안 올라온다
node ~/claude-team-pack/scripts/check-plugin-consistency.js; echo "exit=$?"   # 머지 후 게이트 재확인
```

⚠️ `--delete-branch`를 쓰면 이후 그 PR에 `gh pr checkout`이 **불가**해진다(head 브랜치가 사라짐). 사후 감사 때는 `git fetch origin pull/<N>/head` → `git checkout FETCH_HEAD`를 쓴다 — 이 ref는 삭제 후에도 남는다.

머지 직후 **게이트를 한 번 더 돌린다** — 머지 시점에 다른 PR과 겹쳐 깨질 수 있다.

## 반려할 때

```bash
gh pr comment <N> --body "<이유 + 무엇을 고치면 되는지>"
```

🔴 **"안 됩니다"만 쓰지 말 것.** 올린 사람이 **무엇을 고쳐 다시 올려야 하는지**를 반드시 함께 적는다.

### 🔴 `ownership` 빨강일 때의 문구 (고칠 것이 없는 경우)

이 경우 팀원의 코드에는 **고칠 것이 하나도 없다.** 남의 스킬 본체를 건드려 **소유자 승인이 필요할 뿐**이다.
일반 반려 문구(*"고쳐서 다시 올려주세요"*)를 그대로 쓰면 팀원은 **없는 결함을 찾느라 막힌다.**

```bash
gh pr comment <N> --body "코드에는 고칠 것이 없습니다. 이 PR이 @<소유자>님이 만든 스킬 본체를 수정해서
소유자 승인이 필요합니다(자동검사 ownership).

1) @<소유자>님께 리뷰를 요청해 주세요
2) 승인이 등록되면 검사가 자동으로 다시 돌아 초록이 됩니다

막는 것이 아니라 승인 절차입니다."
```

⚠️ **소유자를 추측하지 말 것** — CI 로그의 `FAIL [소유권]` 메시지가 *"이 스킬을 만든 사람: @…"* 로 알려준다.
판정 SSOT는 git 최초 작성자이고, 손으로 유지하는 명단이 아니다.

## 안 되는 경우

- **팀팩이 아닌 repo** — judgmentos 등은 위험도 표가 안 맞는다. `/review` 또는 `code-verification`을 쓸 것
- **코드 버그 찾기** — 이 스킬은 거버넌스 전용. 버그는 `/review`

### ⚠️ 내가(AI가) 만든 PR을 내가 검토할 때

**금지하지 않는다** — 실제로 대부분의 PR을 AI가 만들고 사장님이 승인하는 구조라, 금지하면 스킬이 무용해진다.
대신 **자기 검토임을 밝히고 더 엄격하게** 본다:

```
⚠️ 이 PR은 제가 만든 것입니다. 자기 검토라 놓칠 수 있어 아래를 특히 확인했습니다:
   - 제가 PR 본문에 쓴 주장을 diff로 재확인 (설명과 실제가 다른가)
   - 제가 "안전하다"고 판단한 근거를 실측으로 재검증
```

🔴 **자기 PR일 때 금지 리터럴**: *"제가 만들었으니 내용은 확실합니다"* · *"위에서 이미 검증했습니다"*
— 오늘(2026-07-30) 같은 세션에서 제 판단이 **세 번** 뒤집혔다. 만든 사람의 확신은 근거가 아니다.

### ⚠️ 열린 PR이 2개 이상일 때

각각 통과해도 **합치면 깨질 수 있다**(같은 파일·같은 버전 번호를 서로 모르고 건드림).
2개 이상이면 **겹치는 파일이 있는지** 먼저 보고, 있으면 **사장님이 하나를 승인·머지한 뒤 나머지를 처음부터 다시 검토**한다 (머지는 이 스킬이 하지 않는다 — § 금지 참조).

```bash
gh pr list --state open --json number,files --jq '.[] | "\(.number): \(.files[].path)"' | sort -t: -k2
```
