## 개요

발행한 네이버 블로그 글이 실제로 검색에 얼마나 노출되는지(=몇 위에 뜨는지)를 매번 손으로 검색해보지 않고 자동으로 체크합니다.

**⚠️ 기술적 배경 (중요, 지우지 말 것):** 네이버 검색결과 페이지(search.naver.com)는 Claude의 인앱 브라우저(mcp__Claude_Browser)와 Claude in Chrome 양쪽 모두에서 플랫폼 안전 정책상 차단되어 있어 접근 불가능하다. 대신 이 PC의 Bash 도구로 직접 실행하는 파이썬 스크립트(`scripts/check_rank.py`, requests 라이브러리로 순수 HTTP 요청)는 정상 작동함을 확인함(2026-08-02). **순위 체크는 반드시 이 스크립트를 Bash로 실행하는 방식으로 해야 하며, 브라우저 도구로 네이버 검색을 시도하지 말 것.**

## 사용 방법

```
"/순위체크"
"어제 올린 글 순위체크 해줘"
"검단가온 어제 발행분 노출순위 확인해줘"
"이 URL 순위 확인해줘: https://blog.naver.com/xxx/1234567890, 키워드는 임플란트 비용"
```

키워드나 URL을 직접 지정하면 그것을 그대로 쓰고, 아무것도 안 주면 아래 자동 감지 절차를 따른다.

## 동작 방식

### 1단계: 대상 포스트 찾기
- 기준 발행일을 정한다 (⭐ **영업일 기준** — 토/일요일 + 공휴일은 블로그 미발행이므로 "어제"를 그대로 쓰면 안 됨. 스케줄링 스킬(있다면 `../<스케줄링 스킬 폴더>/SKILL.md` — 팀팩/개인 설치에 따라 폴더명이 다를 수 있으니 형제 폴더를 직접 확인할 것)의 평일/공휴일 제외 로직과 동일한 사고):
  - 체크 실행일의 하루 전날부터 거슬러 올라가며, **토/일요일이거나 공휴일이면 건너뛰고** 가장 가까운 영업일을 기준 발행일로 삼는다.
  - 예: 체크일이 월요일 → 토/일 건너뛰고 지난 금요일. 체크일이 명절 연휴 다음날 → 연휴 전체를 건너뛰고 그 이전 마지막 영업일.
  - 공휴일 판단은 기본 한국 공휴일(설날·추석 연휴, 삼일절, 광복절, 개천절, 한글날, 성탄절, 신정 등)을 따르고, 정확한 날짜가 애매하면(대체공휴일 등) 사용자에게 확인한다.
  - 결과적으로 "전날~기준 발행일 사이"가 전부 휴무일이라 발행분 자체가 없을 수 있다 — 그 경우 그 앞의 영업일까지 계속 거슬러 올라간다.
- 노션 MCP(claude.ai 연결 계정, `mcp__..__notion-query-data-sources` 등)의 **SQL 모드**로 콘텐츠마스터 데이터소스(`collection://7f410191-5034-4dae-8648-7e109bfffe27`)를 조회한다. 예:
  ```sql
  SELECT url, "기획안(👇클릭해주세요)" AS title, "발행 링크", "date:실 발행일:start" AS actual_publish_date, "키워드"
  FROM "collection://7f410191-5034-4dae-8648-7e109bfffe27"
  WHERE "콘텐츠 구분" = '네이버블로그' AND date("date:실 발행일:start") = '기준발행일(YYYY-MM-DD)'
  ```
  jedi 도구는 단일 페이지 읽기만 가능해 이 필터 조회에는 못 쓴다. 노션 MCP 미인증 시 사용자에게 인증을 안내한다.
- 조회 결과가 0건이면 날짜를 넘겨짚지 말고, 그 주변 날짜(±3일)로 넓혀서 후보를 보여주고 사용자에게 확인한다 (실제로 "기준일 계산"과 "노션에 실제로 찍힌 실 발행일"이 다를 수 있었음, 2026-08-02 실측).
- 각 카드에서 제목과 **"발행 링크"**(네이버 블로그 URL, `blog.naver.com/블로그ID/포스트번호` 형식)를 확보한다.

### 2단계: 키워드 추출
- **먼저 카드 본문을 확인한다** — 작성 시 "SEO 대표 키워드: '...' + '...'" 같은 메모가 본문 하단에 남아있는 경우가 있다(실측 사례 있음). 있으면 이게 제목 추측보다 훨씬 정확한 실제 타겟 키워드이므로 우선 사용한다. "키워드" 속성이 채워져 있으면 그것도 함께 참고한다.
- 위 두 곳 다 비어있으면, 포스트 제목에서 브랜드명·클리닉명, 조사, "총정리"/"완벽 가이드" 같은 상투어를 제거하고 남는 핵심 명사구(2~4어절)를 대표 키워드로 뽑는다.
- 찾은 키워드가 여러 개면 전부 체크해도 된다(연달아 하되 요청 사이 2~3초 간격 유지).
- 사용자가 키워드를 직접 지정했다면 이 단계는 건너뛴다.

### 3단계: 순위 체크 (⭐ 핵심)
Bash로 스크립트를 직접 실행한다. 예:
```bash
python "~/.claude/skills/naver-rank-check/scripts/check_rank.py" --url "https://blog.naver.com/블로그ID/포스트번호" --keyword "핵심키워드" --tab blog --max-page 5
```
- 기본은 `--tab blog` (블로그탭 단독 순위, 명확한 기준). 모든 키워드 후보를 먼저 `--tab blog`로 다 체크하고, **그중 4단계에서 대표값으로 쓸 키워드 하나를 정한 뒤, 그 키워드로만** `--tab view`를 추가로 돌린다 — 서로 다른 키워드의 블로그탭/VIEW탭 결과를 섞어서 나란히 적으면 마치 같은 검색의 두 지표처럼 오해하게 만든다 (실제로 이 실수가 있었음, 2026-08-02: '재외동포 결혼' 블로그탭 4위 옆에 '유학파 재외동포 결혼'의 VIEW탭 1위를 붙여놨다가 사용자가 헷갈림).
- 포스트가 여러 개면 **포스트 사이에 2~3초 간격**을 두고 순차 실행한다 (짧은 시간에 과도한 요청을 보내면 네이버가 의심 트래픽으로 취급할 수 있음).
- `--max-page 5`는 블로그탭 기준 최대 50위까지 탐색한다는 뜻. 그 밖이면 "50위 밖"으로 보고한다.

### 4단계: 노션 카드에 기록
먼저 대표키워드의 **블로그탭 순위(N)**를 확인하고, **7위 이내인지**로 기록 분량을 가른다 (⭐ 사용자 규칙, 2026-08-02):

**공통 — 항상 기록:**
- `notion-update-page`(command: update_properties)로 **"익일 순위 체크 날짜"** (date)에 오늘 날짜를 넣는다. `"date:익일 순위 체크 날짜:start": "YYYY-MM-DD", "date:익일 순위 체크 날짜:is_datetime": 0` 형식.

**대표키워드가 블로그탭 7위 이내일 때만 추가로:**
- **"익일 노출순위"** (number, 공백 없이) ← 그 대표 숫자(N)를 넣는다. 체크한 키워드가 여러 개면 브랜드명 포함 키워드(거의 항상 1위, 변별력 없음)는 참고용으로 빼고, **가장 보수적인(순위가 가장 낮은) 실제 타겟 키워드**를 대표로 쓴다.
- **"특이사항"** (text) ← 키워드별 상세 내역 한 줄 추가. **VIEW탭 숫자를 적을 땐 반드시 그 키워드 바로 옆에 붙여쓴다** (다른 키워드 뒤에 괄호로 덧붙이지 말 것 — 어느 키워드 결과인지 헷갈림). 기존 값이 있으면 덮어쓰지 말고 이어붙인다. 예:
  ```
  📊 익일 노출순위 체크(발행일 2026-07-30 / 체크일 2026-08-02): 대표키워드 '재외동포 결혼' → 블로그탭 4위 / VIEW탭 근사 4위. 참고(브랜드·롱테일, 변별력 낮음, 블로그탭 기준): '유학파 결혼정보회사' 1위, '유학파 재외동포 결혼' 1위
  ```
- `notion-update-page`(command: insert_content, position: {"type":"end"})로 **페이지 본문 맨 아래에도** 같은 내용을 남긴다:
  ```
  ---
  ### 📊 익일 노출순위 체크 (발행일 YYYY-MM-DD / 체크일 YYYY-MM-DD)
  - 대표키워드 **'키워드'** → 블로그탭 **N위** / VIEW탭 근사 **N위**
  - 참고(브랜드·롱테일 키워드, 변별력 낮음, 블로그탭 기준): '키워드2' N위, '키워드3' N위
  ```
  기존 본문 내용은 지우거나 바꾸지 않고 맨 끝에 추가만 한다 (allow_deleting_content 쓸 필요 없음).

**대표키워드가 8위 이하이거나 순위권 밖("50위 밖")일 때:**
- **"익일 노출순위"는 건드리지 않는다** (update_properties 호출에서 이 속성 자체를 아예 빼고 보낸다 — 값을 넣지 않을 뿐, 기존에 다른 날짜 체크로 이미 들어있던 숫자를 임의로 지우지는 않는다).
- **"특이사항"과 본문 추가는 하지 않는다** — 체크 날짜만 남기고 끝낸다.
- 체크를 여러 날 반복하면 이 블록이 매번 쌓인다 — 그게 의도(발행 후 순위 변화 이력을 페이지 안에서 훑어볼 수 있게).

### 5단계: 채팅 리포트
- 체크한 전체 포스트를 표로 요약해 채팅에 보여준다 (제목 / 키워드 / 블로그탭 순위 / VIEW탭 근사 순위).

## 매일 자동 실행하고 싶다면

이 스킬 자체는 채팅에서 호출해야 동작한다(대화형). 매일 저절로 돌게 하려면 **Windows 작업 스케줄러**에 아래와 같이 등록해야 한다 — 이건 OS 설정 변경이라 **사용자 승인 없이 만들지 않는다.** 원하면 실행 시간을 물어보고 아래 명령으로 등록을 제안한다:
```
claude -p "/순위체크"
```
(PC가 꺼져 있으면 그날은 실행되지 않는다.)

## 제한사항

- 노션 필터 조회에는 인증된 Notion MCP 연결이 필요하다 (jedi 도구는 단일 페이지 읽기만 가능, DB 필터 쿼리 불가). 2026-08-02 기준 이 환경에서는 인증되어 정상 작동 확인함.
- "익일 노출순위" 속성은 숫자 하나만 들어간다 — 여러 키워드를 체크했다면 대표값 선정 기준(4단계 참고)을 따르고, 나머지는 "특이사항"에 남긴다.
- VIEW탭 순위는 근사치다 — 블로그 외 콘텐츠(카페·뉴스 등)가 섞여있어 "화면상 정확히 몇 번째"와는 다를 수 있다. 정식 지표는 블로그탭 순위.
- 네이버가 페이지 구조를 바꾸면 `scripts/check_rank.py`의 파싱 정규식이 깨질 수 있다 — 순위가 계속 "검색결과 없음"으로만 나오면 스크립트 점검이 필요하다는 신호다.
- 브라우저 도구(mcp__Claude_Browser, Claude in Chrome)로 네이버를 직접 열려고 시도하지 말 것 — 플랫폼 정책상 막혀있음이 확인됨.
- 과도한 자동 조회는 자제한다 (하루 1회 수준 권장).
