# 팀 스킬 만들기

반복 작업을 팀팩 스킬로 만들어 **전 직원 PC에 배포**되게 한다.
사용자는 무엇을 하고 싶은지만 말하면 되고, 규칙(자리·이름·tier·검사)은 이 스킬이 처리한다.

> 🔴 **머지는 절대 하지 않는다.** PR을 올리는 데까지가 이 스킬의 끝이다.
> 사용자에게 push 권한이 있어 버튼이 눌리지만, 검토 없이 들어가면 전 직원에게 바로 배포된다.

## 언제 쓰나

- "매번 손으로 같은 걸 해요" → 그게 스킬 후보다
- 이미 개인 스킬(`~/.claude/skills/…`)을 만들어 뒀고 팀에 올리고 싶을 때
- 기존 팀 스킬을 고치고 싶을 때 (Phase 1에서 신규/수정을 가른다)

## 안 되는 경우

- **한 번만 할 일** → 스킬로 만들지 말고 그냥 하면 된다
- **회사 데이터를 바꾸는 일**(발행·결제·삭제) → 사장님께 먼저 확인
- 팀팩이 아닌 다른 저장소 → 이 스킬은 `zulgap/claude-team-pack` 전용

## Phase 1 — 어디에 넣나 (이름·tier가 여기서 정해진다)

### 1-A. 기존에 있는지 먼저 본다

```bash
ls ~/claude-team-pack/plugins/*/skills/
```

**목적이 겹치는 스킬이 이미 있으면 새로 만들지 않는다.** 그 스킬을 고치는 쪽으로 방향을 바꾸고
사용자에게 알린다 — 비슷한 스킬이 두 벌이 되면 개선이 한쪽에만 쌓여 갈라진다.

### 1-B. 어느 팩에 넣나

| 팩 | 무엇이 들어가나 | 이름 |
|---|---|---|
| `plugins/zulgap-pack/skills` | 줄갭 콘텐츠·업무 작업 (블로그·보고서·영상 등) | **`zulgap-*`** |
| `plugins/jedi-core/skills` | 회사 무관 범용 도구 (이미지·키워드·저장 등) | **`jedi-*`** |
| `plugins/dev-pack/skills` | 개발자 전용 | (접두사 규칙 없음) |

🔴 **저장소 맨 위(루트)의 `skills/` 는 로드 경로가 아니다.** 거기 넣으면 파일도 있고
자동검사도 초록인데 **어느 직원 PC에도 안 간다**(실사고 있음).

🔴 **접두사가 없으면 아무도 못 찾는다.** 직원은 `/zulgap` 까지 쳤을 때 뜨는 목록에서 스킬을 고른다.
자동검사(C-5)가 막지만, 알고 짓는 편이 낫다.

### 1-C. tier 정하기 — 가장 헷갈리는 지점

| 이런 게 들어가면 | tier |
|---|---|
| 노션 DB ID · 동료사 이름 · 우리 회사 운영 규칙 · 특정 담당자 | **`tenant-only`** |
| 어느 회사에서나 그대로 도는 순수 알고리즘 | `shared` |

**애매하면 `tenant-only`.** `shared` 로 선언해 놓고 회사 고유값이 들어 있으면 자동검사가 막는다
(그때 값을 `channels/` 파일로 내리거나 `tenant-only` 로 바꾸면 된다).

**Phase 1 산출**: 팩 · 최종 이름 · tier 세 가지를 사용자에게 확인받고 다음으로 간다.

## Phase 2 — 만든다

### 2-A. 폴더와 파일

```
plugins/<팩>/skills/<이름>/
├── SKILL.md          ← 본체 (필수)
├── scripts/          ← 파이썬·노드 스크립트 (선택)
└── channels/         ← 회사·채널별 값 (선택)
```

🔴 **폴더명과 `name:` 이 정확히 같아야 한다.** 다르면 자동검사가 막는다(C-4).

### 2-B. frontmatter 5필드

```yaml
---
name: <폴더명과 동일>
description: <아래 규칙>
version: 1.0.0
origin: teampack
tier: tenant-only
---
```

🔴 **`description` 에 한글 표현을 넣는다.** 직원이 명령 이름을 몰라도 평소 말로 부를 수 있어야 한다.

```
✅ good: ... "순위체크", "어제 올린 글 몇 위야", "블로그 순위" 라고 하면 이 스킬을 쓸 것.
❌ bad:  네이버 블로그 순위를 체크하는 스킬.
```

### 2-B2. 이 스킬이 따르는 «정본 스킬» 이 있나 (2026-08-05 신설 — 반드시 물어볼 것)

**만들기 전에 사람에게 묻는다:**

> **"이 스킬이 규칙을 물려받는 정본 스킬이 있습니까?"**
> (예 — 검단가온 블로그는 범용 `/zulgap-blog` 의 키워드·시각물 규칙을 그대로 따릅니다)

**없으면** (대부분) 그냥 넘어간다. **있으면** 두 줄을 추가한다:

```yaml
extends: zulgap-blog          # 규칙을 물려받는 정본 스킬 이름
parent-checksum: 345635f1     # 그 스킬 SKILL.md 의 현재 해시 앞 8자
```

`parent-checksum` 값 얻는 법 — 둘 중 아무거나:

```bash
git hash-object plugins/<팩>/skills/<정본>/SKILL.md   # 앞 8자만 쓴다
node scripts/check-plugin-consistency.js              # 값이 틀리면 정답을 알려준다
```

🔴 **왜 이걸 묻나** — 2026-08-04 실사고: `zulgap-blog` 에 이미지 기준을 넣었는데 그 규칙을 따르는
`zulgap-gaon-blog` 가 안 따라왔고 **우연히 발견됐다.** 관계가 본문에 *"…의 시각물 단계를 따른다"* 라는
한국어로만 있어서 기계가 몰랐다. 위 두 줄이 있으면 **정본을 고칠 때 이 스킬이 자동으로 함께 검토된다.**

🔴 **본문에 *"…의 단계를 따른다"* 라고 쓸 거면 `extends` 는 필수다.** 안 쓰면 `Tier I-2` 가 막는다
(글로만 선언하고 기계는 모르는 상태 = 이번 사고의 원인).

⚠️ 정본이 나중에 바뀌면 `Tier I-3` 이 *"부모가 바뀌었다"* 며 막는다. **그게 정상이다** — 반영이
필요한지 보고, 필요 없으면 `parent-checksum` 만 새 값으로 갱신하면 된다.

### 2-C. 본문에 반드시 넣을 것

- **언제 쓰나 / 안 되는 경우** — 엉뚱한 상황에서 실행되는 것을 막는다
- **막혔을 때** — 실패하면 무엇을 확인하고 누구에게 물을지
- 실제로 돌려본 결과 1건 (검증했다는 근거)

### 2-D. 넣으면 안 되는 것 (자가점검)

```bash
# 내 PC 절대경로
grep -n "C:\\\\Users\\\\" plugins/<팩>/skills/<이름>/SKILL.md
# 노션 ID·UUID (32자리 hex)
grep -nE "\b[0-9a-f]{32}\b" plugins/<팩>/skills/<이름>/SKILL.md
```

- **PC 절대경로**: 직원마다 경로가 달라 그대로는 못 쓴다 → `~/` 상대표기로
- **노션 ID·UUID**: `tenant-only` 면 허용. 단 어디에 쓰는 ID인지 주석 한 줄
- **다른 스킬 폴더를 이름으로 직접 가리키기**: 설치 형태마다 폴더명이 달라 한쪽에서 깨진다.
  자동검사(Tier E)가 막는다 → `` `../<다른 스킬 폴더>/` `` 처럼 **꺾쇠 플레이스홀더** + *"형제 폴더를
  확인하고 실제 이름을 쓸 것"* 안내로 쓴다.
  🔴 이 문서를 처음 쓸 때 여기서 실제로 걸렸다 — 규칙을 설명하는 문장 안에 구체적 폴더명을 넣었다가
  게이트가 잡았다. **설명하려고 적은 예시도 검사 대상이다.**

## Phase 3 — 검사한다 (통과할 때까지)

```bash
cd ~/claude-team-pack && node scripts/check-plugin-consistency.js; echo "exit=$?"
```

- `exit=0` → 통과. Phase 4로
- `exit=1` → **출력 메시지를 사용자에게 그대로 보여주고** 무엇을 고칠지 설명한 뒤 고친다. 0이 될 때까지 반복

자주 나오는 것:

| 메시지 | 뜻 |
|---|---|
| `C-1 이름규격` | 한글·대문자·공백이 들어갔다. 소문자·숫자·하이픈만 |
| `C-4 폴더명불일치` | 폴더명과 `name:` 이 다르다 |
| `C-5 팩접두` | 접두사가 없다 (`zulgap-` / `jedi-`) |
| `D-1 tier미선언` | `tier:` 한 줄이 없다 |
| `D-2 A급리터럴` | `shared` 인데 회사 고유값이 있다 → `tenant-only` 로 바꾸거나 값을 뺀다 |
| `F-1 OS종속경로` | `scripts/` 코드에 한 OS 경로만 있고 대안이 없다 → 다른 OS에서 그 줄에서 죽는다. 후보 배열로 바꿀 것 |
| `F-2 폰트라이선스` | `assets/` 에 폰트를 넣었는데 같은 폴더에 라이선스 사본이 없다 → 배포처의 `OFL.txt` 원문을 함께 넣을 것 |
| `G-1 되돌릴수없음` | 국세청 발행처럼 **되돌릴 수 없는 도구**를 호출하라고 적었다. 스킬은 준비까지만 하고 멈춘다(사람이 버튼을 누른다) |
| `H-1 stub신선도` | `team-CLAUDE*.md` 에 「N시간마다」 같은 **낡을 값**을 적었다 → 그 파일은 설치 후 갱신되지 않아 영영 거짓이 된다. 주기·간격은 `team-guide.md` 에 |
| `I-1 상속대상` | `extends:` 가 없는 스킬을 가리킨다. 오타이거나 그 스킬이 개명·삭제됐다 |
| `I-2 선언누락` | 본문이 *"…의 단계를 따른다"* 고 하는데 `extends:` 가 없다 → Phase 2-B2 |
| `I-3 부모변경` | 정본이 바뀌었다. 반영이 필요한지 보고 `parent-checksum` 을 메시지가 알려준 값으로 갱신 |

> 게이트 전체는 **`Tier A`~`Tier J` 10종**이다. 위 표는 스킬을 만들 때 실제로 걸리는 것만 추렸다 —
> `Tier A`(활성화 집합)·`Tier B`(레거시 잔존)는 설치기·marketplace 쪽이라 스킬 추가로는 잘 안 걸린다.
>
> ⚠️ **`Tier J`(문서 커버리지)가 이 문서를 검사한다.** 게이트에 새 Tier가 생겼는데 여기 안내가 안 늘면
> **그 자리에서 CI가 막는다.** 이 표는 «있으면 좋은 것»이 아니라 **게이트가 강제하는 항목**이다 —
> 새 Tier를 알게 되면 위 표에 1줄 추가할 것. 그게 팀원이 CI 실패 이유를 아는 유일한 통로다.

🔴 **자동검사가 보는 범위는 `SKILL.md` 하나가 아니다** (2026-08-03 `Tier F` 신설로 넓어졌다):

| 대상 | 보나 | 무엇을 |
|---|---|---|
| `SKILL.md` 본문 | ✅ | `Tier C·D·E·G·I` |
| **`scripts/` 안의 `.js`·`.mjs`·`.cjs`·`.py`·`.ps1`·`.sh`** | ✅ | **`Tier F-1`** — OS 종속 경로(`C:/Windows/…`·`/usr/…`)가 **한 계열뿐**이면 FAIL |
| **`assets/` 안의 폰트**(`.ttf`·`.otf`·`.ttc`·`.woff`) | ✅ | **`Tier F-2`** — 같은 폴더에 라이선스 사본(`OFL`/`LICENSE`/`NOTICE`) 없으면 FAIL |
| `channels/*.md` · `templates/*` | ❌ | **사람이 눈으로** — 내 PC 경로·노션 ID는 여기서 안 걸린다 |

⚠️ **`Tier F-1`의 판정축은 "윈도우 경로를 썼나"가 아니라 "대안이 있나"다.** 여러 OS 후보를 배열로 두고
존재하는 첫 경로를 고르면 통과한다. 그 OS 전용이 의도라면 코드 주석에 `@AI:ALLOW os-specific-path` 를 남긴다.

🔴 **`assets/`에 폰트를 넣을 거면 배포처의 라이선스 원문을 같은 폴더에 함께 넣을 것** — 이 레포는 public이라
**커밋이 곧 재배포**이고, OFL·Apache 등 대부분의 무료 폰트가 라이선스 사본 동봉을 재배포 조건으로 요구한다.

여전히 **사람이 봐야 하는 것**: `channels/`·`templates/` 안의 A급(PC 경로·노션 ID)과, 어느 파일이든 **B급**(회사·브랜드·담당자 실명) — 게이트에 B급 정규식은 0개다. Phase 2-D를 그 파일들에도 한 번 더 적용할 것.

## Phase 4 — 올린다 (PR까지만)

```bash
cd ~/claude-team-pack
git checkout main && git pull --ff-only origin main
git checkout -b feat/<스킬이름>
git add plugins/<팩>/skills/<이름>
git status                     # 의도한 파일만 올라가는지 확인해 사용자에게 보여줄 것
```

**커밋 메시지는 파일로 넘긴다** — Windows에서 한글을 명령줄에 직접 쓰면 깨질 수 있다:

```bash
cat > /tmp/msg.txt <<'EOF'
feat(스킬): <이름> — <한 줄 설명>

<무엇을 자동화하는지 2~3줄>
<실제로 돌려본 결과>
EOF
git commit -F /tmp/msg.txt
git push -u origin feat/<스킬이름>
```

**PR 본문에 이 두 가지가 없으면 반려된다**:

```markdown
## 무엇을 / 왜
<이 스킬이 무슨 일을 자동화하나. 지금은 어떻게 하고 있나>

## 영향 범위
<새 스킬 추가만인지, 기존 스킬도 바뀌는지>
<전 직원에게 어떤 명령이 새로 생기나>

## 검증
- 로컬 자동검사 exit=0
- 실제 실행 결과 <1건>

## 되돌리기
<가능/어려움 + 이유>
```

```bash
gh pr create -R zulgap/claude-team-pack --base main --title "<제목>" --body-file /tmp/pr.txt
gh pr checks <번호> -R zulgap/claude-team-pack     # CI 검사가 전부 pass 인지 확인
```

⚠️ **`ownership` 이 빨강이어도 당황하지 말 것** — 남의 스킬 본체를 고쳤을 때 **그 소유자의 승인**을 요구하는 검사다.
**코드에 결함이 있다는 뜻이 아니다.** CI 로그가 소유자를 알려주니 그분께 리뷰를 요청하면 되고,
승인이 등록되면 검사가 **자동으로 다시 돌아** 초록이 된다. (내가 만든 스킬을 내가 고칠 때는 안 걸린다)

**PR 번호와 주소를 사용자에게 알려주고 끝낸다.**

초안(draft)이 아니면 사내 개발 소통방에 알림이 자동으로 간다(`pr-telegram-notify`).
다만 **발송이 실패하면 그 검사가 빨간불이 되고 방에는 아무것도 안 간다** — 그때는 직접 알릴 것.
초안으로 열었다면 "Ready for review" 를 누르는 시점에 알림이 간다.

## 🚫 금지 (리터럴)

- ❌ `gh pr merge` — **머지는 사장님만 한다**
- ❌ `main` 브랜치에 직접 커밋·푸시
- ❌ 저장소 루트 `skills/` 에 넣기 (죽은 경로)
- ❌ 자동검사(Phase 3)를 건너뛰고 올리기
- ❌ 사용자의 개인 스킬 원본(`~/.claude/skills/…`)을 지우기 — 머지되기 전에는 그게 유일한 사본이다
- ❌ 기존 스킬을 "정리·통일" 목적으로 함께 고치기 — 요청받은 것만

## 막혔을 때

| 증상 | 조치 |
|---|---|
| `gh auth` 가 안 된다 | `gh auth login` 안내. `gh` 자체가 없으면 사장님께 문의 |
| push 가 권한으로 막힌다 | 계정이 아직 등록되지 않은 것 — 사장님께 요청 |
| 자동검사가 계속 실패한다 | 메시지 원문을 사장님께 그대로 전달. 게이트 오탐일 수 있다 |
| 무엇을 스킬로 만들지 모르겠다 | 최근 반복한 작업 3개를 물어보고 그중 가장 자주·같은 순서로 하는 것을 고른다 |
