# 🔴 고객사 이름 목록은 이 레포에 두지 않는다

`check-plugin-consistency.js` 의 **D-3 게이트**(공용 팩에 고객사 이름 0건)가 쓰는 재료다.
전에는 이 자리에 `_tenant-names.json` 으로 있었다.

## 왜 뺐나 (2026-08-16)

이 레포는 **PUBLIC** 이다. 그런데 이 파일은 **「공용 팩에 들어가면 안 되는 이름」의 목록**이라,
공개되면 **그 자체가 고객 명부**가 된다. 실제로 고객 7사 실명 + 별칭 + 「경쟁사」 인식까지
기계가 읽기 좋은 JSON 한 장으로 올라가 있었다.

🔑 **유출을 막으려고 만든 게이트가 유출이 됐다.** 게이트용 데이터가 공개 레포에 있으면
게이트가 곧 명부다 — 이 클래스를 다시 만들지 말 것.

## 어디서 읽나 (두 곳뿐, 순서대로)

| 순위 | 자리 | 누가 |
|---|---|---|
| 1 | 환경변수 `TENANT_NAMES_JSON` | **CI** — 저장소 secret 으로 주입 (`.github/workflows/plugin-consistency.yml`) |
| 2 | `~/.claude/zulgap/tenant-names.json` | **로컬** — 레포가 아닌 경로로 받아 둔다 |

## 🔴 둘 다 없으면 FAIL 한다 — skip 이 아니다

재료가 없을 때 조용히 통과시키면, 그게 정확히 이 게이트가 막으려던 사고다
(D-3b 「목록낡음」 검사를 만든 이유와 같은 클래스).
`loadTenantNames()` 가 `process.exit(1)` 로 끊고 무엇을 어디에 두라고 알려 준다.

## 새 고객사가 생기면

**레포가 아니라 위 두 자리를 고친다.** 로컬 파일에 한 줄 추가하고, CI secret 도 함께 갱신할 것.
한쪽만 고치면 로컬은 통과하는데 CI 가 못 잡는다(또는 그 반대).

## 모양

```json
{
  "customers": { "<정식명>": ["<별칭1>", "<별칭2>"] },
  "allowed":   { "<이름>": "<금지 대상이 아닌 이유>" }
}
```

`allowed` 는 외부 공개 채널(벤치마크)·경쟁사처럼 **근거로 인용해도 유출이 아닌 것**이다.
